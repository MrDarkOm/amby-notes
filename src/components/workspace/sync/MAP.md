# Sync connect screen map

The optional module `amby.sync` (beta, opt-in, off by default) and its settings section. Plan:
[sync-plan.md](../../../../docs/sync-plan.md) (Р5, Р12, stage Э4). The connection, and the sync of the open
vault under it. Until the gates of the plan are passed a vault can be switched on only when the person marks
it as a test vault, and the screen says so.

Rules that tests hold: the recovery code is shown **before** anything is sent, and the only way on is typing back
groups of it; the password is judged by the application (12 characters, `zxcvbn` score 3), the screen only
shows the verdict; every error is a machine code translated in `sync.errors.*` (the text of a server is
never shown); the browser build has the `unavailable` port. Keep passwords and codes out of component state
once they have been used, and out of the DOM text.

The window of external changes of the editor ([external-conflict-dialog.tsx](../external-conflict-dialog.tsx)) is tied to an open,
edited buffer and writes through it, so the comparison of a sync conflict is a window of its own that only reads the two files and
resolves through `resolveConflict` (history snapshots and trash as before). It has no manual merge: that comes with the three-way
merge of stage Э5. A deletion from another computer is marked only for a note that is open (Р8); the note stays open under the rule
for externally deleted documents, with its own strip and a way back from `.amby/trash/`.

Tests sit beside the files. The manual check in a native window, against a server in Docker, is the
section "Синхронизация" of [native-ui-smoke.md](../../../../docs/native-ui-smoke.md).
