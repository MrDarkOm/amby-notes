Rules that tests hold: the recovery code is shown **before** anything is sent, and the only way on is typing back
groups of it; the password is judged by the application (12 characters, `zxcvbn` score 3), the screen only
shows the verdict; every error is a machine code translated in `sync.errors.*` (the text of a server is
never shown); the browser build has the `unavailable` port. Keep passwords and codes out of component state
once they have been used, and out of the DOM text.

A vault that was switched off is resumed ("Switch on again") only when `VaultSyncStatus.resumable`: the link remembers the server address
and the key of its space, and both must fit the current connection (runtime.rs `link_matches`). Otherwise the panel shows the
first-time choice (new / existing space, test mark); resuming a space that is gone forgets the stale link. The test mark is asked for on
the resume path too when the gate is closed. The action rows of the wizard are one row per step (`wizard-actions`): primary first,
secondary outline, links last. The server step offers the Amby server (default, address in `src/lib/sync/amby-server.ts`, no address field) or an own server (address field, guide link).

The window of external changes of the editor ([external-conflict-dialog.tsx](../external-conflict-dialog.tsx)) is tied to an open,
edited buffer and writes through it, so the comparison of a sync conflict is a window of its own. It reads the two versions
through the port (`readConflictVersions`; today the file and its copy, later wherever the engine keeps the second version) and
resolves through `resolveConflict` (whole version) or `resolveConflictWithText` (the assembled result: written as given with a
history snapshot, the second version to the trash, the entry cleared; refused with `conflict_changed` when the `stamp` that `readConflictVersions` returned no longer matches both files, and the window then reads them again). In Live mode `planBlockCompare` cuts both versions into units
that tile the text exactly (the source Live Preview keeps per top-level block, and per item for lists; whitespace and text the editor
does not keep as a block stay between or as units of their own), lines them up and finds the differences; `assembleCompare` joins
the chosen units with their own whitespace, in the line endings and BOM of my file, so nothing untouched is rewritten. A version
that does not pass the Live admission is shown as source; a file that is not Markdown text, mixes line endings, has an unterminated
envelope or cannot be tiled is chosen as a whole. A different `amby-id` is never taken over. A deletion from another computer is
marked only for a note that is open (Р8); the note stays open under the rule for externally deleted documents, with its own card
and a way back from `.amby/trash/`.

Before the first pass Rust creates a verified external copy beside the vault.
The panel explains it and shows `VaultSyncStatus.backupPath` with safe restore
instructions. See [the backup contract](../../../../docs/vault-format.md#backup-and-git-policy).

Tests sit beside the files. The manual check in a native window, against a server in Docker, is the
section "Синхронизация" of [native-ui-smoke.md](../../../../docs/native-ui-smoke.md).
