## Блокеры production release

### MANUAL-05 — Windows и непроверенные файловые системы

Статус: `BLOCKED`, нужны целевые среды.

- Выполнить [отдельный Windows-чек-лист](docs/windows-release-checklist.md):
  установка, NTFS, multi-window/autosave/recovery, watcher, history, UI,
  Credential Manager, ошибки настроек/AI и performance smoke.
- Проверить exFAT, FAT32 и сетевую папку: case-only rename файлов, папок и bundle,
  no-replace создание при недоступных hard links, collisions и rollback без
  перезаписи существующих данных. Зафиксировать ОС, filesystem и протокол сети.
- Приложить результаты и evidence для каждого пункта. Недоступная среда —
  `BLOCKED`, не `PASS`.
- Непроверенные платформы/файловые системы либо проверить, либо явно согласовать
  ограничение заявленной поддержки. Вынос Windows в отдельный файл поддержку
  автоматически не меняет; macOS arm64 не подтверждает другие архитектуры и ОС.

### Первичные доказательства data-safety приёмки

Статус: `BLOCKED`, не хватает исходных результатов MANUAL-01—05.

- Найти исходный архив или повторить недостающие изолированные runtime-проверки:
  multi-window/CAS и autosave; внешние edit/rename/move/delete и конфликты;

- Зафиксировать ревизию, среду, ожидаемое/полученное, hashes исходных файлов и

- Исторический протокол доступен через
  `git show 1d3f0d6:AUDIT_ISSUES.md`. Исторические PASS не отменяются, но сами
  по себе не восстанавливают отсутствующие первичные файлы.

  ключей; хранить нужные для приёмки результаты отдельно от временных файлов.
