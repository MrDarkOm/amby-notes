# Обновления Amby

Здесь собраны понятные пользователям изменения, которые войдут в следующие версии Amby. Записи накапливаются до выпуска и публикуются вместе одним аккуратным списком.

## Следующая версия

- Автоматическая проверка, восстановление баз данных и устранение ошибки «database was not found»:
  - **Проверка и починка манифестов при запуске и перезагрузке хранилища**: при открытии приложения (`prepare_activation`) и нажатии кнопки «Перезагрузить хранилище» (`reindex_vault`) теперь автоматически сканируются все базы данных хранилища: старые или неполные манифесты бережно приводятся к новым стандартам (гарантируются корректные ULID-идентификаторы, `membership`, `containerKind`, список свойств и файлы представлений в `.ambd/views/`), свойства синхронизируются в YAML frontmatter заметок, а проекция баз данных SQLite полностью перестраивается.
  - **Устранение ошибки «database was not found»**: исправлена проблема, когда старые базы данных или прикреплённые слои баз данных отображали предупреждение `database was not found` из-за неинициализированной проекции в SQLite. Состояние среды выполнения баз данных теперь мгновенно активируется и связывается с актуальной версией проекции сразу при загрузке или переиндексации хранилища.
  - **Автоматическое самовосстановление по кнопке «Повторить»**: при нажатии кнопки «Повторить» в баннере ошибки базы данных рабочая область автоматически перестраивает проекцию перед повторным запросом, мгновенно восстанавливая доступ к данным без необходимости перезапуска программы.
  - **Надёжный поиск баз данных во вкладках**: исправлен поиск активной базы данных в оркестрации рабочей области, гарантирующий нахождение полной схемы и представлений базы данных даже при отложенной загрузке документа заметки.

- Корректная обработка удаления баз данных и устранение ложных баннеров конфликта:
  - **Автоматическое закрытие вкладок и выгрузка буферов**: при удалении базы данных или папки из хранилища все связанные с ней открытые вкладки автоматически и чисто закрываются, а буферы документов немедленно выгружаются из памяти (`useDocStore`), предотвращая утечку удалённых сущностей.
  - **Устранение ложного баннера «Файл удалён вне Amby»**: при намеренном удалении базы данных или папки пользователем больше не появляется модальное предупреждение о внешнем конфликте удаления на других открытых заметках или слоях.
  - **Корректная обработка отсутствующих баз данных**: если база данных удалена или манифест отсутствует на диске, рабочая область базы данных больше не пытается спамить бэкенд повторными запросами и не падает с ошибкой `database was not found` / «Повторить», а отображает аккуратное состояние «База данных не найдена».
  - **Безопасная обработка внешнего удаления не-Markdown файлов**: при обнаружении внешнего удаления базы данных, холста или наброска система больше не пытается вызывать `restore_deleted_note` (рассчитанную строго на валидные ULID-идентификаторы заметок и вызывавшую системную ошибку) — вместо этого пользователю предлагается безопасное действие «Закрыть» вкладку.

- Полноценная гибридная система свойств заметок: YAML Frontmatter как источник истины, интерактивное редактирование в боковой панели и индексация SQLite:
  - **Свойства в самой Markdown-заметке**: свойства заметки хранятся непосредственно в блоке YAML frontmatter (`.md`) на диске. Добавление, редактирование значений и удаление свойств из правой панели «Свойства» (`InfoPanel`) атомарно записываются прямо в файл заметки, обеспечивая 100% переносимость и совместимость с Obsidian, Git и сторонними редакторами.
  - **Единая кнопка управления свойством в строке**: вся левая часть строки свойства (иконка, название свойства и всё свободное пространство до поля значения) объединена в единую удобную кнопку управления с подсветкой при наведении.
  - **Контекстное меню свойства без обрезания окон**: клик по кнопке свойства открывает компактное всплывающее меню управления (Radix Popover с защитой от выхода за границы экрана через `collisionPadding={16}`). В меню можно:
    - **Изменить иконку**: клик по значку свойства открывает полноценную панель выбора иконок и эмодзи (`EmojiPickerPanel`) без лишней внешней подложки, дублирующих рамок или отступов. Убрана лишняя верхняя строка с дублирующей текстовой кнопкой «Сбросить иконку» — сброс иконки выполняется через штатную кнопку с корзиной в правом углу вкладки панели выбора.
    - **Мгновенный отклик и оптимистичное обновление**: выбор любого эмодзи, значка Lucide или сброс значка немедленно отражается в строке свойства и в меню без ожидания асинхронных ответов бэкенда. Все ключи открытого документа в хранилище синхронизируются мгновенно.
    - **Переименовать свойство**: изменить название ключа в поле ввода по нажатию `Enter` или потере фокуса (старый ключ автоматически и безопасно удаляется из YAML frontmatter, а новый записывается с сохранением значения).
    - **Изменение типа данных и параметров прямо в контекстном меню**: встроенный селектор позволяет на лету сменить тип свойства (текст, число, флажок, дата, выбор, ссылка). При выборе типа «Выбор» прямо в меню открывается поле настройки доступных вариантов (через запятую), а значок свойства в строке динамически отражает выбранный тип.
    - **Интерактивный выпадающий список для типа «Выбор»**: свойства с типом «Выбор» в строке панели отображаются в виде удобного выпадающего списка с настроенными вариантами, позволяя переключать значение в один клик с сохранением в YAML frontmatter заметки.
    - **Удалить свойство**: кнопка удаления с иконкой корзины теперь расположена строго внутри контекстного меню свойства, исключая случайные клики в строке. Служебная корзина на ховере сбоку строки полностью убрана.
  - **Идеальное выравнивание иконок, названий и значений свойств**: иконка свойства (эмодзи или Lucide SVG), название ключа и значение свойства (поле ввода, текст или чекбокс) теперь строго выровнены по одной горизонтальной базовой линии и общему вертикальному центру. Эмодзи-значки центрируются внутри контейнера фиксированного размера без визуального провисания ниже строки, а вертикальные отступы поля ввода синхронизированы с интерактивной кнопкой названия.
  - **Интерактивное редактирование и переключение значений в 1 клик**: логические свойства-чекбоксы переключаются в один клик прямо в панели без перехода в режим исходника; числа и даты редактируются по месту в строке; списки и теги отображаются аккуратными бейджами с мгновенным переходом к редактированию по клику; текстовые свойства поддерживают удобную область ввода с автоматическим сохранением по потере фокуса.
  - **Исключение служебных идентификаторов**: технические идентификаторы документа (`amby-id` и `id`) не засоряют список свойств заметки и остаются доступными в сводном блоке «Сведения» с удобным копированием по клику.
  - **Байт-в-байт безопасность разметки**: запись свойств в frontmatter использует безопасную точечную замену YAML-привязок, строго сохраняя тело заметки, переносы строк (LF/CRLF), комментарии и UTF-8 BOM без малейших повреждений или переформатирования.
  - **Автоматическая синхронизация существующих свойств в Markdown**: при открытии хранилища все свойства, ранее сохранённые в сайдкаре `.amby/properties.json` или SQLite, но отсутствовавшие в frontmatter самих `.md`-файлов, автоматически и бережно дописываются в YAML frontmatter заметок с сохранением типов, значений и безопасным созданием снапшота в истории.
  - **Мгновенная синхронизация со SQLite и сайдкаром**: при любых операциях со свойствами автоматически обновляется индекс `note_custom_properties` в базе данных SQLite и версионированный сайдкар `.amby/properties.json`, обеспечивая мгновенный поиск, фильтрацию и сортировку заметок по свойствам в представлениях баз данных.

- Автоматическая миграция и корректное отображение баз данных:
  - **Автоматическая миграция манифестов `ambd.json`**: устаревшие манифесты `ambd.json` при открытии хранилища автоматически мигрируют в именованные манифесты `<Название_Папки>.json` с присвоением `"containerKind": "standalone"`, исключая появление лишних служебных файлов.
  - **Корректное отображение баз данных в дереве**: устранена проблема, из-за которой базы данных с прикреплённым слоем заметки ошибочно распознавались как обычные бандлы заметок. Любая папка с манифестом базы данных теперь гарантированно отображается как база данных (или супербаза данных при наличии прикреплённых слоёв).

- Стабилизация ввода и сохранения текста заметок и устранение циклических обновлений:
  - **Надёжное сохранение и отзывчивый редактор**: устранено циклическое перечитывание слоёв документа при каждом нажатии клавиши (`Maximum update depth exceeded`), которое блокировало автосохранение и сбрасывало введённый текст к исходному состоянию с диска.
  - **Устранение сброса текста в новых и пустых заметках**: исправлена функция восстановления исходного форматирования `restoreSourceFormatting`. Ранее проверка пустого исходного документа ошибочно возвращала исходную пустую строку вместо сериализованного содержимого, из-за чего введённый в новой заметке текст отбрасывался и автосохранение не запускалось.
  - **Мгновенный индикатор несохранённых изменений**: визуальный редактор Tiptap теперь синхронно при первом нажатии клавиши активирует флаг несохранённых изменений (`onContentDirty`) и отображает точку на вкладке документа ещё до срабатывания дебаунса сериализации.
  - **Стабилизация боковой панели «Свойства»**: устранён циклический перезапрос контекста базы данных при обновлении объекта свойств заметки, а коллекция перетаскиваемых свойств синхронизирована с отфильтрованными свойствами frontmatter.
  - **Корректная инициализация метаданных новых заметок**: при создании новой заметки идентификатор `noteId` и свойства `noteProperties` теперь немедленно передаются в хранилище активного документа, обеспечивая бесшовное сохранение правок и мутаций свойств с первого момента создания.

- Единая шапка документа и прикрепление слоёв к самостоятельным базам данных:
  - **Полнофункциональная шапка**: вкладки самостоятельных баз данных теперь открываются в едином интерфейсе документа Amby с полной поддержкой стандартной шапки: навигационными кнопками назад/вперёд, хлебными крошками пути к файлу, кнопками слоёв и меню действий (`...`).
  - **Прикрепление Заметки, Холста и Наброска**: к любой самостоятельной базе данных теперь можно прикрепить текстовую заметку (`.md`), холст (`.canvas`) или набросок (`.excalidraw`) через меню действий «Прикрепить...». Новые слои атомарно сохраняются прямо в папке базы данных (`<Имя>/<Имя>.md`, `<Имя>/<Имя>.canvas`, `<Имя>/<Имя>.excalidraw`), отображаются в дереве слоёв и мгновенно переключаются через кнопки шапки.
  - **Исправление отображения значка базы данных**: системные идентификаторы `"database"` и `"superdatabase"` теперь правильно нормализуются во всех компонентах вкладок и заголовков страниц, исключая отображение сырого текстового значения `"superdatabase"` перед заголовком и гарантируя отрисовку эталонного значка базы данных как по умолчанию, так и при установке пользовательских иконок.
  - **Корректная инициализация слоя заметки без утечки frontmatter**: при создании слоя заметки или переключении на него служебный блок метаданных `amby-id:` больше не попадает в видимый текст редактора. Тело заметки открывается полностью чистым для ввода текста, а технический идентификатор `amby-id` и ревизия документа связываются в памяти, обеспечивая прозрачное сохранение через стандартный механизм `writeNote`.
  - **Устранение ложного конфликта «Файл удалён вне Amby»**: при добавлении слоя заметки к самостоятельной базе данных устранено ложное срабатывание модального окна внешнего удаления. База данных сохраняет свою идентичность в дереве файлов, слой заметки немедленно индексируется, а редактор корректно инициализирует ревизию и содержимое созданного `.md`-файла для бесшовного редактирования и автосохранения.

- Самостоятельные базы данных и именованный манифест `<Название>.json`:
  - **Первоклассный статус в хранилище**: базы данных теперь могут существовать как полностью самостоятельные документы без обязательной привязки к заметке. В боковой панели файлов автономные базы отображаются собственным узнаваемым значком базы данных, а клик по ним сразу открывает полноценную рабочую область базы данных во вкладке.
  - **Именованный манифест `<Название>.json` вместо `ambd.json`**: при создании базы данных манифест сохраняется как `<Название_Папки>.json` (например, `Задачи/Задачи.json`), восстанавливая архитектурную симметрию со всеми слоями бандлов Amby (`.md`, `.canvas`, `.excalidraw`).
  - **Чистое дерево файлов**: файл манифеста автоматически скрывается из списка дочерних строк-заметок в боковой панели дерева файлов, предотвращая появление лишних технических файлов в интерфейсе.
  - **Сквозное переименование**: при переименовании папки базы данных файл манифеста автоматически переименовывается (`<Старое_Имя>.json` → `<Новое_Имя>.json`), а свойство `"name"` внутри JSON синхронизируется без нарушения целостности связей и представлений.
  - **Полная интеграция с файловыми операциями и обратная совместимость**: автономные базы поддерживают добавление в избранное, перемещение в корзину Amby с возможностью восстановления, назначение пользовательских иконок и карточки баз данных в интерфейсе папок (`FolderView`). Существующие базы данных со старым манифестом `ambd.json` продолжают открываться и работать без изменений.

- Автоматическая синхронизация внешних изменений Холста (`.canvas`) и Набросков (`.excalidraw`):
  - **Мгновенное обновление сцены**: файловый наблюдатель хранилища теперь точно отслеживает изменения файлов `.canvas` и `.excalidraw` от сторонних редакторов. Чистые буферы документов и интерактивные сцены React Flow и Excalidraw обновляются автоматически в реальном времени без перезагрузки приложения или потери фокуса.
  - **Надёжная изоляция при сохранении**: устранены устаревшие замыкания пути документа при переключении и закрытии вкладок. Каждое сохранение холста и наброска направляется строго по целевому пути текущего файла, исключая случайную перезапись других заметок при размонтировании редактора.
  - **Гарантированный сброс при закрытии**: сериализация холста и наброска принудительно вызывается перед закрытием вкладки или сменой активного документа, предотвращая потерю последних правок.

- Глубокая переиндексация хранилища кнопкой «Обновить хранилище»:
  - **Полный повторный скан диска**: команда обновления хранилища теперь выполняет сквозную переиндексацию (`reindex_vault`) на бэкенде с полным сбросом кеша времени модификации (mtime), пересканированием файлов на диске, актуализацией базы метаданных SQLite, дерева файлов, ссылок и тегов.
  - **Синхронизация открытых буферов**: перед переиндексацией принудительно сбрасываются все отложенные автосохранения, а после завершения переиндексации открытые документы, холсты и наброски синхронизируются с актуальным состоянием на диске без конфликтов.

- Симметричная поддержка супер-документов для Холста и Наброска (Суперхолст и Супернабросок):
  - **Единая рабочая область и шапка**: отдельные файлы Canvas (`.canvas`) и Excalidraw (`.excalidraw`) теперь открываются в полнофункциональном интерфейсе документа со стандартной шапкой Amby — с хлебными крошками навигации, значком, переименованием, меню действий и панелью переключения слоёв (Текстовый редактор, Холст, Набросок, База данных).
  - **Надёжная загрузка графических редакторов**: устранена ошибка, из-за которой при открытии наброска или холста отображался пустой экран «Нет открытых заметок». Сессионное восстановление вкладок, клик по дереву и переключение вкладок теперь гарантированно инициализируют буферы Excalidraw и Canvas и активируют соответствующий графический слой по умолчанию.
  - **Прикрепление текстовой заметки и других слоёв**: к любому холсту или наброску можно в один клик прикрепить текстовую заметку («Прикрепить заметку» в меню шапки или контекстном меню файла), а также базу данных, набросок или холст. Прикреплённая заметка сохраняется как полноценный `.md`-файл с идентификатором ULID и синхронизируется в реальном времени.
  - **Вложенные заметки и строгое разграничение слоёв**: холсты и наброски могут содержать дочерние заметки любого уровня вложенности в боковой панели. Полоса вложенных заметок отображается строго только в текстовом слое заметки и исключена из рабочей зоны Холста и Наброска.
  - **Атомарная безопасность и независимое отключение**: при откреплении или удалении привязанных слоёв основной холст или набросок сохраняется без риска перезаписи или повреждения данных.

- Полноценные связи между базами данных (Relations) точь-в-точь как в Notion:
  - **Диалог настройки связи**: выбор целевой базы данных (любой базы хранилища или текущей для связи внутри себя), переключатель ограничения количества элементов («1 страница» или «Без ограничений»), включение двусторонней взаимной связи («Отображать в связанной базе») с настройкой имени парного свойства, а для связей внутри одной базы — выбор между двусторонней иерархической связью (например, Родитель / Подзадача) и взаимной связью.
  - **Интерактивный пикер связей**: всплывающее окно быстрого выбора элементов с поиском в реальном времени, отображением значков и заголовков страниц, чекбоксами выбора, кнопкой очистки всех связей, быстрым открытием выбранной заметки в новой вкладке по клику на стрелочку и созданием новой связанной страницы «на лету» по нажатию Enter.
  - **Отображение ячеек в виде чипов Notion**: связанные записи отображаются компактными аккуратными плашками со значком документа, кликом для открытия заметки, кнопкой удаления крестиком и кнопкой «+» для быстрого добавления новых связей.
  - **Двусторонняя атомарная синхронизация связей**: при включении двусторонней связи система автоматически создаёт парное свойство в целевой базе данных, синхронизирует и удаляет обратные ссылки в записях при любых изменениях, а проекция SQLite индексирует и отображает связи в обе стороны без задержек.

- Единая система блокировки слоёв, панель управления базой данных и контрастное выделение активных элементов:
  - Исправлена разблокировка Холста и Наброска: устранено застревание блокировки из-за устаревшего сигнатурного кеша и привязки к родительскому документу. Разблокировка любого слоя теперь немедленно обновляет рабочую область и снимает ограничение редактирования.
  - Унифицированы подсказки замочка во всех слоях: при редактировании подсказка сообщает «Режим просмотра», при блокировке — «Режим редактирования».
  - В нижней панели заметок выпадающий список заменён на удобный переключатель-замочек (просмотр / редактирование), работающий синхронно с остальными слоями.
  - Для всех слоёв (Текстовый редактор, База данных, Холст, Набросок) кнопки отмены и повтора (Undo/Redo) автоматически скрываются в режиме просмотра и отображаются только в режиме редактирования.
  - В слой Базы данных добавлена полноценная эталонная нижняя панель управления с количеством строк, количеством свойств, стрелками отмены/повтора, переключателем блокировки и настройками ширины контента (с корректными формами склонения числительных в русской и английской локализациях).
  - Улучшена визуальная заметность выбора: кнопки активного слоя в шапке заметки и выбранные опции в меню настроек (ширина контента, отображение вложений, стиль фона холста) выделяются контрастным цветом с чётким акцентом, делая текущий выбор очевидным с первого взгляда.

- Полная изоляция неактивных слоёв документа: устранено визуальное наложение элементов холста (текстовых карточек, связей и узлов) на содержимое заметки и других слоёв при переключении между ними. Для неактивных сохранённых слоёв теперь применяется строгое скрытие из дерева отрисовки (`display: none`), что полностью исключает просвечивание аппаратно-ускоренных графических слоёв браузерного движка (WebKit CoreAnimation CALayers), гарантируя идеально чистый вид активного экрана с безупречным сохранением зума, панорамы и прокрутки при возврате.

- Устранение ложного окна аварийного восстановления при переключении на Холст и Набросок: исправлено ложное появление диалога «Найдена несохранённая версия после аварийного завершения» при переходах между слоями или повторном открытии заметок с холстом и набросками. Пустые шаблоны слоёв теперь используют канонические структуры данных без ошибок парсинга на диске, Excalidraw и Canvas не инициируют фиктивные события сохранения и отметку документа грязным при первичном монтировании, сессионные параметры инструментов исключены из сохраняемого состояния схем, а механизм восстановления сравнивает содержимое холстов и набросков семантически и автоматически удаляет устаревшие пустые черновики без лишних подтверждений.

- Переименование, упорядочивание и сохранение состояния слоёв документа: слои в шапке заметки переименованы в понятные пользователю названия — «Редактор текста», «База данных», «Холст», «Набросок» — и выстроены в строгом порядке во всех меню (кнопки шапки, компактный выпадающий список для узких экранов и подменю прикрепления слоёв). При переключении между слоями одной заметки полностью сохраняется состояние каждого из них: точная позиция вертикальной прокрутки в текстовом редакторе и базе данных не сбрасывается, на холсте сохраняются масштаб, панорамирование и открытое или закрытое состояние миникарты (с сохранением пользовательского выбора), наброски Excalidraw не перезагружают рабочую область, а режим просмотра или редактирования (блокировка от изменений) теперь сохраняется независимо для каждого слоя заметки.

- Стилизация и позиционирование элементов Excalidraw (Наброски): левая панель инструментов и фигур Excalidraw получила объёмную тень (shadow-md), идентичную правой панели управления. Меню настроек набросков теперь гарантированно закрывается при повторном клике на кнопку «Настройки», точно выровнено по правому краю панели управления без смещения, содержит локализованный пункт «Поиск на холсте» и сохраняет аккуратный блок ссылок на сообщество Excalidraw (GitHub, X, Discord). Плавающая кнопка «Библиотека» автоматически скрывается при открытии меню настроек или самой библиотеки, а боковая панель библиотеки Excalidraw преобразована в парящую карточку с эстетичными отступами (0.75rem сверху и справа, 3.5rem снизу над панелью), скруглением, рамкой, эффектом размытия и скрытием неактуальной кнопки докинга.
- Улучшение всплывающего меню настроек заметки и холста: всплывающее меню настроек теперь появляется с аккуратным отступом (8 px) над панелью управления, а его правый край идеально выровнен по правому краю панели управления без смещения. Карточка меню оформлена в едином эстетичном стиле рабочего пространства (rounded-xl, border-border/80, backdrop-blur-md, shadow-lg), заголовок «Настройки» корректно локализован, ширина контента и отображение вложений настраиваются сегментированными переключателями, а избыточный счётчик слов удалён, так как он уже непрерывно отображается в самой панели.
- Устранение ложного всплытия подсказок в дереве хранилища: устранено нежелательное появление подсказки о количестве файлов и папок на активной заметке в дереве при переключении на вкладки холста или набросков. Подсчёт содержимого теперь строго ограничен папками, с рядов обычных заметок сняты лишние подсказки, а глобальный провайдер всплывающих подсказок игнорирует программный фокус элементов без явной навигации с клавиатуры (:focus-visible).

- Единый эталонный стиль нижней панели управления для всех слоёв (Заметки, Canvas, Excalidraw): нижняя панель управления областью стала дизайн-стандартом для всех слоёв Amby. Во всех трёх слоях кнопки упорядочены по единому стандарту с аккуратными разделителями: блоки масштабирования / статистики, стрелки отмены и повтора, переключатель блокировки / режима чтения и кнопка настроек. Карточки заметок, холста и набросков приведены к единому нижнему отступу (mb-2) во вкладках и сплит-виде с бесшовным обнулением в режиме фокуса, а плавающие панели управления, инструментов, миникарта и библиотека получили компактный отступ от нижнего края (8 px), идентичный карточке заметки.
- Компактный дизайн панели фигур Excalidraw и удаление нативной справки: левая нижняя панель инструментов и фигур Excalidraw уменьшена до стандартов интерфейса Amby (высота 36 px, кнопки 28 px, иконки 14 px, скругление rounded-xl, стекло с backdrop-blur и рамка), выровнена по верхнему и нижнему уровню с правой панелью управления областью, а тесные цифры шорткатов на кнопках скрыты. Нативная плавающая кнопка помощи (?) Excalidraw в футере и пункт справки в меню удалены, освобождая рабочую область схемы.

Всплывающая подсказка кнопки подсказывает текущий слой («Справка (Заметка)», «Справка (Холст)», «Справка (Зарисовка)», «Справка (База данных)», «Справка»), а клик открывает обновлённое модальное окно справки сразу на вкладке открытого слоя с горячими клавишами и возможностью быстрого переключения между слоями.

- Самостоятельные файлы `.excalidraw` отображаются в дереве файлов со значком пера, открываются в отдельных вкладках рабочего пространства, могут создаваться через меню создания нового элемента или контекстное меню дерева, а также прикрепляться к существующим заметкам.
- Всплывающие подсказки теперь по умолчанию позиционируются снизу (или сверху при нехватке места внизу экрана), а боковое расположение сохранено точечно — для кнопок вертикальных док-панелей и для подсказок с числом файлов и папок в дереве.
- В таблице базы данных кнопка «...» сдвинута вплотную к кнопке «+» в единую компактную колонку действий, а при клике на неё открывается полноценное меню видимости свойств с возможностью надёжно скрывать и отображать любые колонки, отдельными аккуратными действиями «Показать все» и «Скрыть все», индикацией количества видимых свойств и кнопкой добавления нового поля.
- Компактная плотность интерфейса теперь уменьшает крупные отступы и расстояния между элементами в приложении вдвое, сохраняя безопасные минимумы для кнопок и полей, выравнивание дерева и размеры шрифта.
- Подсказки автоматически скрываются при начале действия, переключении на другое окно или потере фокуса, поэтому больше не зависают поверх открытых настроек и диалогов.
- Таблица базы данных больше не перестраивает всю проекцию при каждом открытии: готовый снимок переиспользуется после быстрой проверки файлов, а изменения записей и представлений обновляются адресно и группируются.
- В таблице базы данных гарантировано появление нижней полосы горизонтальной прокрутки при превышении суммарной ширины колонок над областью видимости: контейнеры строк и шапки строго синхронизированы по ширине содержимого, стандартная ширина колонок свойств увеличена для комфортной читаемости (от 160 px), полоса прокрутки получила контрастную видимую дорожку толщиной 10 px, поддерживается прокрутка жестом трекпада, зажатым Shift или колесом мыши над шапкой, а кнопка добавления новой страницы находится прямо под последней строкой и закреплена слева при горизонтальном скролле.
- В базе данных переработана панель представлений: убрана кнопка с троеточием с вкладок, кнопка добавления представления появляется только при наведении курсора на зону представлений, а клик по активному представлению открывает контекстное меню управления («Переименовать», «Изменить представление» со сменой раскладки, «Отображать» с независимым сохранением режима «Иконка и текст / Только иконка / Только текст» для каждого представления, «Дублировать» и «Удалить»).
- В таблице базы данных улучшено управление колонками: заголовок «Название» теперь можно свободно сужать и расширять (минимальная ширина снижена со 180 до 80 пикселей, разделители получили видимую линию и увеличенную область захвата с цветовой индикацией), всё поле названия свойства в шапке стало интерактивной кнопкой для открытия настроек и переименования, текстовый курсор-каретка отображается только при наведении на ячейки со значениями записей, устранены избыточные отступы слева и справа в ячейках названий (текст больше не обрезается преждевременно), а кнопка быстрого открытия заметки аккуратно появляется поверх текста при наведении на строку.
- Меню свойства стало короче и понятнее: убраны неработающие пункты AI-заполнения, группировки и вычислений, текстовые поля больше не показывают лишнее редактирование настроек, а тип пустого свойства теперь можно изменить из подменю без пересоздания колонки. Если в поле уже есть значения, Amby сохраняет их и отклоняет смену типа вместо скрытой потери данных.
- Иконки типов свойств в базах данных приведены к привычной системе Notion: текст, выбор, множественный выбор, статус, формула, связь и остальные типы теперь легко различимы. В список типов добавлена «Связь» — новая связь по умолчанию соединяет записи текущей базы.
- Исправлено сохранение значений свойства «Связь»: после выбора связанных записей инкрементальная проекция корректно обновляет рёбра, без ошибки SQLite и без необходимости полной пересборки базы.
- Связь теперь можно направить на любую базу: при создании свойства выбирается целевая база, а для уже существующей связи доступна её настройка; в ячейках отображаются строки выбранной базы.
- Смена целевой базы у уже заполненной связи больше не блокируется: сохранённые ссылки остаются нетронутыми и проверяются уже относительно новой базы.
- Новые строки базы получают обычные понятные имена файлов; при совпадении названия добавляется номер («Локация 2»), а технический ID хранится только в метаданных строки.
- При создании базы без выбранной иконки в заголовке снова отображается аккуратная стандартная иконка базы, а не техническое слово `file`; пользовательские эмодзи и иконки по-прежнему сохраняются.
- В меню шаблонов подпись «Пустая страница» заменена на более понятную «Создать новый шаблон».
- В панели инструментов базы данных кнопка создания новой страницы сокращена до «Новая» («New» в английской локализации), а при уменьшении свободного места панель адаптивно сворачивается: действия справа объединяются в компактную кнопку «Настройки», а блок представлений слева сворачивается в единую кнопку активного представления со стрелкой раскрытия вниз (внешний плюс скрывается, а в выпадающем меню доступны переключение между представлениями, их параметры и пункт «Добавить представление»).
- Устранена обрезка карточек заметок и баз данных при малых размерах окна или узких сплит-панелях: нормализованы flex-ограничения ширины во всей цепочке контейнеров (карточки свободно сжимаются до любого размера без выталкивания за край), шапка заметки получила адаптивное сворачивание (скрытие крошек пути на узких экранах, схлопывание кнопок слоёв в компактное выпадающее меню активного слоя и скрытие второстепенных кнопок), нижний статус-бар автоматически скрывает дату при нехватке места, а тулбар базы данных своевременно сворачивается в компактный режим, сохраняя границы карточки и таблицу внутри плавной горизонтальной прокрутки.
- Меню параметров вида (кнопка с ползунками) в базах данных переработано по модели Notion: вверху отображается иконка и название текущего представления с быстрым переименованием, подменю «Раскладка» с моментальным переключением типа (Таблица, Доска, Список, Галерея, График), полноценное подменю «Видимые свойства» с раздельным скрытием и отображением колонок для каждого представления (с кнопками «Показать все» и «Скрыть все» и сохранением состояния), фильтры и сортировка, заглушки «Группировать» и «Цвета» с бейджем «Скоро», копирование ссылки на представление в буфер обмена с визуальным подтверждением, переключатель блокировки базы от редактирования, а также дублирование и удаление представления. На узких экранах при скрытии внешней кнопки создания в начало меню аккуратно добавляются пункты «Новая страница», «Шаблоны» и «Поиск», а настройка ширины контента удалена из таблицы.
- Улучшена контрастность и читаемость светлой темы для бирюзовых, зелёных и имбирных (янтарных) оттенков: акцентные цвета, значки заметок и папок, палитра иконок, цветной текст редактора и системные статусы в светлой теме отображаются в более глубоких и чётких оттенках, сохраняя при этом исходную яркость и насыщенность в тёмной теме.

### Исправления

- Восстановлено автосохранение текста в заметках, прикреплённых к холстам и наброскам: при открытии Amby сразу получает служебный идентификатор и актуальную ревизию слоя, поэтому правки надёжно записываются на диск без ложной блокировки.
- Настройки снова доступны всегда: если отдельное окно настроек не удаётся создать, Amby автоматически открывает тот же интерфейс прямо в основном окне.
- Исправлен сбой при открытии Excalidraw («Amby нужно восстановиться»): исключено попадание временных объектов окружения и списков коллабораторов в сериализуемое состояние холста, добавлена строгая санитизация сохраняемого и загружаемого состояния сцены, а сам редактор защищён локальным барьером ошибок с возможностью быстрого повтора без перезапуска всего приложения.
- Устранено бесконечное зависание индикатора «Загрузка строк…» в базах данных: стабилизирован жизненный цикл запросов при повторных монтированиях, строгом режиме React и быстрых обновлениях фильтров, исключена блокировка сессии в состоянии загрузки.
- Защищена постраничная подгрузка строк в таблице, списке, галерее и доске: добавлен защитный интервал и валидация дистанции прокрутки, предотвращающие неконтролируемую лавину запросов при инерционном скролле на трекпаде.

### Для разработчиков

- Подготовлен подробный план развития баз данных: последовательные задачи, проверки сохранности данных и производительности, критерии готовности и журнал продолжения работы.

- Док больше не скрывается отдельно: в меню осталось только закрепление левой и правой панели, а откреплённые панели вместе с доком автоматически раскрываются поверх основного содержимого с аккуратной тенью и скруглёнными краями.

### Улучшения

- В правой части строк появился слабозаметный индикатор типа элемента: папки отмечаются папкой, заметки — файлом, а избранные заметки — файлом со звездочкой. Иконка файла теперь работает как кнопка избранного: по нажатию заметку можно добавить или убрать из избранного. В разделе избранного сохраняются пользовательские эмодзи, кнопка снятия избранного отображается таким же чётким акцентным цветом, а действие избранного в контекстном меню обозначается обычной звездой в цвете текущего оформления.
- Двойной клик по заметке, Canvas или папке в дереве сразу включает переименование с выделением названия.
- Папки теперь всегда располагаются вверху каждого уровня дерева, а обычные заметки и заметки с вложениями сортируются вместе по выбранному имени или дате.
- Перемещение, переименование и активация хранилища теперь согласуются общим шлюзом, а тяжёлые файловые и ссылочные операции не удерживают SQLite-блокировку.
- Граф связей корректно обновляет новые рёбра, Canvas не перепарсивается на каждом кадре, а ручки блоков стали отзывчивее в больших заметках.
- Тяжёлые редакторы активных и split-вкладок получают адресные обновления; скрытые буферы не подписывают весь workspace на каждую правку.
- Проверка совместимости выделенного Markdown выполняется только при смене режима редактора, а не при каждом движении курсора.
- Квота recovery рассчитывается по метаданным без полного повторного чтения всех черновиков; операции recovery сериализованы без блокировки основного сохранения.
- Граф обновляет координаты SVG напрямую через DOM, а таблица и ручки блоков ограничивают работу до необходимых кадров, диапазонов и инвалидирующих событий.
- Индекс заметки после записи строится из уже подготовленных байтов и метаданных, а файловые мутации удерживают SQLite-блокировку только на коротких фазах.
- Перенос и создание файлов больше не запускают повторные полные сканирования хранилища и пересчёт ссылок, поэтому операции выполняются заметно быстрее.
- Перенос файлов в дереве теперь применяется сразу без визуальной перезагрузки, а несколько выбранных файлов можно переместить одним перетаскиванием.
- Дерево файлов обновляет только изменённые ветки, а новая заметка появляется сразу — без промежуточных пустых папок, повторной подгрузки и рывков.
- Появление и скрытие откреплённых панелей стало заметно плавнее.

## 0.1.1 — 2026-09-08

Первое накопительное обновление: Amby получил встроенную систему обновлений и публичный учёт изменений.

### Новое

- Добавлена система безопасных обновлений через GitHub Releases: приложение проверяет доступность новой версии и устанавливает только подписанные сборки.
- В общих настройках появился раздел «Обновления» с переключателем автопроверки, текущим номером версии и кнопкой ручной проверки.
- Во время загрузки и установки отображается понятный статус и прогресс. Перед автоматической установкой Amby запрашивает подтверждение перезапуска.
- Создан публичный журнал изменений `updates.md`, в котором улучшения накапливаются до следующего выпуска.

### Улучшения

- Настройка автообновления сохраняется глобально и синхронизируется между главным окном и отдельным окном настроек.
- Версии npm, Rust и Tauri теперь проверяются на совпадение перед сборкой релиза.

### Безопасность

- Пакеты обновлений проверяются встроенным публичным ключом; неподписанные или изменённые файлы не устанавливаются.
- Доступ к проверке, установке и перезапуску предоставлен только главному окну и окну настроек.

### Для разработчиков

- Добавлен GitHub Actions-процесс для накопительной сборки macOS, Windows и Linux, создания `latest.json` и публикации релиза только после успешного завершения всех платформ.
- Обычная локальная сборка не требует release-ключа: updater-артефакты включаются отдельной release-конфигурацией.
- Добавлены тесты настроек автообновления, расчёта прогресса и ограничений Tauri permissions.
- Закреплён накопительный процесс выпуска: каждое изменение добавляется в публичный журнал, а patch-версия повышается один раз перед явно запрошенными commit и push.
- Исправлена Linux-сборка диалоговых окон и добавлены необходимые системные зависимости в CI; проверки также совместимы с новым Clippy.
