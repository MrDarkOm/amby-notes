# Amby — Следующая версия

## Новое

## Улучшения

- Если одна вкладка (документ, база данных, холст, мастерская, граф) или одна боковая панель ломается, теперь закрывается только она: на её месте появляется сообщение и кнопка «Попробовать снова», а остальное окно продолжает работать. Раньше ошибка заменяла всё окно.

- В настройках модулей убрана строка установки, удаления, экспорта и проверки версии: остались только переключатели включения. Модуль, удалённый в прежних версиях, возвращается автоматически.

## Исправления

- Если одна команда приложения неожиданно падала в момент работы с хранилищем, все следующие команды падали тоже, пока не перезапустишь Amby. Теперь приложение записывает предупреждение в журнал и продолжает работать; файлы и история при этом пишутся атомарно, поэтому данные не страдают.

- Вложенный слой заметки у базы данных мог остаться пустым, если во время его чтения менялись данные о слоях документа: загрузка отменялась и больше не повторялась. Теперь она повторяется.

- Встроенные модули (в том числе ИИ) снова устанавливаются кнопкой в «Настройки → Модули» без скачивания: их код уже входит в приложение, поэтому установка только отмечает модуль в реестре. Раньше она пыталась скачать пакет и могла завершиться ошибкой.

- Подключения ИИ теперь хранятся в отдельном файле `ai-connections.json`, а не внутри `settings.json`. Более старая сборка Amby, запущенная на тех же данных, больше не может их стереть: она по-прежнему читает свой прежний раздел в `settings.json`. При первом открытии настроек ИИ данные переносятся автоматически с резервной копией; настройки, которые стёрла старая сборка, восстанавливаются из прежнего переноса.

## Для разработчиков

- Удалена поддержка старых форматов, которых больше нет у пользователей. Файлы на диске не удаляются и не меняются, они просто перестают читаться: миграция баз (четыре команды `detect/preflight/execute/rollback_database_migration`), перенос значений из `.ambd/records` во frontmatter при открытии базы, диагностика проектов формата v2 (`amby-project.json`) и строка «Папки старого формата» в панели творчества, перенос скрытых колонок из localStorage в вид, миграция конфигурации модулей в `workspace.json` (файл без профиля получает стандартный профиль). Журналы ID-миграции старейшего вида (только список путей) по-прежнему пропускаются при проверке.
- Подключения ИИ читаются только из `ai-connections.json`; перенос из `settings.json`, команды `migrate_ai_settings`/`rollback_ai_settings` и чтение старого раздела `ai` удалены. Раздел `ai` в `settings.json` и файлы `settings.ai-v1.*`, `settings.pre-ai-connections.backup.json` не читаются, не меняются и не удаляются. Нет файла — нет подключений.
- Из `discovery.rs` убран неиспользуемый ремонт старых манифестов; манифест `ambd.json` теперь называется просто `DATABASE_MANIFEST`.
- Для мьютексов хранилища есть помощник `lock_or_recover` (`src-tauri/src/lock_util.rs`) вместо `.lock().unwrap()`. Подавления `react-hooks/exhaustive-deps` просмотрены: у каждого оставшегося есть однострочная причина. Общая граница ошибок для вкладок и панелей — `surface-error-boundary.tsx`.

- В правила проекта добавлено: формат существующего ключа или файла настроек нельзя менять на месте, несовместимый формат хранится под новым ключом или в новом файле. Настройки выносятся в отдельные файлы только при конкретной причине.
- Из Rust-кода убрана ненужная пометка «неиспользуемый код» там, где код нужен только тестам (он теперь собирается только в тестах), и удалена неиспользуемая функция переноса свойств в заметки вместе с её тестом. Формат данных и поведение приложения не менялись.
- Деление больших файлов без изменения поведения: `src-tauri/src/database/mutations.rs` (3,7 тыс. строк) стал каталогом `mutations/` с модулями по видам мутаций (создание базы, свойства, параметры и настройки свойств, значения-связи, пакеты значений), а его тесты (91 тест, ни один не потерян) разложены в `mutations/tests/` рядом с теми же названиями. Публичные пути `database::mutations::*` не изменились.
- Деление больших файлов без изменения поведения: `database-workspace.tsx` (3,3 тыс. строк) разделён на хуки по задачам (виды и их действия, свойства, строки, заголовок, история, панель настроек) и компоненты (заголовок, вкладки видов, кнопки панели, область видов, панель настроек). Для окна базы данных добавлен смоковый тест `database-workspace.test.tsx`, написанный до переноса и прошедший на старом и на новом коде.
