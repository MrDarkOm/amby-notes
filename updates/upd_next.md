# Amby — Следующая версия

## Для разработчиков

- Начата зашифрованная синхронизация (этапы Э0 и Э1 «тесты до кода»). Каркас `sync/`: отдельный Cargo workspace (`proto`, `core`, `server`, `conformance`, лицензия AGPL-3.0-only), `cargo-deny`, задача `sync.yml` в CI, команды `npm run sync:test`, `sync:lint`, `sync:req-check`, `sync:mutants`, `sync:fuzz`, окружение Python для эталона. `sync:req-check` проверяет, что каждое требование плана названо хотя бы в одном тесте.
- В план синхронизации добавлено приложение «Точный формат v1»: строки HKDF, обёртки ключей, канонический JSON заголовка, раскладка тела STREAM, формула Padmé, код восстановления, параметры Argon2id. Каждое решение помечено «на проверку Opus».
- Написаны тесты криптографии (95 штук) и независимый эталон на Python, который по плану выдаёт векторы формата. Реализации ещё нет: все тесты падают на заглушках `todo!()`, так и задумано. Приложение пока не использует `sync/`.
- Написана криптография синхронизации (этап Э1, `sync/core/src/crypto/`) строго по приложению «Точный формат v1»: пароль и код восстановления → ключи, обёртки ключей аккаунта и пространства, зашифрованный заголовок записи, тело по кускам (STREAM) с размером Padmé. Все 95 тестов проходят, `cargo test` в CI больше не «информационный». Тесты и эталон не менялись. Из внешних библиотек добавлен только `serde` (он и так входит в `serde_json`) ради строгого запрета повторяющихся ключей в заголовке. Приложение по-прежнему не использует `sync/`.
- Сделан этап Э2 «тесты до кода» для сервера синхронизации. В план добавлено приложение «Протокол v1» (решения П1–П41: каждый запрос, коды ошибок, атомарный коммит, лента изменений, SSE, ограничение попыток, уборка, команды администратора, настройки), проверены Opus (сжатая лента изменений, два счётчика попыток входа, квота, шифрование имён устройств, 10 000 записей в коммите). В `sync/server` лежит только интерфейс: настройки, часы, хранилища за интерфейсами, все запросы отвечают `501 not_implemented`. Набор проверки `sync/conformance` (170 тестов по HTTP с настоящей криптографией ядра, плюс 8 тестов настроек сервера) работает против любого адреса; все 178 тестов падают на заглушке по нужной причине, как и задумано. Добавлены `Dockerfile` и скрипт `npm run sync:conformance:docker`, `npm run sync:conformance:red` разбирает падения по причинам. Набор проверен и против контейнера: образ заглушки собирается, все тесты падают по `not_implemented`. Приложение по-прежнему не использует `sync/`.
- Описан план зашифрованной синхронизации через собственный сервер в Docker: что обещаем пользователю, модель угроз, ключи и протокол, поведение при конфликтах и сбоях, этапы работ. Тесты на каждое требование пишутся до кода и должны сначала падать. Кода пока нет.
- Бот CLA теперь работает и для пулл-реквестов в `dev` (туда их направляет `CONTRIBUTING.md`) и ссылается на `CLA.md` из `dev`, а не из `main`, где файла пока нет.
- В репозитории включены приватные сообщения об уязвимостях (на них ссылается `CONTRIBUTING.md`), поиск утёкших секретов и блокировка push с секретами.
- В списке версий `updates/README.md` появились 0.1.5–0.1.9.
- Линтер снова без предупреждений: перетаскивание окна за шапку описано в одном месте вместо двух копий (из шапки страницы в режиме фокуса щелчок по кнопке теперь тоже не начинает перетаскивание окна), раздел «Модули» берёт текущий список модулей через ссылку, а не из устаревшего значения, у ручек блоков указаны все зависимости.
