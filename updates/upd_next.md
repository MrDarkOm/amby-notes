# Amby — Следующая версия

- Выпуск: подготовлена бета 7 цикла 0.1.9 с исправлениями изображений Windows, закрытия и восстановления окон и обработки Enter при вводе через IME. Заметки к выпуску обновлены; окончательная проверка жизненного цикла обычной установленной Windows-сборки остаётся отдельным сценарием.

- Изображения: исправлена блокировка локальных вложений на Windows — картинки, добавленные через меню или буфер обмена, снова могут загружаться. Разрешены только точные локальные адреса протокола Tauri; загрузка изображений с посторонних серверов остаётся запрещённой.
- Для разработчиков: нативный стенд использует общий с приложением обработчик закрытия и восстановления окон; браузерный тест проверяет загрузку вложений с Windows-адресов под политикой безопасности выпуска.

- Окно: Amby больше не остаётся работать без окна. Раньше после закрытия главного окна приложение продолжало висеть в Dock (его держало невидимое окно настроек), а клик по иконке ничего не открывал; свёрнутое окно тоже не разворачивалось по клику на иконку в Dock. Теперь вместе с главным окном закрываются настройки, и если других окон нет, приложение завершается; клик по иконке в Dock и повторный запуск разворачивают свёрнутое окно, а закрытое — открывают заново.
- Обновления: бета снова сможет сама обновиться на следующую бету. С беты 4 приложение сверяет версию, записанную в подписи обновления, с версией в ленте, а беты подписывались как `0.1.9` без номера беты, поэтому бета 4 не ставила бету 5. Теперь бета подписывается полной версией (`0.1.9-beta.6`), а выпуск, у которого подпись и лента расходятся, не публикуется. Бета 5 этой ошибкой уже не исправится, но бету 6 любая прежняя бета поставит сама. Если обновление не установилось, в настройках и в журнале уведомлений видно, какая версия, и есть ссылка «Скачать версию вручную» на её страницу в GitHub.

- Для разработчиков: журнал отладки теперь говорит, почему не прочиталась заметка (её нет в индексе, файла нет на диске, файл не в UTF-8, нет доступа) и почему не установилось обновление (нет прав заменить приложение, подпись не совпала, временная папка на другом диске, сеть) — кодом, без текста ошибки и путей. Раньше в журнале было только «ошибка», и причину нельзя было найти.
- Для разработчиков: проверки выпуска снова проходят на Linux и Windows — убрано лишнее условие, на которое ругался новый Clippy под Windows, тест переноса архива больше не зависит от того, сохраняет ли копирование время файла, а тесты запаса места сервера на Windows пропускаются (там сервер место не измеряет; рабочий сервер — в Docker на Linux).
- Синхронизация: удалить копию хранилища с сервера теперь можно только с текущим паролем — кроме точного названия, окно спрашивает пароль; неверный пароль ничего не удаляет и не выключает синхронизацию, окно просто спрашивает снова. После смены пароля приложение предлагает отключить остальные устройства: они перестанут синхронизироваться и попросят войти с новым паролем, их файлы останутся. Сервер синхронизации больше не отвечает по незащищённому `http://` — только по HTTPS.
- Синхронизация: в окне конфликта оформления свойств на компьютере, который получил этот конфликт с другого, подписи «Этот компьютер» и «Другой компьютер» больше не перепутаны — как и кнопки «Оставить с этого компьютера» / «Взять с другого». Раньше выбор «этого» оставлял версию другого компьютера.
- Для разработчиков: появилось публичное описание протокола и формата синхронизации v1 (`docs/sync-format.md`) — для тех, кто поднимает свой сервер или пишет свой клиент: шифрование, все запросы сервера, коды ошибок, настройки и команды администратора. Поведение приложения не изменилось.
- Свой сервер синхронизации защищён от перегрузки: он держит запас свободного места на диске (по умолчанию 1 ГБ) и при нехватке перестаёт принимать новое, но даёт читать и удалять; можно ограничить число аккаунтов открытой регистрации; запросы входа не больше 64 КБ; большие запросы читаются не больше четырёх одновременно, остальные получают «сервер занят» и повторяются позже. Без подписки удалять можно только то, что действительно лежит на сервере. В приложении для этих случаев понятные сообщения.
- Синхронизация: большое хранилище (тысячи файлов) или переименование большой папки больше не застревает на втором компьютере. Раньше первая выгрузка уходила одним огромным пакетом, который другие устройства не могли прочитать; теперь изменения отправляются частями, а уже лежащие на сервере большие пакеты читаются. Сервер также надёжнее отказывает запросам к только что удалённому хранилищу и запросам отключённого устройства: такая запись больше не может попасть в чужое хранилище.
- Синхронизация по подписке: зарегистрироваться можно свободно, но отправлять файлы на сервер может только аккаунт с подпиской. Без неё аккаунт работает (вход, логин, имена устройств, пароль), а с данными на сервере можно делать всё, кроме добавления: скачать, вернуть прежние версии, удалить файлы или хранилище целиком. В настройках аккаунта видно «Без подписки · синхронизация недоступна» и кнопка «Оформить подписку»: оплаты пока нет, кнопка показывает подсказку, что подписку выдаёт администратор сервера. С подпиской показан её срок. Файлы, ждущие подписки, остаются на компьютере и уходят сами, как только подписка появится. Администратор сервера выдаёт и снимает подписку командой `user plan set` (можно со сроком `--until`). Свой сервер без файла тарифов работает как раньше.
- Для разработчиков: проведена проверка безопасности синхронизации (сервер, клиент, связка в приложении, настройки своего сервера). Отчёт — `docs/road/target/sync-security-review.md`: утечек содержимого и ключей не найдено; найдены риски доступности и ресурсов (общий объём диска при открытой регистрации, большой коммит, который не читают другие устройства, гонка после удаления пространства, пределы запросов). Исправления пойдут отдельно, тестами вперёд. Поведение приложения не изменилось.
- Для разработчиков: начата подготовка удаления серверной копии хранилища из приложения — описаны правила и добавлены интерфейсы-заглушки и тесты перед реализацией. Локальные заметки, вложения, история и данные восстановления должны сохраняться на всех устройствах. Само удаление пока недоступно.

- Исправлено сохранение отложенных изменений холстов и скетчей после переименования или переноса: запись использует новый путь и прежнюю ревизию файла. Перенос recovery-черновика сохраняет новые правки и не затирает уже существующий черновик по новому пути.
- Исправлено обновление открытых заметок: если переименование или перенос переписывает ссылки, чистая заметка перечитывается, а несохранённая правка сохраняется и показывает конфликт. При синхронизации панель свойств также обновляется после удаления или переноса файла свойств. Создание, переименование, перенос и удаление файлов также сообщаются другим окнам.
- Исправлено обновление между окнами после сохранения холста или скетча, восстановления версии или содержимого архива и изменения базы или свойств. При открытых несохранённых правках сохраняется обычная защита от конфликта. Открытая история перечитывает список после новых снимков, а сохранённая копия конфликта сразу появляется в дереве. Открытый холст или скетч больше не закрывается автоматически, если файл исчез из дерева после внешнего изменения.
- Синхронизация сначала завершает пакет файлов, а затем сообщает об изменениях открытым базам и мастерской, чтобы они не перечитывали данные посреди пакета. Перед перестройкой базы Amby также обновляет индекс полученных заметок, чтобы новые строки не пропадали из списка.
- Синхронизация: переименование заметки вместе с правкой больше не уходит на сервер как удаление и новая заметка, если синхронизация как раз шла в этот момент. Раньше такой проход мог увидеть переименованный файл раньше, чем получил пометку о переименовании, и отправить старый путь как удалённый — на другом компьютере старая заметка уходила в корзину, а новая появлялась отдельно (данные при этом не терялись). Теперь проход спрашивает пометки уже после чтения хранилища; пометка, переименование которой он ещё не увидел, ждёт следующего прохода.
- Исправлено: Enter, которым подтверждается ввод через IME (китайский, японский, корейский, диктовка и акценты на macOS), больше не срабатывает как «переименовать», «сохранить», «отправить» или «подтвердить» — включая окно подтверждения с вводом точного названия. Общая проверка `isEnterKey` теперь стоит во всех собственных полях ввода, а ESLint не даёт сравнивать `event.key` с «Enter» напрямую.
- Для разработчиков: в руководство для агентов добавлена политика браузерных движков (WKWebView, WebView2, WebKitGTK): какие возможности веб-платформы можно использовать и когда нужна проверка поддержки с запасным вариантом. Поведение приложения не изменилось.
- Для разработчиков: проведена сверка настроек безопасности Tauri с внешним чеклистом. Открытие ссылок и вложений, CSP и права окон уже были в порядке. В правила записаны две вещи: каждая команда приложения сама проверяет входные данные, потому что её может вызвать любое окно; защиту `freezePrototype` включать нельзя, с ней приложение не запускается из-за библиотеки d3. Для Claude Code добавлены три проектных скила (команды IPC, строки интерфейса, выпуск версии) — только на ветке `dev`. Поведение приложения не изменилось.

- Исправлено опасное удаление: если в корне хранилища лежит заметка с тем же именем, что и папка хранилища (например, `Notes/Notes.md`), «Удалить», «Удалить навсегда», «В архив», «Переименовать» и «Переместить» теперь действуют только на эту заметку. Раньше Amby принимал её за главную заметку «пакета», папкой которого считал всё хранилище: удаление навсегда стирало всё хранилище вместе с историей, обычное удаление отправляло его целиком в системную корзину, а переименование переименовывало папку хранилища. Само хранилище и служебную папку `.amby` теперь нельзя удалить ни в одном режиме.
- Исправлена потеря текста при полном диске: если заметка не сохранилась и черновик восстановления тоже не записался, окно больше не закрывается молча и хранилище не переключается. Amby спрашивает «Закрыть окно и потерять несохранённый текст?» (или «Переключить хранилище…»), а по умолчанию окно остаётся открытым — можно освободить место и сохранить снова. Если черновик записан, всё работает как раньше. Карточка «Не удалось сохранить заметку» больше не обещает черновик, которого может не быть.
- Исправлено на macOS: выход по Cmd+Q и через «Завершить» в меню приложения больше не теряет последние правки. Раньше приложение завершалось сразу, и текст, набранный за последнюю секунду, не успевал сохраниться. Теперь выход закрывает окна так же, как кнопка закрытия: они сначала сохраняют правки, а если текст может пропасть (полный диск) — спрашивают. «Завершить» из меню Dock и выход из системы пока работают по-старому.
- Исправлено: внешняя правка заметки (из другого окна, другой программы или синхронизации) больше не затирается молча старым текстом. Раньше, если вы набрали и тут же стёрли символ, заметка на мгновение выглядела сохранённой, хотя её сохранение ещё ждало в очереди. Пришедшая в этот момент внешняя правка подставлялась в редактор, а через полсекунды поверх неё на диск записывался ваш прежний текст. Теперь такая заметка считается несохранённой, и внешняя правка показывается как конфликт.
- Холсты и скетчи больше не теряются молча. Холст с меткой порядка байтов (BOM) или без списка связей (так бывает у файлов из других программ) теперь открывается со всем содержимым. Раньше такой файл открывался пустым, и первая же правка заменяла на диске весь холст. Файл, который действительно нельзя прочитать, больше не открывается пустым: Amby пишет под деревом «Не удалось прочитать …» и ничего в него не сохраняет. Если холст или скетч не удалось сохранить (например, на полном диске), заметка показывает карточку «Не удалось сохранить», как обычная заметка, а на вкладке видна точка «не сохранено».
- Исправлено: действия из меню блока (ручка слева от строки), сделанные только мышью, снова сохраняются. Раньше, если сразу после открытия заметки удалить, дублировать, превратить блок в другой или сменить цвет выноски, ничего не набирая с клавиатуры, изменение было видно на экране, но не попадало в файл и пропадало при повторном открытии.
- Исправлено: одна заметка в чужой кодировке больше не мешает открыть хранилище. Раньше файл, сохранённый не в UTF-8 (например, «Юникод» из Блокнота Windows или старый экспорт в cp1251), не давал открыть хранилище, а в уже открытом — ни одну заметку. Теперь такая заметка пропускается, о ней сообщается, а её прежняя версия в поиске и дереве сохраняется. Сам файл Amby не трогает; когда его пересохранят в UTF-8, он вернётся.
- Исправлено: заголовки и таблицы больше не портятся при сохранении. Раньше Shift+Enter в заголовке сохранялся как заголовок с лишней «\» и отдельный абзац, а Enter или Shift+Enter в ячейке таблицы сливал строки ячейки или оставлял в ней «\». Список или заголовок, созданный внутри ячейки, после сохранения превращался в простой текст. Теперь эти клавиши в заголовке и в ячейке ничего не делают, а ячейка, как и в Markdown, хранит одну строку текста.
- Исправлено: история заметки больше не теряется при переименовании и переносе. Раньше после переименования или переноса заметки (или папки с ней) панель «История» была пуста: версии оставались на диске, но были привязаны к старому имени. А новая заметка, созданная под старым именем, показывала чужие версии, и «Вернуть» могло записать в неё текст другой заметки. Теперь версии переходят вместе с заметкой.
- Безопасность и сохранность данных, несколько мелких исправлений:
  - восстановление из служебной корзины больше не переносит в хранилище посторонний файл, если её запись подменена (например, в чужой резервной копии);
  - автоматическая очистка истории больше не удаляет последние «страховочные» версии — исходный текст до переписывания в Live, версию, заменённую синхронизацией, и версию, заменённую восстановлением;
  - синхронизация больше не записывает файлы в служебные папки `.git`, `.amby` и `.obsidian`, если их имя пришло в другом регистре (`.GIT`, `.Amby`) или в коротком виде Windows (`GIT~1`);
  - после внутренней ошибки синхронизации открытые заметки снова узнают о правках извне, без перезапуска.
- Для разработчиков: CI и проверка выпуска теперь действительно ловят устаревший `src/lib/bindings.ts`: раньше проверка сравнивала файл, только что перегенерированный тестами, с ним же самим.
- Для разработчиков: проведено полное ревью кодовой базы только на чтение (11 областей, каждая находка уровня Critical и High проверена отдельно). Отчёт — `docs/audit/2026-11-15-code-review.md`. Главное: удаление или переименование корневой заметки с именем папки хранилища действует на всё хранилище; при полном диске закрытие окна может потерять текст; Cmd+Q и действия меню блока мышью могут не сохранить последние правки; один файл не в UTF-8 мешает открыть хранилище. Исправления пойдут отдельно, тестами вперёд. Поведение приложения не изменилось.

## Новое

- Синхронизация: прежние версии заметки и удалённые файлы теперь можно вернуть с сервера. В истории заметки версии с сервера идут в одном списке с локальными, с облачком и подписью устройства; на новом компьютере или после очистки истории они единственные. Удалённые файлы лежат в архиве в разделе «На сервере»: отметьте нужные и нажмите «Вернуть» — если путь занят, файл ложится рядом («Имя 2.md»), ничего не затирается. Перед возвратом версии текущий текст сохраняется в истории. Без связи или при выключенной синхронизации вместо списка одна спокойная строка.
- Синхронизация: в истории заметки снимок, который есть и на сервере, получает облачко «Есть на сервере» с названием устройства; отдельной строки для такой версии по-прежнему нет. Если текущий текст совпадает с последней версией на сервере, вверху списка одна спокойная строка «Текущий текст сохранён на сервере». То же в боковой панели. В архиве запись корзины, которую сервер тоже хранит, помечена облачком «есть на сервере до …». Без связи или при выключенной синхронизации отметок нет. Это только показ: записи на диск не изменились.
- Синхронизация: в настройках можно сменить пароль. Нужен старый пароль; остальные устройства и код восстановления продолжают работать, данные не перешифровываются.

## Улучшения

- Если новое имя заметки не принято (занято или содержит недопустимые символы), причина теперь видна сразу под полем: в дереве файлов, в названии строки базы, в меню строки и в карточках доски и галереи. Поле остаётся открытым с тем, что вы ввели, под ним строка вроде «Такое название уже занято. Введите другое.»; она уходит, когда имя меняется, и по Esc. Раньше имя молча оставалось прежним. Данные при этом не затрагиваются.
- Центр уведомлений. Колокольчик в доке открывает не боковую панель, а стопку спокойных карточек прямо у себя: она растёт вверх от кнопки, закрывается повторным нажатием, кликом мимо и Esc. Сверху «Требует решения» (конфликты синхронизации с кнопкой «Сравнить», остановки синхронизации, заметки, которые не сохранились или изменились вне Amby, найденные черновики), затем «Внимание» (лимиты тарифа и файлы с ошибками; запись можно скрыть, она вернётся, только если причина исчезнет и появится снова), внизу «Ранее» — журнал за 7 дней (заметка вернулась, правки двух компьютеров объединены, итог выбора в конфликте, резервная копия готова, сбой проверки обновлений): три последние строки, «Показать все» и «Очистить». Число на колокольчике считает первые два раздела, журнал его не меняет. Стопка лежит на одной подложке, как всплывающие меню (фон, рамка, тень), и отстоит от края дока на 12 пикселей, так что кнопки дока не перекрыты; тосты стоят с тем же отступом. Карточки выглядят спокойно: обычная поверхность, тонкая рамка, цветная полоска слева и значок уровня, без цветной заливки. Всплывающие сообщения стоят там же, у колокольчика, и только для опасности и решений о том, чего нет на экране (новый конфликт закрытой заметки, остановка синхронизации, сбой сохранения закрытой заметки): 10 секунд, не больше трёх, остальные — «ещё N»; нажатие на сообщение открывает стопку, а пока стопка открыта, сообщений нет. Если заметка не сохранилась после закрытия, больше нет системного окна: карточка в центре и сообщение «Заметка «Имя» не сохранилась — Текст в черновике, не потерян». Когда программа слила правки двух компьютеров, открытая заметка тихо говорит об этом («Прежняя версия — в истории»). Тексты исправлены по роду: «Заметка «Дневник» не сохранилась», «Заметка «Имя» изменена на двух компьютерах».

- Конфликт синхронизации заметки стал проще. В списке колокольчика, в настройках и в карточке заметки теперь заголовок «“Имя” изменили на двух компьютерах», строка «Обе версии целы» и одна кнопка «Сравнить»: без путей, слов «основной файл» и «копия» и абзаца с пояснениями. Выбирать нужно в окне сравнения, где видны обе версии: «Оставить версию в заметке» и «Взять вторую версию», а «Сохранить обе как отдельные заметки» спрятано в меню «…». Подписи сторон — «Версия в заметке» и «Вторая версия»: приложение не знает наверняка, с какого компьютера вторая, и не утверждает этого. После выбора сказано, что сделано и где осталась вторая версия («в корзине хранилища» или «в истории заметки», в последнем случае есть кнопка «Открыть историю»): карточкой в открытой заметке или строкой в списке колокольчика. Если в окне выбрать по-своему хотя бы один абзац, главная кнопка сама становится «Собрать из выбранного» (рядом «Сбросить выбор»), так что выбор по абзацам нельзя потерять случайным нажатием. Данные при этом ведут себя как прежде.
- Уведомления заметки стали компактнее. Свёрнутые, они теперь маленькая пилюля у правого края нижней панели, с зазором над ней (раньше полоса была такой же ширины, как панель, и выглядывала из-за неё): иконка самого серьёзного уведомления, его короткий заголовок, «+N» при остальных и шеврон. Развёрнутые, они лежат в скруглённой панели на той же поверхности, что и стопка у колокольчика, со строкой «Уведомления заметки · N» сверху и карточками отдельными плитками; панель не шире области заметки и не перекрывает кнопки нижней панели. Порядок и уровни карточек не изменились, опасность и решение по-прежнему раскрывают панель сами.
- Полоса уведомлений заметки в свёрнутом виде стала шире (не меньше 300 пикселей, растёт влево от нижней панели), поэтому заголовок обычно виден целиком. Карточки в развёрнутой полосе идут от самых серьёзных к менее серьёзным: опасность, нужно решение, внимание, сведения.
- Уведомления заметки теперь выглядят как полоса, которая выглядывает из-за нижней панели заметки («Только что · 19 сл.»): в свёрнутом виде это одна строка с иконкой самого серьёзного уведомления, его заголовком, «+N» и цветной точкой, по клику она разворачивается вверх в панель со всеми карточками. Вместо лампочки и плавающей стопки. Сама разворачивается только при опасности или когда нужно решение.
- Плавающий значок конфликтов синхронизации в углу окна убран: в доке внизу, над настройками, появилась обычная кнопка-колокольчик «Уведомления». На ней число конфликтов и предупреждений о лимитах тарифа, цвет по самому серьёзному; по клику рядом открывается список конфликтов.
- Уведомления заметки: предупреждения о повреждённой или незакрытой шапке и о расхождениях значений при переводе свойств больше не раскрывают стопку сами, а ждут клика по лампочке. Потеря ID заметки и режим «свойства только для чтения», наоборот, теперь раскрываются сами, как просьба решить. Цвет лампочки показывает самый серьёзный уровень карточек: красный, оранжевый или жёлтый; если есть только сведения, она нейтральная.
- Синхронизация: конфликт оформления свойств решается по заметкам. В настройках синхронизации видно, какие заметки изменили по-разному на двух компьютерах; для каждой выбирается «С этого компьютера» или «С другого», а правки остальных заметок соединяются сами и больше не пропадают при выборе одной версии.
- Синхронизация: два хранилища, которые перешли на новый формат свойств каждое у себя и встречаются впервые, сливают оформление свойств по заметкам. Правки разных заметок соединяются сами, в конфликт попадают только заметки, изменённые по-разному на обоих компьютерах.
- Первое открытие большого хранилища новой версией стало быстрее: проверка повторяющихся `amby-id` больше не перебирает все заметки ради каждой. Подготовка переноса свойств для 50 000 заметок — 4 секунды вместо почти двух минут.
- Синхронизация: конфликт служебных данных Amby (свойства заметок, расположение графа) описан словами, без путей вроде `.amby/properties.json`. У него два выбора, «Оставить с этого компьютера» и «Взять с другого компьютера», и предупреждение, что правки невыбранной стороны пропадут. Кнопки «Оставить оба» и «Сравнить» для таких файлов убраны: вторая копия служебного файла никому не нужна.
- Файлы и папки можно перетащить из проводника или Finder прямо в дерево заметок: они копируются в папку под курсором (над пустым местом — в корень хранилища), исходники остаются на месте. Занятое имя не перезаписывается, а получает « 2», « 3». Скрытые файлы, ссылки и файлы больше 100 МБ пропускаются, об этом приложение говорит списком.
- Исправлено: на Windows в режиме Live строки, разделённые одним переводом строки, слипались в одну. Базовые правила редактора (в том числе сохранение переводов строк) раньше вставлялись в страницу на лету, и на Windows политика безопасности окна могла их отбросить. Теперь они лежат в стилях самого приложения (`src/themes/prosemirror-base.css`) и одинаково работают на всех системах.
- Настройки синхронизации разделены на две зоны: «Аккаунт» (профиль, смена пароля, выход, хранилища аккаунта, устройства) и «Хранилище» (переключатель, статус, конфликты и резервные копии текущего хранилища).
- Новый пароль синхронизации: не короче 12 символов, со строчной и заглавной буквой, цифрой и спецсимволом. Под полем одна строка подсказки с тем, чего не хватает. Вход по уже созданному паролю это правило не проверяет.

- Подсказка о надёжности пароля при вводе больше не мигает и не двигает форму: пока идёт проверка, остаётся прежняя подсказка.
- Синхронизация: если она не работает, клик по её кнопке на боковой панели открывает небольшое меню. В нём одной строкой написано почему (не выполнен вход, нет доступа к связке ключей, выключена для этого хранилища, сервер недоступен, остановлена вопросом о массовом изменении и т. п.) и есть действие: включить снова, разрешить доступ, повторить, проверить снова — прямо отсюда, или открыть нужный раздел настроек, где ответ требует больше одного клика. Ответы, которые меняют или удаляют файлы, даются только в настройках, после списка файлов. Обычное «Обновить файлы с диска» осталось в этом же меню.

- Вопросы перед необратимыми действиями (удалить навсегда, сбросить настройки, откатить миграцию, перезаписать файл, изменённый вне Amby и другие) теперь задаёт само приложение, а не окно системы: заголовок — вопрос с названием («Удалить «План» навсегда?»), строка о том, что будет с данными, кнопка глаголом («Удалить»), опасная выделена красным, а фокус стоит на «Отмена». `Esc` и щелчок мимо — «Отмена». Окно работает и в окне настроек, и до открытия хранилища, и поверх другого окна.
- Сообщения об ошибках больше не открывают окно системы и не показывают текст ошибки: неудавшийся перенос, удаление или перетаскивание файлов — строка под деревом файлов; ошибка в окне обрезки картинки и в карточке подключения ИИ — под самим элементом; хранилище, которое не открылось, найденные незавершённые операции, ссылка, которую не удалось открыть, картинка, которую не удалось сохранить, — в центре уведомлений (первое — ещё и тостом).
- Черновик холста и скетча: на вопрос «Восстановить несохранённую версию?» черновик стирает только кнопка «Не восстанавливать». `Esc` и щелчок мимо закрывают вопрос без решения: черновик остаётся, холст или скетч открывается только для чтения (правка не затрёт черновик), а вопрос задаётся снова, когда слой открывают в следующий раз. Раньше `Esc` и щелчок мимо стирали черновик.
- Перенос заметки в базу данных: если Amby не смог перенести её свойства (не прочиталось место заметки в базе, сами свойства или не удалась запись), под деревом теперь появляется строка «Свойства «…» не перенесены в базу» с кнопкой «Перенести», а у самой заметки — такая же карточка. Раньше вопрос «перенести свойства?» молча не задавался. Свойства остаются в заметке, пока вы не ответите; если модуль «Базы данных» выключен, ничего не показывается. Состояние синхронизации, которое перестало обновляться, и проверки свойств, которые не удалось выполнить, теперь видны в центре уведомлений; панель синхронизации в этом случае пишет «Состояние неизвестно» вместо устаревшего «синхронизировано» и пробует подписаться заново.
- Меньше лишних вопросов: восстановление версии, «убрать тему» и «удалить блокнот» больше не переспрашивают. Восстановление всегда сохраняет текущий текст как версию истории (раньше при выключенной истории этого не было), тема убирается со строкой «Вернуть», заметки блокнота уходят на уровень выше, а пустая папка — в корзину. Вопросы остались у переименования и переноса, которые переписывают ссылки, и у слияния заметок.
- Ошибки в редакторах свойств баз и заметки и в ячейках больше не красные: они показываются строкой уровня «Внимание» в цветах темы.
- Перенос свойств заметки в базу данных после перемещения исправлен: варианты выбора переносились кусками («{"options":["Idea"» и т. п.), потому что строка настроек читалась как список через запятую, а это JSON; простые ключи заголовка (например `rating: 5`) вообще не предлагались и не переносились; список («мультивыбор») становился текстом. Теперь варианты читаются из JSON, переносятся все свойства заметки (кроме служебных ключей, тегов и псевдонимов), список становится полем с несколькими значениями. Поле называется как ключ заголовка, значение остаётся только в заметке, и заголовок заметки не меняется ни на байт; если в базе уже есть поле с таким именем, но другого вида, второе поле под другим именем не создаётся. Вопрос склоняет слово «свойство» по-русски и по-английски. Тот же разбор вариантов исправлен в панели свойств заметки из базы.
- Перенос свойств в базу после перемещения заметки доводил поля до конца, но в конце падал: сохранение копии прежних свойств требовало, чтобы у заметки была запись о их виде, а у простых ключей заголовка её нет, и это считалось ошибкой — отсюда вечное «Свойства не перенесены» и повтор. Теперь «нечего сохранять» — не ошибка. Ещё: у списка не появляется лишний вариант «one, two» (варианты берутся из самого списка), а открытые базы заново читают строки и поля после переноса заметки и после создания полей, поэтому не остаются на «0 строк · 0 свойств». Путь «создать базу, перенести заметку, перенести свойства, получить строки» теперь проверяет тест на настоящих командах Rust.

## Исправления

- Упрощено хранение баз: новые базы сохраняют схему, представления и шаблоны в одном `Название.json`. При открытии старого хранилища появляется уведомление с кнопкой «Обновить данные»; перенос выполняется только по нажатию, с проверкой файлов, резервными копиями и восстановлением при сбое. Вложения базы теперь находятся в обычной `assets/`; новым файлам назначаются уникальные имена с префиксами `img_`, `pdf_`, `audio_`, `video_` или `file_`, а исходные имена остаются в описании. Существующие пути вложений при переносе сохраняются. Перед переходом нужно обновить Amby на обоих устройствах.

- При добавлении базы к заметке дерево сохраняет идентификатор основной заметки: открытая вкладка следует за суперзаметкой, выделение в дереве не теряется и ложная карточка удаления не появляется. Подтверждённое удаление синхронизацией также запускает проверку открытых заметок напрямую, даже если системный наблюдатель не сообщил о переносе в корзину: текст и вкладка сохраняются, автосохранение приостанавливается и появляется карточка удаления.

- Центр уведомлений: карточка открытой заметки, чей файл удалили, больше не застревает. «Открыть заметку» теперь показывает вкладку этой заметки (раньше ничего не происходило, пока файла нет в дереве), а карточка исчезает, когда вкладка закрыта или заметку вернули. Для заметки, удалённой на другом компьютере, подпись говорит «Текст ещё открыт здесь, его можно вернуть».
- Открытый архив больше не показывает устаревшее: после каждого прохода синхронизации он сам перечитывает корзину и список файлов на сервере, а список сервера обновляется ещё и при каждом нажатии облака. Раньше файл, который синхронизация убрала в корзину, или файл, удалённый на другом компьютере, появлялся только после повторного открытия архива.
- Синхронизация свойств заметок: файлы оформления (`.amby/properties/`) раньше не отправлялись на сервер вообще, поэтому иконка и другое оформление не доходили до второго компьютера. Теперь они синхронизируются. Если на двух компьютерах оформление уже отличается, при первой синхронизации появится один конфликт на файл: ничего не теряется, местная версия сохранится в нём.
- Исправлено: уведомления синхронизации вообще не показывались в приложении — о новом конфликте, об открытой заметке, удалённой на другом компьютере, о вернувшейся заметке и о лимитах. Из-за этого же панель свойств не обновлялась после изменений с другого компьютера.
- Панель свойств теперь сама обновляется, когда другой компьютер изменил свойства, и не затирает вашу правку, которая ещё идёт. Если вы правите свойство, которое на другом компьютере переименовали или удалили, панель обновится и скажет об этом понятным текстом вместо «Не удалось сохранить свойство».
- Клик по картинке больше не подсвечивает всю заметку: картинка теперь забирает фокус редактора, и прежнее выделение текста не остаётся нарисованным поверх блока.

(3) Название открытой заметки и название базы данных, которое не приняли (занято, недопустимые символы), больше не молчат: поле остаётся открытым с введённым именем, под ним строка с причиной, по Esc возвращается настоящее название. (4) Отказ окна базы (новый вид, новая запись, новое свойство) показывается один раз, под полем в окне, а не ещё и красной строкой над таблицей; «Отмена» её снимает; строки рисуются цветами уровней. (5) Стопка уведомлений и тосты у колокольчика поднимаются над переключателем рабочей области и не закрывают его. (6) Вопрос об удалении называет вещь по виду («Удалить папку «Идеи»?», заметку, холст, скетч, базу), без слова «файл», одной короткой строкой; вопрос «Перезаписать…» сокращён до одной строки. Если безопасность не доказана (есть замороженная база, набор баз изменился, у нетронутой базы изменились манифест или состав строк), выполняется прежняя полная пересборка. Остаются на полной пересборке: создание и переименование базы, синхронизация и разрешение конфликтов YAML, события наблюдателя и включение модуля. Тесты: две несвязанные базы, связанные через rollup, равенство частичной и полной пересборки, запасной переход на полную.

- Внутреннее (CORE-16): слой атомарной записи (запись через временный файл, создание без замены, повтор переименования, внедрение сбоев в тестах) вынесен из `frontmatter.rs` в `atomic_fs.rs`; старые пути `frontmatter::atomic_write_bytes` и другие остались как реэкспорт. Поведение не менялось.

- Сохранение (CORE-18): атомарная замена файла больше не сбрасывает права: заменяющий файл получает права прежнего (например, `0600` остаётся `0600`). Имя временного файла теперь содержит не более 64 байт имени заметки, поэтому заметку с очень длинным именем (около 240 байт) можно сохранить. Расширенные атрибуты файла (теги Finder, карантин) по-прежнему не переносятся: у стандартной библиотеки нет переносимого способа, а зависимости для этого в проекте нет.

- Переименование и перенос (CORE-12): переименование и перенос папки, заметки или контейнера, а также помещение в архив и возврат из него больше не заменяют файл или папку, появившиеся между проверкой «имя свободно» и самим переименованием: проверка и переименование теперь одна операция ядра (`renameat2` с `RENAME_NOREPLACE` на Linux, `renamex_np` с `RENAME_EXCL` на macOS, `MoveFileExW` без замены на Windows; ветка Windows собрана только в CI, не проверена вживую). Если файловая система не поддерживает флаг, остаётся прежняя проверка перед переименованием.

- Имена (CORE-14): создание и переименование заметки, папки, холста и наброска теперь проверяют имя одной общей проверкой `validate_item_name`: отклоняются `.git`, `.amby`, `.obsidian`, `.trash`, имена из одних точек или с точкой в конце, имена устройств Windows (`CON`, `NUL.txt`, `COM1`), символы `: < > " | ? *`, управляющие и переопределяющие направление символы и имена длиннее 200 байт. Ошибка приходит с кодом `invalidPath`. Путь нового имени при переименовании ещё раз проверяется на выход за хранилище. Браузерный режим (`item-name.ts`) использует те же правила.

- Устойчивость (CORE-13): очередь изменений индекса наблюдателя, соединение хранилища (`generation`, выход из приложения), состояние базы данных времени выполнения, подготовленный перенос и кэш завершённых журналов миграции теперь берут замок через `lock_or_recover`, как остальные замки хранилища: паника в одном потоке больше не ломает все следующие команды. В `lock_util.rs` описано, почему это безопасно для каждого из них.

- Сохранение (CORE-11): сохранение тела заметки с корректным frontmatter больше не приводит концы строк всего файла к одному виду: блок frontmatter пишется байт в байт, как есть, а тело получает правило концов строк прежнего тела (как у заметок с неразобранным frontmatter). Заметка со смешанными концами строк (CRLF в frontmatter и LF в теле, или наоборот) не меняется вне правки; снимок истории из EDIT-08 остаётся страховкой для режима Source, где файл записывается целиком.

- Документация (CORE-17): `docs/vault-format.md` — явная очистка истории («очистить всё») удаляет все снимки хранилища или одной заметки, а не оставляет 20 последних; `docs/ai/agent-guidelines.md` — значения свойств лежат во frontmatter, `.amby/properties.json` только читается (старый формат), писатели `property_store.rs` нужны для тестов; карта `src-tauri/src/MAP.md` — единственная запись в заметку при сканировании индекса это выдача `amby-id` заметке без него (`assign_missing_identities`, со снимком `id-assignment`). Код не менялся.

- Базы данных (DB-05): пакетная запись значений больше не принимает пустую `expectedRevision` как «без проверки конфликта»: пустая ревизия в любой ячейке — ошибка до любых изменений. Единственным законным отправителем пустой ревизии была расстановка новой записи в колонку доски (`new-record-lane.ts`): теперь она читает ревизию только что созданной заметки и передаёт её. Тест: пустая ревизия отклоняется и заметка не меняется.

- Базы данных (DB-07): доска больше не хранит счётчики и данные полос в обычных объектах, где ключом служит значение, заданное пользователем: теперь это `Map`. Полоса со значением `__proto__` или `constructor` раньше терялась или получала вместо числа функцию в счётчике. Тест: полосы `__proto__`, `constructor`, `hasOwnProperty`.
