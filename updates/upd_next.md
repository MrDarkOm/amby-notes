# Amby — Next version

- Fixed side-panel open/close animation: the central workspace stage now shifts smoothly in lockstep with the side panels and header columns instead of snapping at the end of opening or the start of closing.
- Fixed header sidebar-toggle alignment across OSes and Web: both toggles align flush with their dock rails when no OS window buttons sit on that edge (including in Web builds, which no longer reserve macOS traffic-light space on the left or render inactive Windows buttons on the right); only the side with native window buttons shifts its toggle inward.

- For developers: `npm run lint` passes again — the browser-console audit scripts in `docs/audit/**/scripts/` now lint with browser globals, and one needless regex escape was removed.

- Interface polish (no layout or style changes): keyboard focus is now visible on the dock, tabs and toolbars; the "Delete" items in menus are readable in the light theme; an "off" switch is clearly visible in the light theme; the emoji picker uses the app accent and font instead of blue; the note title lines up with the text below it; a hovered row in the file tree no longer looks selected; settings drop-downs have one size and long values no longer push the arrow out.
- The file tree is one Tab stop again: the type icon of a row (it adds the note to favourites) is no longer a separate stop; favourites stay available from the context menu. Tab no longer enters the note text, where it typed a tab: it moves between the buttons; the text is entered with a click or with Enter from the title.
- Shortcut hints match the system: ⌘ on macOS, Ctrl on Windows and Linux (undo, redo, link, formula). "Show in Finder" / "Show in File Explorer" / "Show in the file manager" now names the file manager of the current system.
- After the window is narrowed and widened again, the side panels come back as they were. Closing Settings returns focus to the Settings button.
- If a database cannot be created, the dialog now says so instead of silently staying open; its default name is selected so typing replaces it.
- The main window cannot be shrunk below 720×480, as note windows already could not, so the dock, tabs and editor never overlap.
- In windows 960–1100 px wide the right panel steps aside so the note keeps a readable width; it comes back when the window grows.
- The page-icon picker is no longer cut off by a narrow editor, and Esc closes it.
- Code uses one monospace font stack everywhere, with system fonts for macOS, Windows and Linux, so it never falls back to Courier.
- Nested-note chips and folder tabs use the same type icons as the file tree instead of emoji; the "Colors & effects" settings group has its own icon.
- Screen readers hear the names of settings controls, which dock section is open, and the selected search result. Russian texts consistently address the user formally.

- Fixed note windows opened separately using a system title bar instead of Amby's header. They now use the same macOS overlay and window-button placement as the main window, and no system decorations on Windows and Linux.

- Fixed "Show in file manager" for workspace and note folders: it now opens the folder itself instead of showing its parent with the folder selected. Files are still selected in their containing folder.

- The copy made before sync is first switched on is no longer created next to your vault folder (no more `<vault>.amby-backups` clutter). It lives in Amby's own data folder, one copy per vault, and Amby deletes it 14 days after the first successful sync. Settings → Backups shows one line, "Copy before sync: created <date>", with Show and Delete. If that copy is missing, switching sync on no longer fails with "the copy could not be verified": Amby says the copy is missing and makes a new one. Copies made by earlier versions beside the vault are never moved or deleted automatically; the one a vault still points to can be shown or deleted in Settings.

- For developers: the repository now uses English for all docs, plans, maps, agent instructions and release notes (`updates/`); Russian stays only as an app interface language. `AGENTS.md` (also read by Claude Code and Gemini CLI) has a language policy for agents: they take requests in Russian, work and write in English, and answer the owner briefly in Russian. The release notes template, the GitHub installation footer and the beta banner of a release are in English; older Russian documents are translated over time. App behavior did not change.
- For developers: a plan for the `amby` command line (for people, scripts and AI agents through `amby mcp`) and for moving the vault core into its own crate without Tauri — `docs/road/cli.md`. This is a task description; app behavior did not change.
- For developers: the remaining Russian documents (plans, audits, contracts, the sync plan) are translated to English; app behavior did not change.
- For developers: a UI/UX polish audit of the current interface with screenshots, measurements and a prioritised fix plan — `docs/audit/ui-ux-audit-2026-11/`. App behavior did not change.

- The emoji picker is prepared in the background after startup and reuses a single ready-made grid instead of rebuilding it on every open. Closing it clears the search, refreshes "Recents", and releases handlers for the current note; switching language or theme refreshes the cache.

- Updated the sync icon: the arrows keep their outer triangular tips and the center dot is removed. The arrows are neutral, while status is shown with a bright circular fill inside the arcs with a small gap to the arrows; rotation during transfer is preserved.

- Fixed SVG flag squashing after searching in the picker: local images now use a uniform intrinsic size while preserving the original artwork proportions.

- Emoji search respects the current app language and always supports English. A local Russian Unicode CLDR dictionary of 3,963 entries is included; switching RU ↔ EN updates the search index. Additional languages connect as separate dictionaries through a shared registry; original Unicode values, skin tones, and offline operation are preserved.

- Unified search in the "Emoji" and "Icons" sections of the picker: the same Lucide Search icon and identical input styling, removing the separate black fill on focus. Aligned the search icon's inner padding with the input border so it does not shift when switching tabs.

- Emoji and flags ship as optimized SVGs: icons stay sharp when scaled, and the compressed set takes less space than PNGs. Sources, licenses, and checksums are preserved; SVGO is used only during resource preparation, not in the app.

- Emoji picker: styles load from local CSS after initialization so native WKWebView does not leave the picker unstyled under the active security policy. App permissions were not expanded.

- Interface emoji icons and the picker use local Google Noto Emoji images: the same set across OSes, with no network downloads. Lucide icons, custom images, layout, and system emoji rendering in regular text are preserved.
- Fixed recognition of compound emoji in callout icons: skin tones, ZWJ sequences, flags, keycaps, and variation selectors are preserved intact. Added a fallback when an image is unavailable and offline access to Noto licenses in settings.

- For developers: Rust was updated to 1.100.0 (`rust-toolchain.toml`, `rust-version` in `src-tauri/Cargo.toml`). CI sync checks (`sync-gates.yml`) now also use the pinned version instead of floating stable.

- Updating: before installing an update, all windows save open edits. Previously, restarting after an update could cut off the last seconds of typing. If edits could not be saved, the update is not installed: settings explain this, and the "Install" button retries.
- For developers: updating is split into download and install, with windows flushing edits in between (`flush-all-windows.ts`). Quit interception (`terminate_gate.rs`) was rewritten: instead of the hanging `NSTerminateLater`, it uses `NSTerminateCancel`, a normal `request_quit`, and an `exit(0)` timer; the quit reason is read from `keyAEQuitReason`.
- macOS: "Quit" in the Dock menu (and the `quit` command via Apple Event) now saves open edits: the app cancels termination once, windows save text and close, and then the app exits; if it has not exited within 5 seconds, it forces exit. Log out, restart, and shut down are not delayed and work as before (the last seconds of typing are preserved by the recovery draft).

- macOS: Amby now requires macOS 13 Ventura or newer. On older systems the built-in Safari engine lacks some styles and the UI would look broken; now such an installation simply will not start. Help window height gained a fallback for older engines.

- Rename and move: links are now also updated in the archive (wikilinks, Markdown links, canvases), while trash, backups, and internal folders (`.amby`, `.obsidian`, `.git`) are no longer modified. Previously, renaming a note rewrote links in any matching files across the vault, including hidden folders; now only in regular notes and the archive. A wikilink in the archive whose name also matches another note is left unchanged. A quoted path is replaced only in canvases and sketches; in Markdown text it stays as is.

- For developers: two owner items were added to the review work plan — removing deleted empty folders from the tree and a setting for folder click behavior. This is a task specification, not an app behavior change.

- File tree: the empty-area context menu now has sorting, type filter, auto-reveal current file, expand/collapse all, and open vault folder in the file manager. The settings match the toolbar buttons; creation commands still create items at the vault root.

- Release: prepared beta 7 of the 0.1.9 cycle with fixes for Windows images, window close/restore, and Enter handling during IME input. Release notes updated; final lifecycle verification of the regular installed Windows build remains a separate scenario.

- Images: fixed blocking of local attachments on Windows — pictures added via menu or clipboard can load again. Only exact local Tauri protocol URLs are allowed; loading images from external servers remains forbidden.
- For developers: the native harness shares the window close/restore handler with the app; a browser test verifies loading attachments from Windows URLs under the release security policy.

- Window: Amby no longer stays running with no window. Previously, after closing the main window, the app stayed in the Dock (kept alive by the hidden settings window), and clicking the icon opened nothing; a minimized window also did not restore on clicking the Dock icon. Now settings close together with the main window, and if no other windows remain, the app quits; clicking the Dock icon or relaunching restores a minimized window and reopens a closed one.
- Updates: a beta can once again self-update to the next beta. Since beta 4, the app checks the version recorded in the update signature against the feed version, while betas were signed as `0.1.9` without the beta number, so beta 4 would not install beta 5. Now betas are signed with the full version (`0.1.9-beta.6`), and a release whose signature and feed diverge is not published. Beta 5 cannot be fixed by this retroactively, but any earlier beta can install beta 6 on its own. If an update fails to install, settings and the notification log show which version it is, with a "Download version manually" link to its GitHub page.

- For developers: the debug log now states why a note could not be read (missing from index, file missing on disk, not UTF-8, permission denied) and why an update failed to install (no permission to replace app, signature mismatch, temp folder on another drive, network) — by code, without raw error text or paths. Previously the log only said "error", making the cause impossible to find.
- For developers: release checks pass again on Linux and Windows — removed a redundant condition that the new Windows Clippy complained about, the archive migration test no longer depends on whether copying preserves file timestamps, and server free-space tests are skipped on Windows (the server does not measure disk space there; the production server runs in Docker on Linux).
- Sync: deleting a vault copy from the server now requires the current password — in addition to the exact name, the dialog asks for the password; a wrong password deletes nothing and does not turn off sync, the dialog simply asks again. After changing the password, the app offers to disconnect other devices: they stop syncing and prompt to sign in with the new password, while their files remain. The sync server no longer responds over plain `http://` — HTTPS only.
- Sync: in the property styling conflict dialog on a computer that received the conflict from another device, the "This computer" and "Other computer" labels are no longer swapped — nor are the "Keep this computer's" / "Take the other's" buttons. Previously choosing "this" kept the other computer's version.
- For developers: added public documentation of sync protocol and format v1 (`docs/sync-format.md`) for anyone self-hosting or writing a client: encryption, all server requests, error codes, settings, and admin commands. App behavior did not change.
- Self-hosted sync server is protected against overload: it keeps a free disk-space reserve (1 GB by default) and stops accepting new writes when low while still allowing reads and deletes; open registration can be capped by account count; sign-in requests are capped at 64 KB; at most four large requests are read concurrently, with others receiving "server busy" and retrying later. Without a subscription, only items that actually exist on the server can be deleted. The app shows clear messages for these cases.
- Sync: a large vault (thousands of files) or renaming a large folder no longer stalls on a second computer. Previously the initial upload went out as one huge batch that other devices could not read; now changes are sent in parts, and large batches already on the server can be read. The server also more reliably rejects requests to a recently deleted space or from a disconnected device: such a record can no longer land in someone else's vault.
- Subscription sync: anyone can register freely, but only an account with a subscription can upload files to the server. Without one, the account works (sign-in, username, device names, password), and everything except adding data can be done on the server: download, restore previous versions, delete files or an entire vault. Account settings show "No subscription · sync unavailable" and a "Get subscription" button: there is no billing yet, and the button shows a hint that the server administrator grants subscriptions. With a subscription, its expiration is shown. Files waiting for a subscription stay on the computer and upload automatically once a subscription appears. The server administrator grants and revokes subscriptions with `user plan set` (optionally with `--until`). A self-hosted server without a plans file works as before.
- For developers: completed a sync security review (server, client, app integration, self-hosted server settings). Report — `docs/road/target/sync-security-review.md`: no content or key leaks found; availability and resource risks found (shared disk space under open registration, large commit unreadable by other devices, race after space deletion, request limits). Fixes will follow separately, tests first. App behavior did not change.
- For developers: started preparing deletion of the server copy of a vault from the app — rules are documented and stub interfaces and tests added before implementation. Local notes, attachments, history, and recovery data must remain intact on all devices. Deletion itself is not yet available.

- Fixed saving pending changes to canvases and sketches after rename or move: writes now use the new path and the previous file revision. Moving a recovery draft preserves new edits and does not overwrite an existing draft at the new path.
- Fixed refreshing open notes: if a rename or move rewrites links, a clean note is reloaded, while an unsaved edit is kept and shows a conflict. During sync, the properties panel also refreshes after a properties file is deleted or moved. File creation, rename, move, and deletion are also announced to other windows.
- Fixed cross-window refresh after saving a canvas or sketch, restoring a version or archive item, and modifying a database or properties. When unsaved edits are open, normal conflict protection is preserved. An open history panel reloads its list after new snapshots, and a saved conflict copy appears in the tree right away. An open canvas or sketch is no longer closed automatically if the file disappears from the tree after an external change.
- Sync now finishes a batch of files before notifying open databases and the workshop, so they do not re-read data mid-batch. Before rebuilding a database, Amby also updates the index of received notes so new rows do not disappear from the list.
- Sync: renaming a note together with an edit no longer goes to the server as a deletion plus a new note if sync happened to be running at that moment. Previously such a pass could see the renamed file before receiving the rename hint and send the old path as deleted — on another computer the old note went to trash and the new one appeared separately (without data loss). Now the pass reads hints after scanning the vault; a hint whose rename it has not seen yet waits for the next pass.
- Fixed: Enter used to confirm IME input (Chinese, Japanese, Korean, dictation, and macOS accents) no longer triggers "rename", "save", "send", or "confirm" — including the confirmation dialog requiring the exact name. The shared `isEnterKey` check is now used in all custom inputs, and ESLint forbids comparing `event.key` directly to `"Enter"`.
- For developers: added a browser-engine policy (WKWebView, WebView2, WebKitGTK) to the agent guidelines: which web platform features may be used and when a support check with fallback is required. App behavior did not change.
- For developers: checked Tauri security settings against an external checklist. Opening links and attachments, CSP, and window permissions were already in order. Two rules were recorded: every app command validates its own inputs because any window can invoke it; `freezePrototype` must not be enabled because it prevents the app from starting due to d3. Three project skills were added for Claude Code (IPC commands, UI strings, release) — on `dev` only. App behavior did not change.

- Fixed dangerous deletion: if a note at the vault root has the same name as the vault folder (for example, `Notes/Notes.md`), "Delete", "Delete permanently", "Move to archive", "Rename", and "Move" now act only on that note. Previously Amby treated it as the main note of a "bundle" whose folder was the entire vault: permanent deletion erased the whole vault along with history, normal deletion sent the entire vault to the system trash, and renaming renamed the vault folder. The vault itself and the `.amby` folder can no longer be deleted in any mode.
- Fixed text loss on a full disk: if a note failed to save and the recovery draft also failed to write, the window no longer closes silently and the vault does not switch. Amby asks "Close window and lose unsaved text?" (or "Switch vault…"), and by default the window stays open so you can free space and save again. If the draft was written, everything works as before. The "Failed to save note" card no longer promises a draft that might not exist.
- Fixed on macOS: quitting via Cmd+Q or "Quit" in the app menu no longer loses recent edits. Previously the app exited immediately and text typed in the last second did not have time to save. Now quit closes windows the same way the close button does: they save edits first, and ask if text might be lost (full disk). "Quit" from the Dock menu and system log out still work the old way.
- Fixed: an external edit to a note (from another window, another app, or sync) is no longer silently overwritten by old text. Previously, if you typed and immediately deleted a character, the note briefly appeared saved while its save was still queued. An external edit arriving at that moment was loaded into the editor, and half a second later your previous text was written over it on disk. Now such a note counts as unsaved, and the external edit is shown as a conflict.
- Canvases and sketches are no longer lost silently. A canvas with a byte-order mark (BOM) or without an edges list (as in files from other apps) now opens with all its contents. Previously such a file opened empty, and the first edit replaced the entire canvas on disk. A file that genuinely cannot be read no longer opens empty: Amby shows "Failed to read …" under the tree and writes nothing to it. If a canvas or sketch fails to save (for example, on a full disk), it shows the "Failed to save" card like a regular note, and the tab shows an "unsaved" dot.
- Fixed: actions from the block menu (the handle to the left of a line) performed with the mouse alone are saved again. Previously, if right after opening a note you deleted, duplicated, converted a block, or changed a callout color without typing anything on the keyboard, the change appeared on screen but was not written to the file and vanished on reopen.
- Fixed: a single note in a foreign encoding no longer prevents opening the vault. Previously, a file not saved in UTF-8 (for example, "Unicode" from Windows Notepad or an old cp1251 export) prevented opening the vault, or opening any note in an already-open vault. Now such a note is skipped, reported, and its previous version in search and the tree is preserved. Amby does not touch the file itself; once resaved as UTF-8, it comes back.
- Fixed: headings and tables no longer break on save. Previously Shift+Enter in a heading saved as a heading with a stray `\` and a separate paragraph, and Enter or Shift+Enter in a table cell merged cell lines or left `\` inside it. A list or heading created inside a cell turned into plain text after saving. Now those keys do nothing in a heading or cell, and a cell, as in Markdown, stores a single line of text.
- Fixed: pasting multiple paragraphs, a list, a heading, or a code block into a table cell no longer breaks the table or loses text. Previously pasted text could overwrite neighboring cells or keep only the first line; now everything becomes a single cell paragraph: parts separated by spaces, formatting (bold, italic, links) preserved, code blocks turned into inline code, and `|` escaped.
- Fixed: note history is no longer lost on rename and move. Previously, after renaming or moving a note (or its folder), the "History" panel was empty: versions stayed on disk but were tied to the old name. Meanwhile, a new note created under the old name showed someone else's versions, and "Restore" could write another note's text into it. Now versions move along with the note.
- Security and data safety, several small fixes:
  - restoring from the internal trash no longer moves an unrelated file into the vault if its entry was tampered with (for example, in someone else's backup);
  - automatic history cleanup no longer deletes the latest "safety" versions — the original text before Live rewriting, the version replaced by sync, and the version replaced by restore;
  - sync no longer writes files into internal folders `.git`, `.amby`, and `.obsidian` if their name arrives in a different case (`.GIT`, `.Amby`) or as a Windows short name (`GIT~1`);
  - after an internal sync error, open notes once again learn about external edits without restarting.
- For developers: CI and release checks now genuinely catch an outdated `src/lib/bindings.ts`: previously the check compared the file just regenerated by tests against itself.
- For developers: completed a full read-only codebase review (11 areas; every Critical and High finding verified separately). Report — `docs/audit/2026-11-15-code-review.md`. Key findings: deleting or renaming a root note with the vault folder's name affects the whole vault; closing a window on a full disk can lose text; Cmd+Q and mouse-only block menu actions can fail to save recent edits; a single non-UTF-8 file blocks opening the vault. Fixes will follow separately, tests first. App behavior did not change.

## New

- Sync: previous note versions and deleted files can now be restored from the server. In note history, server versions appear in the same list as local ones, with a cloud icon and device label; on a new computer or after clearing history, they are the only ones. Deleted files live in the archive under "On server": check the ones you want and click "Restore" — if the path is occupied, the file is placed alongside ("Name 2.md") and nothing is overwritten. Before restoring a version, the current text is saved in history. When offline or with sync off, a single quiet line appears instead of the list.
- Sync: in note history, a snapshot that is also on the server gets an "On server" cloud icon with the device name; there is still no separate row for that version. If the current text matches the latest version on the server, a single quiet line at the top of the list says "Current text is saved on the server". The same applies in the sidebar. In the archive, a trash entry also kept on the server is marked with an "on server until …" cloud icon. When offline or with sync off, no badges are shown. This is display-only: disk writes did not change.
- Sync: you can change your password in settings. The old password is required; other devices and the recovery code continue to work, and data is not re-encrypted.

## Improvements

- If a new note name is rejected (already taken or contains invalid characters), the reason now appears right below the field: in the file tree, in database row names, in the row menu, and on board and gallery cards. The field stays open with what you typed, and a line like "That name is already taken. Enter another." appears below it; it clears when the name changes or on Esc. Previously the name silently reverted. Data is not affected.
- Notification center. The bell in the dock now opens a stack of calm cards right next to it instead of a sidebar: it grows upward from the button and closes on a second click, clicking outside, or Esc. At the top is "Needs decision" (sync conflicts with a "Compare" button, sync pauses, notes that failed to save or changed outside Amby, found drafts), then "Attention" (plan limits and files with errors; an entry can be dismissed and returns only if the cause clears and reappears), and at the bottom "Earlier" — a 7-day log (note restored, edits from two computers merged, conflict choice outcome, backup ready, update check failed): the last three lines, "Show all", and "Clear". The badge on the bell counts the first two sections; the log does not affect it. The stack sits on the same surface as popovers (background, border, shadow) and is offset 12 px from the dock edge so dock buttons are not covered; toasts use the same offset. Cards look calm: standard surface, thin border, colored left bar, and level icon, with no tinted fill. Toast popups appear in the same spot by the bell, and only for danger and decisions about things not on screen (new conflict on a closed note, sync pause, save failure on a closed note): 10 seconds, at most three, the rest as "N more"; clicking a toast opens the stack, and while the stack is open no toasts appear. If a note fails to save after closing, there is no longer a system dialog: a card in the center and a toast "Note 'Name' failed to save — Text is in a draft, not lost". When the app merges edits from two computers, an open note quietly mentions it ("Previous version is in history"). Texts are grammatically fixed for gender/agreement.

- Note sync conflict became simpler. In the bell list, settings, and note card there is now the title "'Name' was edited on two computers", the line "Both versions are intact", and a single "Compare" button: without paths, "main file"/"copy" wording, or an explanatory paragraph. You choose in the comparison dialog where both versions are visible: "Keep version in note" and "Take second version", while "Save both as separate notes" is tucked into the "…" menu. Side labels are "Version in note" and "Second version": the app does not know for sure which computer the second came from and does not claim it. After choosing, it tells you what was done and where the second version was kept ("in vault trash" or "in note history", with an "Open history" button in the latter case): via a card in an open note or a row in the bell list. If you pick at least one paragraph your own way in the dialog, the primary button becomes "Build from selection" (next to "Reset selection"), so per-paragraph choices cannot be lost by an accidental click. Data behaves as before.
- Note notices became more compact. Collapsed, they are now a small pill at the right edge of the bottom bar with a gap above it (previously the strip was as wide as the bar and peeked out from behind it): the icon of the most severe notice, its short title, "+N" for the rest, and a chevron. Expanded, they sit in a rounded panel on the same surface as the bell stack, with "Note notices · N" at the top and cards as separate tiles; the panel is no wider than the note area and does not cover bottom-bar buttons. Card order and levels did not change; danger and decision still expand the panel automatically.
- The collapsed note notices strip became wider (at least 300 px, growing left from the bottom bar), so the title is usually visible in full. Cards in the expanded strip are ordered from most severe to least severe: danger, needs decision, attention, info.
- Note notices now appear as a strip peeking out from behind the bottom bar of the note ("Just now · 19 words"): collapsed, it is a single line with the icon of the most severe notice, its title, "+N", and a colored dot; clicking expands upward into a panel with all cards, replacing the lightbulb and floating stack. It expands automatically only for danger or when a decision is needed.
- Removed the floating sync-conflicts badge in the corner of the window: a regular "Notifications" bell button appeared in the dock at the bottom above settings. It shows the count of conflicts and plan-limit warnings colored by the most severe; clicking opens the conflict list nearby.
- Note notices: warnings about a damaged or unclosed frontmatter header and about value mismatches during property migration no longer expand the stack on their own and wait for a click on the lightbulb. Losing a note ID and "properties read-only" mode, on the contrary, now expand automatically as a decision prompt. The lightbulb color reflects the most severe card level: red, orange, or yellow; if there is only info, it is neutral.
- Sync: property styling conflicts are resolved per note. Sync settings show which notes were edited differently on two computers; for each you choose "From this computer" or "From the other", while edits to other notes merge automatically and are no longer lost when picking one version.
- Sync: two vaults that each migrated to the new properties format independently and meet for the first time merge property styling per note. Edits to different notes merge automatically; only notes edited differently on both computers enter conflict.
- First opening of a large vault on the new version became faster: checking for duplicate `amby-id`s no longer iterates over all notes for each note. Preparing property migration for 50,000 notes takes 4 seconds instead of nearly two minutes.
- Sync: an Amby internal data conflict (note properties, graph layout) is described in plain words, without paths like `.amby/properties.json`. It has two choices, "Keep from this computer" and "Take from the other computer", and a warning that the unchosen side's edits will be lost. The "Keep both" and "Compare" buttons were removed for such files: nobody needs a second copy of an internal file.
- Files and folders can be dragged from Explorer or Finder directly into the note tree: they are copied into the folder under the cursor (or the vault root over empty space), leaving originals in place. An occupied name is not overwritten and gets " 2", " 3". Hidden files, symlinks, and files over 100 MB are skipped and listed by the app.
- Fixed: on Windows in Live mode, lines separated by a single line break collapsed into one. Base editor rules (including preserving line breaks) were previously injected into the page at runtime, and on Windows the window security policy could drop them. Now they live in the app's own stylesheet (`src/themes/prosemirror-base.css`) and work identically on all systems.
- Sync settings are split into two areas: "Account" (profile, password change, sign out, account vaults, devices) and "Vault" (toggle, status, conflicts, and backups of the current vault).
- New sync password: at least 12 characters, with a lowercase and uppercase letter, a digit, and a special character. A single hint line below the field lists what is missing. Signing in with an existing password does not enforce this rule.

- The password strength hint while typing no longer flickers or shifts the form: while checking, the previous hint stays in place.
- Sync: when it is not working, clicking its sidebar button opens a small menu. It states in one line why (not signed in, no keychain access, turned off for this vault, server unreachable, paused by a mass-change prompt, etc.) and offers an action: re-enable, grant access, retry, check again — right from there, or open the relevant settings section when a response takes more than one click. Answers that modify or delete files are given only in settings, after the file list. The regular "Refresh files from disk" remains in this same menu.

- Prompts before irreversible actions (delete permanently, reset settings, roll back migration, overwrite a file modified outside Amby, etc.) are now shown by the app itself rather than a system dialog: the title is a question with the name ("Delete 'Plan' permanently?"), a line explaining what happens to the data, a verb button ("Delete"), dangerous actions highlighted in red, and focus on "Cancel". `Esc` and clicking outside trigger "Cancel". The dialog works in settings, before opening a vault, and on top of another window.
- Error messages no longer open a system dialog or show raw error text: a failed move, delete, or drag-and-drop shows a line under the file tree; an error in the image crop dialog or AI connection card appears under the element itself; a vault that failed to open, found incomplete operations, a link that failed to open, or an image that failed to save appear in the notification center (the first also as a toast).
