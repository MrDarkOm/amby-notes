# Реализация режимов «Блочный» и «Строчный»

Работай в репозитории Amby Notes:

`/Users/paul/Codding/amby-notes`

Это Tauri 2 desktop-приложение с React 19, TypeScript, Vite, Tiptap/ProseMirror и CodeMirror. Перед началом полностью прочитай `AGENTS.md`, изучи актуальное состояние репозитория и выполни `git status`.

Рабочее дерево может содержать незакоммиченные изменения пользователя. Сохрани их, не откатывай, не перезаписывай и не форматируй несвязанные файлы. Не делай коммит без отдельной просьбы пользователя.

## Цель

Добавь в существующий Live-редактор два способа работы с одним и тем же Markdown-документом:

1. **Блочный** — существующее поведение Amby с `BlockHandles`, блочными действиями, drag-and-drop и визуальной блочной структурой.
2. **Строчный** — чистое непрерывное текстовое полотно без Grid, ручек и постоянного блочного интерфейса, по ощущению близкое к простоте Obsidian Live Preview.

Это два представления одного Live-редактора, а не разные типы файлов или заметок.

Основной принцип продукта:

> Markdown по умолчанию, сложные блоки — по необходимости.

Не создавай сущности «Страница» и «Заметка», конвертацию между ними, разные расширения файлов или разные иконки в дереве. Все заметки остаются обычными `.md`.

## Подтверждённая текущая архитектура

Сейчас приложение устроено следующим образом:

```text
TiptapEditor
├── Live — editable=true
└── Read — editable=false

SourceEditor на CodeMirror
└── Source — побайтовое редактирование исходного Markdown
```

Существующий тип:

```ts
type DocumentViewMode = "source" | "live" | "read"
```

не меняй и не переименовывай.

Source должен продолжить использовать `SourceEditor`/CodeMirror. Он необходим для сырого Markdown, malformed frontmatter, footnotes, reference-style links, смешанных переносов строк и конструкций, которые нельзя безопасно представить в ProseMirror.

Read должен продолжить использовать существующий `TiptapEditor` с `editable=false`. Не меняй его внешний вид и поведение в рамках этой задачи.

Новый режим относится только к `viewMode === "live"`.

Добавь отдельный тип, например:

```ts
export type LiveEditorLayout = "block" | "linear"
```

Пользовательские названия:

- `block` → «Блочный»;
- `linear` → «Строчный».

## Границы задачи

Не создавай второй Tiptap-редактор для Строчного режима и не создавай третий редакторный движок.

Итоговая архитектура должна быть такой:

```text
Tiptap
├── Live / Блочный
├── Live / Строчный
└── Read

CodeMirror
└── Source
```

Блочный и Строчный режимы должны использовать:

- один Tiptap instance;
- одну ProseMirror schema;
- один набор Markdown parser/serializer;
- одинаковое содержимое;
- одинаковые NodeView для сложных элементов;
- общую историю undo/redo.

Переключение между ними не должно размонтировать Tiptap, повторно парсить Markdown или изменять файл.

## Управление в интерфейсе

В меню троеточия редактора добавь компактный выбор Live-представления:

```text
Режим редактора
  ✓ Блочный
    Строчный

Исходный Markdown

```

Используй подходящий Radix dropdown radio/checkbox API и существующие UI-паттерны приложения.

Требования:

- выбранный режим должен быть однозначно отмечен;
- пункты доступны только для Markdown/editor layer;
- переключение работает с клавиатуры;
- добавь корректные `aria`-атрибуты и локализованные подсказки;
- добавь русские и английские строки;
- существующий пункт Source и остальные пункты меню должны продолжить работать;
- не добавляй второй переключатель в дерево или тулбар;
- не меняй управление режимом Read в рамках этой задачи.

## Хранение выбора

Для первой версии используй одну глобальную пользовательскую настройку последнего выбранного Live-режима:

```ts
liveEditorLayout: "block" | "linear"
```

Правила:

- значение по умолчанию — `block`;
- переключение сохраняется в существующей системе настроек Amby;
- после перезапуска восстанавливается последний выбранный режим;
- старые настройки без этого поля безопасно получают `block`;
- неизвестное или повреждённое значение нормализуется в `block`;
- не записывай режим в Markdown, frontmatter или sidecar конкретной заметки;
- не создавай в первой версии отдельную настройку для каждой заметки.

Не добавляй отдельный экран настроек, если для сохранения последнего выбранного режима он не нужен. Основной способ переключения — меню троеточия.

## Передача режима в Tiptap

Передай `LiveEditorLayout` по существующей цепочке:

```text
Workspace/settings store
→ DocumentEditor
→ TiptapEditor
→ BlockHandles и CSS
```

Добавь на корневой контейнер Tiptap явный data-атрибут:

```html
<div class="amby-tiptap" data-live-layout="block">
  <div class="amby-tiptap" data-live-layout="linear"></div>
</div>
```

Когда `viewMode === "read"`, выбранный Live layout не должен менять существующий Read-интерфейс. Если для CSS нужен отдельный признак, добавь явное состояние `data-editor-readonly` или эквивалент, не смешивая Read со Строчным режимом.

## Блочный режим

Блочный режим должен остаться визуально и функционально таким, как сейчас.

Сохрани:

- `BlockHandles`;
- добавление и перемещение блоков;
- drag-and-drop;
- `BlockActionsPanel`;
- фоновые цвета и настройки блоков;
- slash-меню;
- bubble toolbar;
- callout;
- таблицы;
- изображения;
- transclusion;
- Amby blocks;
- текущую Markdown-сериализацию.

Не рефактори существующий блочный UX без необходимости для переключения режима.

## Строчный режим

Строчный режим должен ощущаться как обычный непрерывный Markdown-документ.

В нём необходимо:

- не рендерить `BlockHandles`;
- не открывать `BlockActionsPanel`;
- отключить блочный drag-and-drop и drop indicator;
- убрать постоянные кнопки добавления блоков возле строк;
- убрать Grid, отдельные блочные рамки и оформление, разделяющее обычные абзацы на карточки;
- использовать естественный вертикальный поток документа;
- сохранить существующую ширину контента и типографику Amby;
- не показывать блочный chrome при обычном наведении на абзац.

При этом сохрани:

- редактирование через Tiptap;
- bubble toolbar для выделенного текста;
- slash-меню;
- горячие клавиши;
- wiki-ссылки и теги;
- таблицы;
- callout;
- изображения и вложения;
- transclusion;
- HTML и opaque Markdown nodes;
- Amby database/interactive blocks;
- вставку медиа;
- undo/redo;
- текущий parser/serializer.

Сложные элементы должны оставаться встроенными в поток документа. Не заменяй их сырым Markdown и не заставляй пользователя конвертировать заметку в другой тип.

Если конкретный NodeView имеет блочную рамку как часть содержимого, сохрани её, когда она нужна для понимания элемента. Убирай интерфейс управления блоками, а не визуальную семантику callout, таблицы, базы или embed.

## Чего не нужно делать сейчас

Не реализуй в этой итерации полную копию Obsidian Live Preview.

В частности, не создавай с нуля сложную систему динамического раскрытия каждого Markdown-маркера около курсора, если текущая архитектура этого уже не поддерживает.

Не расширяй задачу на:

- отдельные типы заметок;
- конвертацию документов;
- разные иконки в дереве;
- поблочное хранение обычных абзацев;
- перенос всего содержимого в sidecar JSON;
- базы данных нового формата;
- переработку SourceEditor;
- переработку Read mode;
- полную имитацию всех деталей Obsidian или Notion.

Цель первой версии — дать пользователю простой непрерывный режим письма и сохранить сложные возможности Amby по необходимости.

## Бесшовное переключение

При переключении «Блочный» ↔ «Строчный» должны сохраняться:

- содержимое;
- несохранённые изменения;
- Tiptap instance;
- позиция курсора;
- выделение;
- прокрутка;
- фокус;
- undo/redo;
- открытые панели, если они допустимы в новом режиме.

Если при переходе в Строчный режим открыта блочная панель или идёт drag operation, корректно закрой или заверши её без изменения документа.

Простое переключение не должно:

- вызывать `onChange`;
- запускать лишнее сохранение;
- сериализовать документ заново;
- изменять Markdown;
- перемещать курсор в начало;
- прокручивать документ.

## Безопасность Markdown

Не ухудшай существующую защиту Markdown round-trip.

Учитывай, что Tiptap не может побайтово представить все варианты Markdown. `SourceEditor` остаётся единственным редактором сырого исходника.

Проверь существующий `roundTripCheck()` и его фактическое использование. Если он используется только в тестах, не превращай это автоматически в большой отдельный рефакторинг. Сообщи об этом как об обнаруженном ограничении. Добавляй автоматическую маршрутизацию в Source только если она уже предполагалась существующей архитектурой и реализуется локально без расширения задачи.

Не изменяй frontmatter и opaque Markdown при простом переключении Live layout.

## Тесты

Добавь целевые автоматические тесты на новую функциональность.

Обязательно проверь:

- значение по умолчанию `block`;
- безопасную загрузку старых настроек;
- нормализацию неизвестного значения;
- сохранение глобального выбора;
- правильное отображение активного пункта меню;
- передачу layout в `TiptapEditor`;
- наличие `BlockHandles` в Блочном режиме;
- отсутствие `BlockHandles` в Строчном режиме;
- отсутствие размонтирования редактора при переключении;
- отсутствие `onChange` при переключении;
- неизменность Markdown;
- сохранение undo/redo и selection там, где это разумно проверить автоматически;
- отсутствие изменений в Source и Read;
- работу сложных NodeView в обоих Live-режимах.

Используй существующую тестовую инфраструктуру Vitest. Не добавляй новый тестовый фреймворк без необходимости.

## Визуальная проверка

После реализации запусти локальный Vite preview и визуально проверь оба режима. Если доступен навык управления браузером, используй его.

Проверь:

- обычные абзацы и заголовки;
- длинную заметку;
- списки и чекбоксы;
- таблицы;
- callout;
- изображения;
- transclusion;
- Amby block/database block;
- тёмную и светлую темы;
- узкую и широкую ширину;
- несколько вкладок;
- split editor;
- переходы Live → Source → Live;
- переходы Live → Read → Live;
- Block → Linear → Block без скачка курсора и прокрутки.

В Строчном режиме не должно быть ручек, блочного drag UI и визуального ощущения Grid. В Блочном режиме текущий интерфейс должен сохраниться.

## Критерии готовности

Задача завершена только если:

- в меню есть режимы «Блочный» и «Строчный»;
- они работают внутри одного существующего `TiptapEditor`;
- Блочный режим сохраняет текущее поведение;
- Строчный режим не показывает `BlockHandles`, Grid и блочный drag UI;
- сложные элементы Amby остаются доступны в Строчном режиме;
- переключение не изменяет Markdown;
- курсор, selection, scroll и undo/redo не теряются;
- последний глобальный выбор восстанавливается после перезапуска;
- Source продолжает использовать CodeMirror без изменений;
- Read продолжает использовать Tiptap `editable=false` без изменений;
- старые настройки совместимы;
- тесты, typecheck и production build проходят;
- оба режима визуально проверены.
