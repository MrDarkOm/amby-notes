# Markdown compatibility matrix

This document is the executable compatibility contract for M2. The Markdown
file remains the source of truth.

## The Live Preview contract

A note is not converted when it is opened. Every top-level block of the note
(a paragraph, a heading, a list, a table, a quote, a column set, …) keeps the
exact text it was read from, together with the lines that stood between it and
the block before it.

1. **A save without an edit writes the same file, byte for byte.** This holds
   for every note admitted to Live Preview and is checked when the note is loaded.
2. **A block that was not edited is written as the text it was read from**,
   whatever its spelling (`* * *`, `1)`, a sparse list, a setext heading).
3. **A block that was edited is written in the editor's own form**, and only
   that block. The lines between it and its neighbours become the usual single
   blank line. A block made in the editor has only that form.
4. **Rewriting a block changes its spelling and nothing else.** A block the
   editor cannot write in its own form without changing it — for the editor's
   parser, or for an independent plain markdown-it reading that would notice
   anything the editor's parser drops while reading (a link title once was such
   a thing) — is not rebuilt at all. It is shown in Live Preview as its own
   source text (an opaque block) and written back exactly; the rest of the note
   stays editable. Such a block is changed in Source mode. The whole note is
   then checked the same way, and a note that still cannot promise this (a link
   definition, mixed line endings) stays in Source mode.
5. **Before the first save that may rewrite a block's source, the file being
   replaced is kept in local history**, regardless of autosave coalescing and of
   whether history is switched on for the vault (see `vault-format.md`).

"Not edited" needs no tracking of edits: a block is unchanged while the editor
would write for it exactly what it would have written right after reading it.
Undo, a reload of the editor through JSON, moving and duplicating a block
therefore keep its bytes; splitting it or changing its text or type does not.

Kept text is never trusted blindly. What is about to be saved is read back, and
when kept text would change what its neighbours mean in their new place (an
indented paragraph moved under a list, an unclosed code fence before a new
block), the note is written in the editor's own form throughout.

The unit is the top-level block. Editing one item of a list rewrites the whole
list; editing one cell rewrites the table (a table also keeps its own source
until its cells change). Finer units are a later step.

The matrix certifies compatibility and data preservation, not necessarily a
special visual widget for every construct. For example, Mermaid and math may
remain portable Markdown text/code until their dedicated renderer is enabled;
their source is still preserved exactly.

## Status legend

| Status                 | Meaning                                                                                                                            |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Live, byte-exact**   | The editor writes this form itself: the block is the same bytes before and after an edit elsewhere in it.                          |
| **Live, source kept**  | Opened in Live Preview. The block keeps its bytes until it is edited; then it is written in the editor's own form, meaning intact. |
| **Live, opaque block** | Shown in Live Preview, never rebuilt: the source is the block.                                                                     |
| **Source-only**        | Rewriting a block would lose something, so the note is opened in Source mode and never rewritten.                                  |
| **Planned**            | Not yet a supported M2 contract.                                                                                                   |

| Whitespace and markers in text typed in the editor                                                                                                                                                                                                            | **Live, byte-exact**       | Whitespace at the start of a line the editor writes (paragraph, heading, list item, quote, after a hard break; space, tab, no-break space) is written as its first character's numeric reference (`&#32;`, `&#9;`, `&#160;`), a space-only paragraph included. | Display math (`$$ … $$` on its own lines) and Mermaid fences                                                                                                                                                                                                  | **Live, byte-exact**       | Block math is held as an opaque source block and drawn as a formula; its source shows when the block is selected and is changed in Source mode. A `mermaid` fence is an ordinary code block with its diagram drawn above the code. Nothing drawn is written to the file.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Malformed closed YAML is kept outside the editor's Markdown body and preserved
byte-for-byte on body saves. The body may enter Live Preview only after the usual
lossless round-trip check. Non-mapping YAML roots use the same policy. Missing
closing fences have no trustworthy body boundary: the full source stays
searchable and editable in Source mode, with a warning and no automatic repair.
YAML properties are unavailable in both cases; see `vault-format.md` for identity,
save, conflict, and restoration rules.

## Test fixtures

- `src/components/workspace/tiptap/fixtures/live-preview-safe.md` is the
  golden fixture for syntax the editor writes itself.
- `src/components/workspace/tiptap/markdown-block-source.test.ts` holds the
  invariant "saved without an edit, the file is the same" for the fixtures, the
  shared corpus and a generated corpus, the forms the editor spells differently,
  and the edit cases (one block edited, deleted, moved, duplicated, split, undone).
- `src/components/workspace/tiptap/fixtures/obsidian-compat.md` exercises
  opaque frontmatter, foldable callouts, tables, footnotes and raw HTML.
  Its body opens in Live Preview with its footnotes as nodes;
  frontmatter is kept by the Rust write boundary.
- `src/components/workspace/tiptap/fixtures/malformed-frontmatter.md` verifies
  that malformed YAML is never passed through visual serialization.
- `src-tauri/src/index/malformed_tests.rs` covers malformed lists/indentation,
  scalar/sequence roots, missing fences, searchable bodies, opaque saves, external
  conflicts, restore/move behavior, and envelope-preserving link refactors.
- `tests/fixtures/markdown-compatibility.json` is the shared cross-platform
  corpus executed by both TypeScript (Vitest) and Rust (`cargo test`) to ensure
  identical indexing of tags, wikilinks, targets, labels and protected regions
  (code fences, inline code, comments, frontmatter) between web fallback and
  desktop Tauri index.

The unit suite also generates deterministic compatibility corpora (80 documents of
clean blocks, 400 of clean and odd blocks with varied gaps). Every generated
document is either saved byte for byte when nothing was edited, or rejected by
the Live Preview guard before it can be saved; for an admitted one the editor's
own form must be admitted too. This is a lightweight fuzz regression guard
without a non-reproducible test seed.

Selection is transferred between Source and Live Preview using a local textual
anchor. The Markdown bytes and editor history are not changed by a mode
transition; if an anchor is ambiguous, the nearest valid cursor position is
used. Since every admitted Live Preview document is saved byte for byte until it
is edited, the automated re-open compatibility check is equivalent to opening the
original file in Obsidian: its bytes are unchanged.

Admission to Live Preview is decided when a note is loaded (opened, reloaded from
disk, restored, conflict resolved), not by what is typed afterwards. A note that
fails the contract above opens in Source mode and stays there while it is
edited; the editor never jumps between modes on its own. The user leaves Source
only by choosing Live Preview, which is refused while the current text still
fails it. Typing in Live Preview never switches to Source: the editor writes
its own document, and a note it could not read back opens in Source the next time.

When adding a Live Preview feature, add a fixture or focused round-trip case
first. When rewriting a construct would lose anything a reader of the note sees,
the block must be kept as its source text (or the note kept Source-only): add
that case and its test before the feature.
