## Решения, которые принял автор тестов (на проверку Opus)

1. **Где проверка запуска.** План говорит «отказ запуска», но `plans check` и `user plan set <имя> --default` должны работать именно тогда, когда запуск отказал (П52 «лечит»). Поэтому `AppState::try_open` **не отказывает** по тарифам, а отдельный `AppState::check_plans()` (файл верен, у закреплённых есть тариф) зовёт `serve` до прослушивания. Тесты проверяют `check_plans`; в заглушке `serve` его не зовёт.
2. **Формат `meta.last_migration`** в плане не задан: тесты требуют JSON-объект `{from, to, at_ms, backup}` (имя файла копии).
3. **Форматы вывода команд** (план говорит «вывод», `--json`): `user plan show --json` → `{username, plan{name,title,pinned}, limits{…}, usage{…}}`; `plans list --json` → `{default_plan, plans[{name, title, users, pinned_users, пределы…}]}` (`users` — действующие, включая «по умолчанию»); `user list --json` получает `plan`, `pinned`, `used_bytes` (= `live + pending`); `space list --json` → `[{space_id, created_ms, live_bytes, history_bytes}]`. Журнал — `stderr` команды (в Docker это журнал сервера). `space remove` без `--yes` — код 2, `plans check` с проблемой — код ненулевой.
4. **Мелочи протокола:** кривое `replaces` (не 32 строчных hex-символа) — `400 bad_request`; `needed_bytes = used + size − зачёт − limit`; источник `server` — когда потолок сервера меньше тарифа.
5. **Пробел в П61.** Строка У2 «История 30 дней, **до 1 ГБ**» требует `max_history_bytes`, а `limits` в П61 его не перечисляет. Тесты просят ключ `limits.max_history_bytes` (`null` — нет потолка), клиент и `AccountOverview` его несут. Если Opus против — вычеркнуть тест `the_account_also_tells_the_ceiling_of_the_history` и подпись в У2.
6. **`sync_account_overview(known_vaults: Vec<String>)`:** список известных хранилищ интерфейс берёт из `useVaultStore.vaults` (в Rust такого реестра нет); Rust читает у каждого привязку (`space_id`) и называет в строке только имя папки. Типы — в `account_types.rs`; порядок строк (это хранилище, затем по размеру) проверяется в vitest, Rust отдаёт порядок сервера.
7. **Пределы в `UnsyncedView`:** необязательные `maxBytes` и `limitSource` рядом с `reason: "tooLarge" | "quotaFull"`; карточки строятся функцией `limitNoticesOf(status)`.
8. **Источник предела в движке:** `Plan`, если эффективный `max_file_bytes` из `account()` меньше `info.max_blob_bytes`; иначе `Server`. `RemoteError::Rejected` не несёт `details`, поэтому для 413/507 от сервера тесты проверяют только вид причины, а не число.

## Чего нет и почему

- **Мини-движок симуляции не знает пределов**, поэтому новые инварианты `sim/src/limits.rs` не проверены «сломанными мини-движками» (как инварианты К1/К2). Проверка их самих — задача реализующей сессии (или отдельный шаг).
- **Проверка «до» миграции** — только на повреждённой версии 1 (страница затёрта). «Проверка после» отдельным тестом не выделена: её видно только как успех миграции.
- **Тесты, которым нужен свой сервер, в режиме Docker пропускаются** (`SKIP`), как и прежние: тарифы пишутся в файл каталога данных. Команды администратора для Docker работают через `UserAdmin::run`, но проверяющих их тестов с чужим сервером нет.
- **Движок «в чистом виде»** (`sync/core/tests`) не получил своих файлов: у движка нет теста без сервера для этих решений, они проверены против настоящего сервера (`limits_e.rs`); падают они сначала из-за заглушек сервера (`user plan set`), а не движка. Движок станет причиной красного, когда сервер заработает.
- **Не проверено живыми тестами:** `GET /v1/account` для сервера, которого нет в процессе; внешний вид (проверяется в нативном окне); `quota recount` (нужен только если замер провалится); `SIGHUP` (Е.10-8 — не нужен).
- **Тесты, которые на заглушках зелёные по замыслу (страж):** `an_old_style_request…` убран; в `sync/` страж один по замыслу — тест ключей `noSpacesHint` в vitest (ключи добавлены заглушкой). Зелёные новые тесты проверяются скриптом: тест из списка, который прошёл, — ошибка.

## Открытые вопросы реализующей сессии

- `AppState::check_plans` должен звать `serve`; `main.rs` пока пересылает новые команды в `admin::run_cli` по слову команды и по `--plan`.
- Крейт сервера нужно поднять (например, до `0.2.0`) — тест сверяет `/v1/info.server_version` с `amby_sync_server::VERSION` и с «не `0.0.0`».
- Документы: `sync/server/README.md` (резервная копия перед `space remove`, откат миграции), строки Б.0.1 и Б.9 в плане.
