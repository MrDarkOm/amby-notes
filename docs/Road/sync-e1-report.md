## Проверка Opus (20.10) и правки

Opus принял формат; по его замечаниям внесено (отдельный коммит после первых трёх):

- **Ф16:** повторяющийся ключ JSON на любом уровне — `Malformed`. В эталоне `object_pairs_hook`, векторы `duplicate_key*`, тест `a_repeated_key_in_the_header_json_is_an_error`.
- **Ф26:** `size` больше `2^62` — новая ошибка `SizeTooLarge`; `padme` и `sealed_body_len` возвращают `Result`, `open_body` проверяет размер первым. Тесты в `crypto_standards.rs` и `crypto_body.rs`.
- **Ф18, Ф25:** любое несовпадение эпохи, включая 0, — `EpochMismatch`; `header_envelope_epoch` для эпохи 0 — `Malformed`. Тесты `an_epoch_of_zero_in_a_header_is_a_mismatch`, `epoch_zero_in_a_body_is_an_epoch_mismatch`.
- **Ф33 (новое):** синтаксис пути, ошибка `InvalidPath`, проверяется раньше NFC. Тесты на каждое правило (включая 4096 байт против 4097 и символы в четыре байта), порядок проверок, свойство «принятый путь не выходит за корень», векторы эталона (`paths`, `path_*`). Пример пути с `\`, табом и переводом строки в векторах заголовка перенесён в неизвестное поле, потому что в пути их теперь нельзя.
- **Ф8:** добавлена причина нижних пределов. **Э3:** добавлены требования к тестам (согласованность полей заголовка, потоковое открытие через временный файл). **Раздел 6 плана:** правило веток `sync/*` и вливания в `dev` обычным merge без squash. Все решения приложения помечены «проверено Opus, 20.10».
- Остаётся напомнить: перед вливанием Э1 в `dev` убрать `continue-on-error` у `cargo test` в `sync.yml`.

## Реализация

Шаги 6 и 7 раздела 6: код написан по приложению А, ветка `sync/e1-impl` (от `sync/e0-e1-tests`).

- **Тесты:** все 95 Rust-тестов проходят (`npm run sync:test`). Файлы в `sync/core/tests/`, `sync/vectors/`, `sync/reference/` и цели фаззинга не менялись; изменился только `sync/core/fuzz/Cargo.lock` (следствие новой зависимости ниже).
- **Интерфейс** `sync/core/src/crypto/` не менялся: только тела функций и приватные помощники. Единственное добавление: `pub(crate) const MAX_SIZE` в `padme.rs`.
- **Зависимости:** только перечисленные в `Cargo.toml` плюс прямой `serde` (он и так в дереве через `serde_json`): без него нельзя написать `Visitor`, который отвергает повторяющиеся ключи JSON (Ф16) и дробные числа (Ф15) во время чтения.
- **CI:** у шага `cargo test` в `sync.yml` убран `continue-on-error` (у `req-check` остаётся).
- **Проверки:** `sync:lint` (fmt, строгий clippy, cargo-deny) чистые.

### Решения там, где приложение молчит

- Обёртка ключа: неверная версия — `UnsupportedVersion`, неверная длина — `Malformed`.
- Тело короче 32 байт после верных магии, версии и эпохи — `Malformed`; остаток после преамбулы короче 16 байт — `Authentication`.
- Заголовок: сначала формат (`UnsupportedFormat`), потом поля (`Malformed`), потом путь (`InvalidPath`, `PathNotNfc`), потом версия (`VersionMismatch`). Нули в конце снимаются все; ненулевой мусор после JSON даёт `Malformed` (так в векторе `nonzero_padding_byte`), `BadPadding` только для длины не кратной 256 или пустого текста.
- `seal_header` и `canonical_header_json`: `format` не 1 — ошибка (`UnsupportedFormat` или `InvalidParams`); эпоха ключа 0 — `InvalidParams`. Это приложением не оговорено, тестов нет.
- Параметры Argon2id проверяются до любого обращения к случайности.

### Фаззинг

Обе цели на nightly по 30 минут: `header_open` — 128 млн запусков, `body_open` — 301 млн запусков. **Падений нет**, примеров для корпуса нет. Замечание: покрытие `body_open` крошечное (61 ветка): случайные байты почти всегда отвергаются на магической строке `AMBYBODY`, до расшифровки не доходят. Чтобы цель проверяла и разбор кусков, ей нужен начальный корпус из настоящих тел или правило «подставить верную преамбулу». Цели менять запрещено, поэтому это предложение для проверки Opus.
