# Синхронизация, Э4 (движок в приложении): отчёт

Дата: 23 октября 2026 года. Ветка `sync/e4-engine` (от `dev`, `cacf6c3`). План: [sync-plan.md](../sync-plan.md), раздел 6 («Строгость по риску»: для интерфейса и связки с приложением порядок облегчённый — тесты первым коммитом, потом код, одна проверка Opus; мутации и независимые эталоны не обязательны).

Что умеет синхронизация теперь: хранилище можно **включить** (новое пространство на сервере или существующее), после чего заметки, вложения, пустые папки и имена на любых языках передаются между компьютерами зашифрованными; правка появляется на другом компьютере сама. Включить можно **только на хранилище, которое пользователь отметил как тестовое**, пока не пройдены ворота перед настоящими заметками (мутации движка и долгая симуляция).

## Ошибки тестов (исправлены отдельным коммитом `b27004b`)

1. `hints_tests`: команда переименования сама дописывает расширение, а предпросмотр только планирует; тест переименовывал на диске не то и не тогда.
2. `vault_fs_tests`: APFS не разрешает имена не в UTF-8, файл создать нельзя; тест возвращается, если система отказала (проверка работает на Linux).
3. `session_tests`: «одна пачка на проход» сравнивалась с числом 3, а первый проход запускается сам; сравнение с реальным числом проходов.
4. `runtime_tests`: ждал `last.uploaded == 2`, которое затирает следующий пустой проход; ждёт два элемента на сервере.
5. Три предупреждения строгого Clippy в тестах (`result_large_err`, `cloned_ref_to_slice_refs`, `manual_is_multiple_of`; ещё одно такое же в тестах клиента позже).

Обещания тестов не менялись. Одна проверка обещания «заметки не передаются» (заголовок раздела, русский и английский тест) заменена, потому что это обещание этим этапом сознательно снято.

## Что сделано

Подробности — в [sync/MAP.md](../../sync/MAP.md) и [src-tauri/src/MAP.md](../../src-tauri/src/MAP.md). Коротко:

- **Порты.** `LocalFs` — `src-tauri/src/sync/vault_fs.rs`: атомарная запись через временный файл рядом, снимок `sync-overwrite` перед заменой (даже при выключенной истории; ошибка снимка отменяет запись), корзина `.amby/trash/` ровно для названного файла (не для всей «связки» заметки), переименование без перезаписи (ссылка + удаление, папка — проверка), путь не может выйти из хранилища (ни `..`, ни ссылка на пути). `StateStore` — `state_db.rs`: SQLite с номером схемы, одна транзакция на операцию, повреждённый файл откладывается, файл новее схемы не трогается, блокировка файлом. `Remote` — `remote.rs` поверх асинхронного клиента, `Clock`, `Random` — `SystemClock`, `OsRandom`.
- **Сессия** (`session.rs`): проходы по событиям файлов (через правило Р4, включая собственные записи Amby и файлы `.amby/`), по уведомлениям сервера (свои коммиты не будят), по просьбе пользователя и раз в 5 минут; пауза Д19 5, 10, 20… секунд до 5 минут; остановки Р8 ждут ответа; незавершённый журнал (`planned`/`inProgress`, нечитаемый тоже) задерживает отправку; блокировка сессии на хранилище.
- **Среда** (`runtime.rs`): включение (новое пространство с именем по Ф34 или существующее, ключ пространства хранится в состоянии обёрнутым ключом аккаунта, поэтому хранилище запускается без сети), возобновление при открытии хранилища и после входа/выхода, отключение сохраняет связь.
- **Наблюдатель и редакторы.** Записи синхронизации **не** регистрируются как собственные записи приложения: наблюдатель сообщает о них как о правке другой программы, поэтому открытый редактор получает обычный конфликт (проверено настоящим наблюдателем системы). События пачки склеиваются (`EventBatch`): каждый путь один раз после пачки.
- **Подсказки о переименовании (Д70)**: команды переименования и перемещения записывают пары до выполнения.
- **Интерфейс** (`sync-vault-panel.tsx`): включение (новое/существующее пространство, отметка тестового хранилища и предупреждение), статус, остановки Р8 с понятным текстом, список конфликтов с тремя вариантами, список «Не синхронизируется» с причинами; русский и английский.
- **Ворота**: `gate.rs`, константа `GATES_PASSED = false`; снимается отдельным коммитом после согласия владельца.
- **Перенесённое из Э3**: `FsError::AccessDenied` (один недоступный файл не останавливает проход), файл не выгружается второй раз под старым путём, копия по Д71 в списке конфликтов, тест `Interrupted`, повторное использование соединений тестового клиента. Потоковое шифрование тела **не** сделано: файлы крупнее 256 МБ остаются в списке «Не синхронизируется».
- **Документы**: `.amby/sync/` и таблица «какие файлы `.amby/` синхронизируются» в `docs/vault-format.md`; тест держит таблицу и правила движка вместе.

## Решения реализации, не отменяющие приложения Б и В

- Копия конфликта получает тот же `amby-id`, что и файл (Р7: «проверить на Э4»). Проверка по коду показала **дефект индексатора**: копия сортируется раньше файла (`Name.0123…` < `Name.md`) и забирала стабильный ID, а оригинал получал ключ конфликта и переставал редактироваться. Исправлено (см. ниже), а не вынесено в `.amby/sync/conflicts/`, как предполагал план: копия остаётся видимым файлом, ID не теряет оригинал.
- Событие `hello` потока уведомлений будит проход только если голова ленты дальше курсора; свои коммиты не будят.
- Сервер, не отвечающий, и пропавшая папка хранилища — разные вещи: `VaultMissing` сам проверяется заново с нарастающей паузой, остальные остановки ждут пользователя.
