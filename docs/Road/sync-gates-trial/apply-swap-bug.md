# Найдено при разборе мутантов apply.rs:170 (break_cycle / раунды переименований)

Ветка: claude/priceless-turing-155156. Код движка НЕ менялся.

## Исправление Codex (25 октября)

После разрешения владельца ошибка воспроизведена готовым тестом: на устройстве 1 остались
`S/a.md=AAA` и `S/b.md.amby-swap-0=BBB`. Из теста снят только `#[ignore]`, проверки не менялись.
В `apply_plan` разрыв обнаруженного цикла больше не зависит от продвижения независимых
переименований: он проверяется после каждого из первых двух раундов. Лимит Д49 в три раунда
сохранён; `break_cycle` по-прежнему переносит только участника найденного цикла.
Тест и все соседние сценарии `survivors_apply_decide` прошли: 39/39.
Это исправление не заменяет окончательный прогон ворот.

## Что происходит

Принимающее устройство (d1) получает с сервера «обмен имён» двух файлов (a↔b) вместе с независимым
переименованием третьего файла (c→d) в том же проходе. `apply_plan` делает 3 раунда переименований
(`for round in 0..3`) и ломает цикл (`break_cycle`) только если в раунде НЕТ прогресса и round < 2.
Независимое переименование c→d даёт «прогресс» в раунде 0, цикл ломается лишь в раунде 1, и на третий
раунд не остаётся места: файл остаётся под служебным именем `b.md.amby-swap-0`, а следующий же шаг
прохода (`push`) отправляет это состояние на сервер как обычное. В итоге имена перепутаны на ВСЕХ
устройствах, включая то, где пользователь сделал обмен.

## Воспроизведение (устройства d0, d1; на обоих S/a.md=AAA, S/b.md=BBB, S/c.md=CCC)

d0: a→tmp, pass; b→a, pass; tmp→b + c→d, pass. d1: один pass.
Ожидалось на d1 (как на d0): S/a.md=BBB, S/b.md=AAA, S/d.md=CCC.
Получилось: S/a.md=AAA, S/b.md.amby-swap-0=BBB, S/d.md=CCC; после settle то же самое на d0 и на сервере.
Чистый обмен без третьего переименования работает правильно (a↔b за 3 раунда). Цикл из трёх (a→b→c→a) тоже.

## Данные

лишний синхронизируемый файл с служебным именем.
