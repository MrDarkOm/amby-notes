## Что сделано

- **Сервер** (`sync/server`): `plans.rs` (строгий разбор файла, повтор имени ловится, эффективные пределы под потолками сервера); `quota.rs` (живые / ожидающие / история — запросами по индексам, без счётчиков); миграция v1→v2 (`VACUUM INTO backups/pre-v2-<мс>.db`, `quick_check` до и после, одна транзакция, `meta.last_migration` как JSON); `check_plans` перед `serve`; квота при `POST …/blobs` (с `replaces`), точная проверка роста в `commit` внутри той же транзакции (откат точки сохранения, пакет не оставляет следов), `413` с `details` и в коммите, `403 space_limit`, `DELETE …/blobs/{id}`, `GET /v1/account` (с `limits.max_history_bytes`); `keep_until_ms` закрепляется при замене и при удалении, уборка по нему, потолок истории убирает самые старые прежние версии и никогда не последнюю; команды `user add --plan`, `user list`, `user plan set|show`, `plans list|check`, `space list|remove` (`main.rs` отдаёт их `admin::run_cli`); README (файл тарифов, команды, резервная копия перед `space remove`, откат миграции).
- **Клиент и движок**: `account()`, `blob_start_replacing`, `blob_delete`; `PassLimits` читается на шаге 2 (после проверки сервера); больший, чем предел, файл без базы остаётся на диске и в списке (`TooLarge {max_bytes, source}`); файл с базой читается и участвует в правилах Р7 (чужая правка — конфликт без потерь), push отказывается его отправлять и показывает; `QuotaFull` с вычитанием `free_bytes` внутри прохода; `replaces`; `413/507` от `blob_start` и `commit` больше не `Rejected`-остановка: `413` снимает запись о коммите (ничего не применено), `507` держит её и запрещает отправку до успеха; закрытое сервером тело брошенного коммита (`422 unknown_blob`) снимает запись и загрузки (иначе проход застревал навсегда — найдено сценариями); брошенные загрузки освобождаются `blob_delete` по возможности.
- **Приложение**: `sync_account_overview` (пути канонизируются, состояние хранилищ читается только на чтение: `read_meta_only`), `HttpRemote`, раздел «Хранилища аккаунта» (У1–У2), три уведомления (У3) и «Показать список» через событие в Настройки, `space_limit` в мастере с кнопкой «Выбрать существующее», подсказка и кнопка «Создать новое» для пустого списка, тексты ru + en, `formatSize` (десятичные единицы).
- **Сила тестов** (отдельный коммит): `sim/src/broken_limits.rs` — настоящий движок с одним сломанным правилом (удаляет отказанный файл; теряет запись об отправке при `507`; считает отказы по пределу массовым изменением; повторяет отказанный `blob_start` в проходе; модель сервера, убирающая последнюю версию при потолке истории). `sim/tests/limits_self_check.rs`: настоящий движок проходит, каждый сломанный ловится своим инвариантом (новый `Kind::LimitRetryStorm`). В сценарии добавлены гонки посреди прохода (другое устройство занимает место / тариф понижают перед `blob_start` и перед `commit`), тариф `tiny`, выравнивание перед уборкой (иначе пропуск за уборкой — штатный полный сверочный проход Д58 — возвращает удалённый файл), и исправлен инвариант потолка истории (удалённая запись по сроку уходит штатно).

## Остановки: тесты, которые кажутся неверными (я их не менял)

1. **`retention::plans::a_body_that_the_latest_version_needs_survives_the_removal_of_older_rows`** — `fetch_file` не может открыть тело: оно создано `raw_file` (заполнитель 0x42 без `AMBYBODY`), а заголовок описывает `b"x"`. Поведение сервера проверено другими утверждениями теста (скачивание тел, `z_old` 404); падает только `assert_eq!(space.fetch_file(renamed), b"x")`.
2. **`limits_e::d75_a_507_on_one_file_does_not_stop_the_others_and_is_not_repeated`** — после всех утверждений про список и проход `w.server_files()` открывает все тела, в том числе `other.bin` из подсказки `raw_file` (заполнитель без `AMBYBODY`) → та же паника (`client.rs:662`). Утверждения про `QuotaFull` и список проходят; счёт `BlobStart == 2` до паники не доходит.
3. **`limits_e::d78_deleting_a_file_that_never_reached_the_server_sends_nothing`** — после удаления `Big/huge.bin` папка `Big/` пуста, и по Д45 движок отправляет пустую папку (коммит с `Big`, `kind: Folder`), поэтому `server_head` растёт. Файла на сервере нет и удаление не отправляется — как и требует Д78-в; ожидание «голова не выросла» ошибочно из-за папки.
4. **`limits_e::d78_a_merge_result_that_does_not_fit_stays_local_and_the_server_keeps_the_old`** — обе стороны дописывают строку в одно и то же место: по правилам приложения Г это пересечение, то есть конфликт (набор в `.amby/conflicts/`, в `Notes/a.md` версия сервера, локальная — в наборе, не влезающая копия значится `TooLarge`). Тест же ждёт локальный длинный текст в самом `Notes/a.md`. Ничего не потеряно, но ожидание тестом противоречит Г; либо изменить тест (правки в разных местах), либо решение владельца о том, где остаётся локальная версия.

Если координатор подтвердит, что тесты 1–4 неверны, их нужно поправить в отдельной сессии; кода сервера и движка это не меняет.
