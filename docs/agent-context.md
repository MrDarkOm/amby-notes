# Контекст проекта для ИИ-агентов

## Как устроено чтение

Общий вход — [AGENTS.md](../AGENTS.md): краткое описание продукта, обязательные
границы и порядок работы. [Корневая карта](../MAP.md) направляет к нужной
подсистеме. Локальные `MAP.md` рядом с кодом показывают владельцев поведения,
соседние границы, контракты и подходящие тесты. Полные прежние правила вынесены
в [agent-guidelines.md](agent-guidelines.md), с уточнениями актуальных путей и
проверок; читать нужно применимые разделы.

Обычный маршрут: вход → строка в корневой карте → одна локальная карта → нужный
код и тесты. Например, ошибка автосохранения ведёт в
[карту сохранения](../src/components/workspace/autosave/MAP.md), а изменение
оформления — в [карту тем](../src/themes/MAP.md). Межслойная задача требует
нескольких карт; искусственно ограничивать чтение одной нельзя.

Карты — обычные Markdown-файлы. Они намеренно не называются `AGENTS.md`,
`CLAUDE.md` или `GEMINI.md`: подробности открываются по задаче, а не подключаются
все сразу как инструкции. Корневые файлы не импортируют карты или полные правила.

## Входы разных инструментов

| Инструмент                    | Вход в этом репозитории                                       |
| ----------------------------- | ------------------------------------------------------------- |
| Codex                         | Корневой `AGENTS.md`                                          |
| Claude Code                   | `CLAUDE.md` импортирует только `@./AGENTS.md`                 |
| Gemini CLI                    | `GEMINI.md` импортирует только `@./AGENTS.md`                 |
| Другой агент с чтением файлов | Указать: «Начни с AGENTS.md и выбери нужный маршрут в MAP.md» |

Общие правила существуют в одном экземпляре. Не копируйте их отдельно для каждой
модели и не добавляйте в адаптеры импорты всех документов. Запускайте инструмент
из корня репозитория; после изменения инструкций откройте новую сессию. Личные
глобальные инструкции и настройки агента могут дополнительно влиять на контекст.

Механизмы сверены с официальными документами 1 октября 2026 года:
[Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md),
[Claude Code memory/imports](https://code.claude.com/docs/en/memory),
[Gemini CLI context/imports](https://geminicli.com/docs/cli/gemini-md/).
Codex собирает инструкции по пути проекта; Claude Code и Gemini CLI поддерживают
импорт Markdown через `@`. В Gemini загруженный контекст можно посмотреть через
`/memory show`. Настройки и версии клиента могут менять обнаружение файлов.

Это уменьшает стартовую документацию, но не обеспечивает «нулевой контекст»
или идеальное понимание без чтения кода. Любой прочитанный файл занимает контекст;
агент обязан проверять актуальное поведение. Автозагрузка не проверена запуском
отдельных сессий всех трёх CLI; адаптеры используют документированный синтаксис.

## Поддержание карт

При переносе владельца поведения или добавлении подсистемы обновите ближайший
`MAP.md` в том же изменении. Добавьте новую карту в корневую или родительскую
карту. Давайте ссылки на стабильные файлы и каталоги, а не номера строк,
перечни всех функций, текущие количества тестов или временный статус задачи.
Планы и архивы не должны подменять описание реализованного кода.

`npm run docs:check` проверяет существование локальных ссылок, доступность всех
карт из корневой карты, ограничение размера входов/карт и единственный импорт
общих правил в адаптерах. Проверка включена в полный gate и frontend CI.
Она не проверяет смысл описаний, Markdown-якоря или внешние сайты; актуальность
ответственности файлов остаётся частью ревью. Полные правила не ограничены
маленьким размером, поскольку не загружаются через импорт.

Для ручной проверки новой сессии дайте безопасную задачу: «Найди владельца
сохранения заметки и связанные тесты, ничего не меняй». Правильный маршрут
должен привести от корневой карты к autosave, storage и Rust-командам без
предварительного чтения всех планов, фикстур и сгенерированных файлов.
