# Творческий модуль Amby: контракт формата (редакция 3)

Дата: 13 октября 2026 года.
Версия формата: 3.
Статус: **действующий контракт данных плоской мастерской**. Заменяет вложенную модель
редакции 2 от 6 октября 2026 года.
План перехода и подтверждённые проверки этапа 0 — в [creative-workshop-plan.md](creative-workshop-plan.md).

---

## 1. Архитектурные принципы

1. **Заметка — данные, модуль — проекция и оформление.** Каждая сущность (персонаж, локация,
   глава, арка, якорь, заметка) — обычный Markdown-файл с метаданными во frontmatter.
   Каждый раздел — стандартная база данных Amby ([database-format.md](database-format.md)).
   Без творческого модуля хранилище остаётся полностью читаемым и структурированным.
2. **Папка мастерской — переносимая единица (W1).** Все данные мастерской находятся внутри
   единой корневой папки мастерской с маркером `amby-workshop.json`. В хранилище может быть
   одна или несколько мастерских; связи между разными мастерскими не поддерживаются.
3. **Плоская организация баз и принадлежность через связи (W2, W5).** В мастерской нет
   вложенности папок проектов и вселенных. Базы сущностей мира, историй, арок, якорей и заметок
   расположены на одном верхнем уровне мастерской. Принадлежность сущности историям или вселенной
   задаётся исключительно свойствами-связями (Relation по ULID заметки).
4. **История как прикреплённая база текста (W3).** Единственное место физической вложенности —
   папка текста истории: карточка истории является строкой общей базы «Истории», а сама папка —
   прикреплённой базой данных страниц текста. Внутри папки истории других вложенных папок нет.
5. **Один источник фактов и атомарность.** Значения и связи хранятся во frontmatter заметок.
   Файл маркера мастерской и файл настроек текста истории фиксируют конфигурацию и схемы,
   но не дублируют значения свойств. Запись ведётся через Rust-слой атомарных операций
   с журналированием и поддержкой отката.

## 2. Структура каталогов мастерской

```text
Мастерская/
├── amby-workshop.json          ← маркер мастерской (формат v3)
├── Вселенные/                  ← база вселенных (ленивая, W11)
├── Истории/                    ← база историй (базовая)
│   └── Моя история/            ← прикреплённая база текста истории (W3)
│       ├── Моя история.md      ← карточка истории (строка базы «Истории»)
│       ├── Моя история.json    ← манифест базы текста истории
│       ├── amby-story.json     ← настройки текста (уровни, форматы, свойства)
│       ├── Глава 1.md          ← страницы текста (строки базы текста)
│       └── Глава 2.md …
├── Персонажи/                  ← база персонажей (базовая)
├── Локации/                    ← база локаций (базовая)
├── Арки/                       ← база сюжетных линий (ленивая, W11)
├── Якоря/                      ← база якорных событий (ленивая, W11)
└── Заметки/                    ← общая база заметок (ленивая, W11)
    └── Идеи/                   ← блокнот (подпапка базы «Заметки», W7)
```

## 3. Файл-маркер мастерской `amby-workshop.json`

Файл находится в корне папки мастерской. Наличие файла `amby-workshop.json` с валидным ULID
и `formatVersion: 3` определяет папку как мастерскую Amby.

```json
{
  "formatVersion": 3,
  "workshopId": "01JAX000000000000000000001",
  "name": "Моя мастерская",
  "icon": "icon:feather",
  "tags": ["Фэнтези", "Комиксы"],
  "revision": "rev_01JAX…",
  "sections": [
    {
      "id": "stories",
      "role": "stories",
      "name": "Истории",
      "databaseId": "01JAX000000000000000000002",
      "path": "Истории"
    },
    {
      "id": "characters",
      "role": "characters",
      "name": "Персонажи",
      "databaseId": "01JAX000000000000000000003",
      "path": "Персонажи"
    },
    {
      "id": "locations",
      "role": "locations",
      "name": "Локации",
      "databaseId": "01JAX000000000000000000004",
      "path": "Локации"
    }
  ]
}
```

### Спецификация полей `amby-workshop.json`

| Поле            | Тип            | Назначение                                                                                      |
| --------------- | -------------- | ----------------------------------------------------------------------------------------------- |
| `formatVersion` | целое (`3`)    | Версия формата. Значения выше 3 открывают мастерскую только для чтения без модификации маркера. |
| `workshopId`    | ULID string    | Стабильный уникальный идентификатор мастерской.                                                 |
| `name`          | string         | Отображаемое название мастерской.                                                               |
| `icon`          | string / null  | Закодированное значение иконки (`IconValue`).                                                   |
| `tags`          | string[]       | Пользовательские теги мастерской.                                                               |
| `revision`      | string         | Непрозрачный хэш/ревизия для защиты от конфликтов параллельной записи (CAS).                    |
| `sections`      | SectionEntry[] | Список зарегистрированных разделов мастерской (базовых, ленивых и авторских).                   |

### Элемент `sections`

```typescript
type SectionEntry = {
  id: string // Уникальный строковый ID раздела в мастерской (часто совпадает с role)
  role: WorkshopRole // Предопределённая системная роль или "custom"
  name: string // Пользовательское название папки/базы
  databaseId: string // ULID базы данных Amby
  path: string // Относительный путь к папке базы от корня мастерской
}

type WorkshopRole =
  "stories" | "characters" | "locations" | "universes" | "arcs" | "anchors" | "notes" | "custom"
```

## 4. Базы данных мастерской и их роли

Все разделы мастерской являются стандартными базами Amby. Роль определяет специализированное
отображение в интерфейсе модуля (панель, галереи, досье, фильтры).

| Роль         | База по умолчанию | Создание                | Назначение и стартовые свойства                                                                                                                                                                                                                                                                         |
| ------------ | ----------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `stories`    | `Истории`         | При создании мастерской | Каталог всех произведений. Заметки — карточки историй. Свойства: «Вселенная» (Relation на `universes`, 1 цель), «Статус» (Status), «Синопсис» (Text).                                                                                                                                                   |
| `characters` | `Персонажи`       | При создании мастерской | Досье действующих лиц. Заготовка `characters`: «Истории» (Relation на `stories`, multiple), «Вселенная» (Relation на `universes`), «Значимость» (Select: Главные / Второстепенные / Эпизодические), «Портрет» (Files), шаблон досье с разделами «Основное», «Характеристика», «Внешность», «Биография». |
| `locations`  | `Локации`         | При создании мастерской | Места действия. Заготовка `locations`: «Истории» (Relation на `stories`, multiple), «Вселенная» (Relation на `universes`), «Тип» (Select: Город / Район / Место / Природа), «Изображение» (Files), шаблон описания.                                                                                     |
| `universes`  | `Вселенные`       | Ленивое (W11)           | Карточки вымышленных миров/сеттингов. Свойства: «Описание» (Text), «Изображение» (Files).                                                                                                                                                                                                               |
| `arcs`       | `Арки`            | Ленивое (W11)           | Сюжетные линии (W8). Свойства: «Истории» (Relation на `stories`, multiple), «Персонажи» (Relation на `characters`, multiple), «Тип» (Select: Линия персонажа / Сюжетная / Мини-арка), «Статус» (Status), «Метка» (Select с цветом).                                                                     |
| `anchors`    | `Якоря`           | Ленивое (W11)           | Закреплённые ключевые события мира и историй (W8). Свойства: «Истории» (Relation на `stories`, multiple), «Вселенная» (Relation на `universes`), «Участники» (Relation на `characters`, multiple), «Арки» (Relation на `arcs`, multiple), «Описание» (Text).                                            |
| `notes`      | `Заметки`         | Ленивое (W11)           | Заметки автора мастерской (W7). Свойство: «Истории» (Relation на `stories`, multiple). Организуется блокнотами через подпапки.                                                                                                                                                                          |
| `custom`     | Любое имя         | По действию автора      | Авторские разделы («Организации», «Бестиарий», «Артефакты»).                                                                                                                                                                                                                                            |

### Ленивое создание (W11)

Базы «Вселенные», «Арки», «Якоря» и «Заметки» не загромождают диск при создании новой мастерской:

- В интерфейсе боковой панели их блоки присутствуют всегда.
- Сама папка и манифест базы создаются автоматически в момент добавления первой записи
  в соответствующий раздел (или при явном нажатии «Создать базу»).
- Создание базы выполняется единой транзакцией с созданием первой записи через recovery-журнал.

## 5. Модель истории и файл настроек `amby-story.json` (W3, W4)

История — это супер-заметка с прикреплённой базой текста.

- **Карточка истории:** `<Мастерская>/Истории/<Имя истории>/<Имя истории>.md` — файл строки общей базы «Истории». Не входит в собственную базу текста.
- **Манифест базы текста:** `<Мастерская>/Истории/<Имя истории>/<Имя истории>.json` — описывает прикреплённую базу страниц текста.
- **Файл настроек текста:** `<Мастерская>/Истории/<Имя истории>/amby-story.json` — описывает уровни структуры текста, доступные форматы страниц и системные свойства.

### Frontmatter карточки истории

Карточка — обычная заметка со служебными полями; значения записываются как строки YAML в двойных
кавычках с экранированием (так же, как `amby-title` у строк баз), поэтому кавычка, обратная черта или
двоеточие в названии не ломают frontmatter:

```yaml
---
amby-id: "01JAY000000000000000000002" # ULID заметки-карточки
amby-title: "Дом О'Брайена" # отображаемое название (W10)
amby-story-id: "01JAY000000000000000000001" # storyId из amby-story.json
---
```

`amby-story-id` связывает карточку с файлом настроек в той же папке; сейчас его пишет только создание
истории, а чтение и сверку при обнаружении модуль не выполняет — ключ нужен для будущего восстановления
карточки (`storyMissingMainFile`) и не должен меняться вручную. Байты карточки заносятся в журнал
операции, и при возобновлении записываются те же байты. Название истории — это имя папки и файлов,
поэтому оно проходит ту же проверку имени, что и название раздела: без `/ \ : * ? " < > |`, управляющих
символов, начальной и конечной точки и зарезервированных имён; пробелы по краям обрезаются.

### Содержимое `amby-story.json`

```json
{
  "formatVersion": 3,
  "storyId": "01JAY000000000000000000001",
  "text": {
    "levels": [
      { "id": "01JAY_LVL_1", "icon": "icon:book" },
      { "id": "01JAY_LVL_2", "icon": "icon:bookmark" },
      { "id": "01JAY_LVL_3", "icon": "icon:file-text" }
    ],
    "formats": [
      { "id": "01JAY_FMT_1", "kind": "manuscript" },
      { "id": "01JAY_FMT_2", "kind": "screenplay" },
      { "id": "01JAY_FMT_3", "kind": "comic" },
      { "id": "01JAY_FMT_4", "kind": "note" }
    ],
    "properties": {
      "level": "01JAY_PROP_LEVEL",
      "parent": "01JAY_PROP_PARENT",
      "order": "01JAY_PROP_ORDER",
      "format": "01JAY_PROP_FORMAT",
      "status": "01JAY_PROP_STATUS",
      "anchors": "01JAY_PROP_ANCHORS",
      "arcs": "01JAY_PROP_ARCS"
    }
  }
}
```

### Схемы уровней текста (W4)

Схема уровней выбирается автором при создании истории:

1. **«Роман»** (по умолчанию): Книга → Глава → Сцена (3 уровня).
2. **«Рассказ»**: Страница (1 уровень).
3. **«Комикс»**: Книга → Том → Глава → Страница (4 уровня; термин «Арка» исключён из схемы текста, так как закреплён за сюжетными линиями W8).
4. **«Своя»**: Пользовательский список от 1 до 6 уровней.

Уровни текста реализуются через свойство Select в манифесте базы текста. Идентификаторы `levels[].id` соответствуют ULID вариантов Select. Названия и цвета вариантов хранятся в манифесте базы текста, в `amby-story.json` хранится их иерархический порядок и значки.

### Системные свойства страницы текста истории

| Свойство  | Тип базы        | Назначение                                                                    |
| --------- | --------------- | ----------------------------------------------------------------------------- |
| `level`   | Select          | Уровень страницы в иерархии произведения.                                     |
| `parent`  | Relation (self) | Родительская страница той же базы текста (односторонняя связь, maxItems: 1).  |
| `order`   | Text            | Лексикографический ключ сортировки порядка следования (напр. `"a0"`, `"a1"`). |
| `format`  | Select          | Формат страницы (`manuscript`, `screenplay`, `comic`, `note`).                |
| `status`  | Status          | Статус готовности (группы `notStarted`, `inProgress`, `done`).                |
| `anchors` | Relation        | Связь с общей базой «Якоря» (W9, multiple: true).                             |
| `arcs`    | Relation        | Связь с общей базой «Арки» (W9, multiple: true).                              |

## 6. Правила связей и отношений (W5, W6, W8, W9)

### Связи сущностей с историями и вселенными (W5, W6)

- Каждая сущность мира (персонаж, локация, арка, заметка) содержит свойство-связь `Истории` типа Relation, указывающее на базу «Истории» (`multiple: true`).
- Сущность относится к истории, если:
  1. Связь явно указана во frontmatter заметки, **ИЛИ**
  2. Имя сущности упомянуто в тексте страниц этой истории (динамический поисковый резолвинг без принудительной записи во frontmatter).
- История, у которой не заполнена связь «Вселенная», считается **одиночной**.
- Переключателя «История \| Вселенная» нет (W6). В навигации доступны фильтры:
  - «Вся мастерская» — отображает все сущности всех баз.
  - Конкретная «Вселенная» — сущности, привязанные к этой вселенной или её историям.
  - Конкретная «История» — сущности, входящие в эту историю.
  - Сущности без привязки отображаются в группе **«без истории»**.

### Правило связей глав с якорями и арками (W9)

Поскольку база текста у каждой истории является изолированной базой со своим `databaseId`,
стандартное ядровое свойство Relation с двусторонним `inversePropertyId` не может связать
одну общую базу «Якоря» со всеми отдельными базами текста.

- Связи «глава → якоря» и «глава → арки» сохраняются исключительно в свойствах страниц текста конкретной истории.
- Обратное отображение («в каких главах участвует якорь/арка») строится запросом по проекции.
- Привязка якоря или арки со страницы досье самого якоря/арки выполняется модулем через запись ID якоря/арки во frontmatter выбранной главы соответствующей истории.

## 7. Правило разрешения коллизий имён (W10)

В общей базе мастерской (например, «Якоря» или «Персонажи») разные истории могут содержать
сущности с одинаковыми именами (например, событие «Финал» или персонаж «Алекс»):

1. **Имя файла:** Файловая система требует уникальности путей внутри одной папки. Механизм
   `unique_row_path` автоматически разрешает коллизии добавлением числового суффикса:
   `Финал.md`, `Финал 2.md`, `Финал 3.md`.
2. **Отображаемое имя:** Во frontmatter заметки всегда сохраняется исходное название автора:
   `amby-title: "Финал"`.
3. **Отображение в интерфейсе:** Все представления творческого модуля (дерево рукописи, досье,
   списки связей, поиск, таблицы баз) используют `display_title` (`amby-title`), поэтому
   пользователь везде видит чистое авторское название «Финал» без системных цифровых индексов.
4. Разделение сущностей по подпапкам историй внутри общих баз не используется (W10).

## 8. Заметки и блокноты (W7)

- База «Заметки» — общая для мастерской с мульти-связью «Истории».
- **Блокнот** — это физическая подпапка внутри папки «Заметки» (например, `Заметки/Идеи/`).
- Заметки внутри подпапки наследуют принадлежность базе «Заметки», а имя подпапки фиксируется
  в проекции `category_path: ["Идеи"]`.
- Перемещение заметок между блокнотами выполняется стандартной операцией перемещения файлов
  `move_item`, сохраняя целостность ссылок и ID.
- Сквозные темы заметок оформляются стандартными тегами (`tags` во frontmatter).

## 9. Обработка повреждений и проектов прежних форматов

### Проекты прежнего формата v2

- Папка, содержащая файл `amby-project.json` (формат v2):
  - Диагностируется как `legacyProjectFormat` («проект прежнего формата»).
  - Доступна в Amby как обычные папки и базы данных.
  - Творческий модуль v3 не изменяет, не конвертирует и не удаляет файлы проектов v2.
  - Миграция с v2 на v3 не выполняется (пользователей v2 нет).

### Повреждённые или неполные данные в мастерской

1. **Пропавшая база (`missingDatabase`):**
   Если папка базы, указанная в `amby-workshop.json`, удалена с диска:
   - Мастерская остаётся полностью работоспособной.
   - Раздел помечается предупреждением в каталоге диагностик.
   - Пользователю предлагается воссоздать базу или удалить запись о разделе.
2. **История без главного файла (`storyMissingMainFile`):**
   Если папка `Истории/<Имя>/` существует и содержит страницы, но файл `<Имя>.md` отсутствует:
   - Страницы текста доступны для чтения через базу текста.
   - В каталоге мастерской генерируется диагностика `storyMissingMainFile`.
   - Модуль предлагает создать карточку истории заново с привязкой существующей базы.
3. **Повреждённый манифест базы (`brokenManifest`):**
   Если файл `<Имя>.json` или `amby-story.json` содержит невалидный JSON:
   - Механизм границ (`discovery.rs`) изолирует повреждённую базу от остального дерева.
   - Мастерская продолжает работать для всех остальных исправных баз.
   - Диагностика указывает точный путь к повреждённому файлу.
4. **Удаление истории или вселенной (W12):**
   Удаление карточки истории или вселенной очищает только саму историю/вселенную.
   Сущности мира (персонажи, локации, арки, якоря), ссылавшиеся на неё, **не удаляются**:
   неразрешённые ULID сохраняются во frontmatter и автоматически восстанавливаются при
   создании сущности с тем же ID или очищаются автором вручную.

---

## 10. Rust-слой и транзакционность

- Все изменения мастерской выполняются с фиксацией в журнале восстановления
  `.amby/recovery/creative/<operationId>.json`.
- Создание мастерской, истории или раздела атомарно: сбой на промежуточном шаге
  полностью откатывает созданные папки и манифесты до исходного состояния хранилища.
- Повтор команды с тем же `operationId` возвращает сохранённый результат (`replayed`).
- Проекция мастерской кешируется в SQLite-индексе и автоматически обновляется
  по событиям файлового наблюдателя (`watcher`).
