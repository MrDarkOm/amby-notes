# Творческий модуль Amby: план переработки

Дата: 6 октября 2026 года.
Статус: согласованная концепция и план. Заменяет задание от 30 сентября
(редакции 1–2). Контракт данных — в [creative-format.md](creative-format.md).

## 1. Почему переделываем

Первая реализация `amby.creative` (незакоммиченная, не выпускалась) выполнила
прежний план по форме, но не по сути:

- нет backend-слоя: проект создаётся из интерфейса ~15 последовательными
  вызовами без отката, часть ошибок игнорируется;
- шаблон заметки применялся строковой перезаписью файла в обход lossless-записи;
- оверлеи типов ссылались на условные ID свойств; собственные типы не
  загружались после перезапуска;
- каждый режим загружал всю базу с пределом 500 записей и фильтровал на клиенте;
- «Рукопись» — дерево и карточка без редактора; «Доска» — сетка без раскладки по
  связям; страницы сущности нет;
- собственные карточки и иконки вместо компонентов баз, `IconValue` и тем;
- тесты проверяли вспомогательные функции на моках, а не путь записи.

Главная причина — концепция: получилась «панель над базой», а не рабочее место
автора.

## 2. Требования владельца

- Каждая сущность — заметка; без модуля персонажей и тексты можно забрать как
  обычные файлы. Модуль использует базы и возможности Amby и оформляет их.
- Отдельный боковой раздел с иерархией. Наглядно, понятно, красиво; разделов
  может быть много, если они интуитивны.
- Папка проекта — сам проект, переносится куда угодно; раздел «Творчество»
  читает файл структуры.
- Уровни произведения настраиваются (например, Книги → Арки → Главы → Страницы).
- При создании страницы выбирается формат: рукопись, сценарий, другое.
  Сценарный редактор — позже.
- Заложить вселенные и сборники с общим миром.
- Базовые разделы минимальны; «Организации», «Артефакты» и подобные создаёт
  автор.
- Ориентиры: KIT Scenarist, Campfire (связи), собственная система в Notion
  (галерея персонажей с группировкой по значимости, вкладки-категории).

## 3. Решения

| №   | Решение                                                                               |
| --- | ------------------------------------------------------------------------------------- |
| R1  | Раздел = отдельная база. Общая база «Сущности» и оверлеи типов отменены.              |
| R2  | Проект = папка с `amby-project.json`; виды `collection` и `story`; вложенность папок. |
| R3  | Общий мир вселенной лежит в сборнике; история видит свои разделы и разделы сборника.  |
| R4  | Текст — одна база с настраиваемыми уровнями, родителем и дробным ключом порядка.      |
| R5  | Формат страницы — поле заметки; сценарный редактор отложен.                           |
| R6  | Базовые разделы: Текст, Заметки, Персонажи, Локации. Остальное — действием «Раздел».  |
| R7  | Отношения с подписью делаются через связь на несколько баз в ядре, без базы «Связи».  |
| R8  | Создание и обнаружение проектов — в Rust; интерфейс собирается из компонентов баз.    |
| R9  | Группировка галереи добавляется в базы и доступна всем базам, а не только модулю.     |

## 4. Поверхности

- **Боковой раздел «Творчество».** Дерево: сборники → истории → группы →
  разделы; у раздела текста — дерево уровней с перетаскиванием. Клик открывает
  обычную вкладку Amby.
- **Страница проекта.** Шапка (иконка, название, метки) и вкладки разделов;
  «Обзор» — прогресс текста, недавние правки, быстрые действия.
- **Раздел мира.** Виды базы: галерея карточек (с группировкой), таблица,
  список; вкладки-категории — сохранённые виды.
- **Досье.** Та же заметка в оформлении: обложка или портрет, ключевые поля,
  текст, «Появляется в…», связи.
- **Текст.** Редактор Amby, справа контекст страницы (участники, место, арка);
  вид «Карточки» для планирования.
- **Карта связей.** Раскладка по связям; протягивание линии создаёт отношение.

## 5. Что проверено в коде

- Relation указывает на одну базу: `targetDatabaseId` в
  `src-tauri/src/database/format.rs`. Поле используется примерно в 110 местах
  Rust (из них ~50 в тестах) и ~50 местах интерфейса — связь на несколько баз
  является отдельной доработкой ядра.
- Вложенные базы поддерживаются: заметка принадлежит ближайшему `ambd.json`
  ([database-format.md](database-format.md), раздел 13).
- У видов есть `groupField` и готовая логика дорожек доски
  (`use-board-lanes.ts`); в `gallery-view.tsx` группировки нет.
- Скрытые каталоги пропускаются сканированием (`vault/scan.rs`), поэтому файл
  структуры не скрытый.
- В базах есть режим подэлементов (`subitemsMode`); пригодность для дерева
  текста не проверена.

Не проверялось: проверка зависимостей в `ModuleHost` (известна по журналу
изменений), показ не-Markdown файлов в дереве.

## 6. Этапы

Каждый этап — отдельный запуск с проверками и отчётом; следующий начинается
после просмотра владельцем.

| Этап | Результат                                                                                                                                                       |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | Согласованный контракт формата и макеты трёх экранов (боковой раздел, досье, текст).                                                                            |
| 1    | Каркас: Rust-слой (обнаружение, создание проекта и раздела), боковой раздел, страница проекта, разделы мира на галерее, группировка галереи. Старый код удалён. |
| 2    | Текст: уровни, дерево с перетаскиванием, порядок, выбор формата, контекст страницы, карточки, сборка в Markdown.                                                |
| 3    | Связи: связь на несколько баз в ядре, отношения с подписью, карта связей, блок связей в досье.                                                                  |
| 4    | Сборники и вселенные в полном объёме: общий мир, фильтр «в этой истории», перенос сущности между разделами.                                                     |
| 5    | Сценарный редактор, хронология, дополнительные форматы экспорта.                                                                                                |

Формат закладывает сборники с этапа 1 (вид `collection`, вложенность); этап 4
добавляет удобства поверх.

## 7. Что берём из первой реализации

- `src/lib/storage/fractional-index.ts` и `manuscript-compiler.ts` — после
  сверки с контрактом (побайтное сравнение, тай-брейк по `amby-id`).
- Регистрацию модуля и зависимость от `amby.databases`.
- Остальной код `src/components/workspace/creative/`, `creative-port.ts`,
  `creative-types.ts` и их тесты удаляются на этапе 1.

## 8. Правила выполнения

Действуют `AGENTS.md` и [guidelines](agent-guidelines.md). Дополнительно:

- проверять путь записи, а не только чистые функции; состояние «работает на
  фикстуре» этап не закрывает;
- не менять версию, не делать commit/push без явного запроса;
- изменения ядра баз (группировка галереи, связь на несколько баз) оформлять
  как доработки баз с их собственными тестами и контрактом.
