## Windows retest after pipe fix

The first connection returns `vaultNotActive`; the second connects to the pending pipe instance. Windows still counts the preceding instance during handle teardown. Creating the next listener then failed with `ERROR_PIPE_BUSY` (231) at the two-instance limit. `accept` returned an error, the desktop stopped its listener and dropped the already-connected second instance, so the client saw `UnexpectedEof` and mapped it to `desktopRequestInterrupted`.

The listener now waits for a free instance on error 231 while retaining the connected instance. The current-user SID ACL and server SID verification are unchanged. The client still sends each request once, with no replay after connection. A Windows regression test reproduced both the server error and the client failure before the change, and passed after it with the expected two full error responses.

## Windows follow-up: bounded listener and native verification

The listener now waits at most five seconds for a replacement pipe instance. If Windows stays saturated, the pending connection is dropped without dispatching or retrying its request; the desktop loop treats the timeout as recoverable, and the listener rearms on the next iteration. The pipe ACL, remote-client rejection and server SID check remain unchanged. Windows tests cover both consecutive responses and recovery after a deliberately saturated listener times out. The test-only blocker is released before a later valid request. The Windows-exclusive lease is released before the archive migration test scans files, and the compatibility fixture assertion uses its original LF or CRLF bytes.

The native attachment test now joins the verbatim Windows path using `joinStoragePath`; the Debug fault test accepts the OS-specific sanitized `PermissionDenied` or `IoError`, while still requiring a failed flush within five seconds. Both previously failing targeted Rust cases passed individually. Byte-sensitive emoji assets and the editor Markdown fixture retain their repository bytes on Windows checkout; the documentation budget check normalizes CRLF for counting. Windows URL-path and lockfile test parsing were also corrected. All six previously failing Vitest files passed individually (227 tests).
