# Native UI smoke harness

Run `npm run test:native:ui` to open the production React interface in a real
Tauri/WebView runtime with disposable vaults, isolated global settings and an
isolated WebView profile. The opt-in `native-contract` feature is never enabled
by normal development or production builds. The runner refuses to reuse a path
without its exact marker. It does not read existing Amby settings or vaults.

The command prints the generated profile path. Reopen the same profile with
`npm run test:native:ui -- "<printed path>"` to test full process restart.
Generated profiles live under ignored `.release-evidence/` and remain available
for byte-level verification. The regular storage contract still deletes its
own temporary profile automatically.

Windows smoke on 2026-09-01 covered UI save/autosave, close/reopen, rename,
successful and failed dirty vault switching, external create/edit/rename/delete,
external conflict resolution with local-copy preservation, deleted-file restore,
controlled identity migration, duplicate identity visibility, and a supported
paragraph edit in the compatibility corpus. The latter changed exactly the
intended paragraph while keeping every other fixture byte-exact and preserving
the rest of the edited file byte-for-byte.

This harness is full React lifecycle evidence, but it does not claim installer,
code-signing, removable/network-filesystem, or multi-window acceptance.

## Творческая мастерская: ручная проверка в нативном окне (этапы 7 и 8)

Эту проверку делает владелец: она не входит в `npm run test:native:ui` (тот гоняет контракт хранилища).
Остальное по плану мастерской проверено тестами; что именно не проверено руками — в разделе «Результаты этапа 7»
плана.

**Подготовка.** Пустая папка как новое хранилище (не рабочее хранилище и не его копия). Модуль «Творческая
мастерская» включён. Приложение — отладочная сборка без упаковки, собранная на этапе 7
(`src-tauri/target/debug/amby-notes`; она несёт интерфейс на момент сборки), либо `npm run tauri dev`.
В файловом менеджере держите открытой папку хранилища: часть шагов смотрит на диск.

1. **Инициализация и история.** Откройте панель «Мастерская». _Ожидается:_ экран «Мастерской здесь ещё нет»,
   «Папка: Мастерская» и кнопка «Инициализировать»; ни выбора мастерской, ни кнопки «Создать» внизу, ни названия
   для ввода. Нажмите «Инициализировать». _Ожидается:_ на диске папка `Мастерская` с файлом `amby-workshop.json`
   и семью базами: `Истории`, `Персонажи`, `Локации`, `Вселенные`, `Арки`, `Якоря`, `Заметки`; в панели сразу
   есть части «Якоря» и «Заметки» и, под «Мир», персонажи и локации; плашки «Создать недостающие разделы» нет.
   Затем «Создать» → «Новая история», название «Роман 1», схема «Роман». _Ожидается:_ дерево текста пустое с
   кнопкой «Добавить первую страницу»; на диске `Мастерская/Истории/Роман 1/` с тремя файлами: `Роман 1.md`,
   `Роман 1.json`, `amby-story.json`. Добавьте страницы: «Книга», внутри неё «Глава 1» и «Глава 2», в «Главе 1» —
   «Сцена». _Ожидается:_ уровни называются «Книга», «Глава», «Сцена»; у сцены нет кнопки «+» для вложенных.
2. **Персонаж при выбранной истории.** Вверху, в карточке «Истории», выбрана «Роман 1» (отдельная история:
   внизу в карточке «Вселенные» стоит «Отдельные истории»). В части «Персонажи» нажмите «+», введите «Анна»,
   Enter. _Ожидается:_ «Анна» остаётся в списке и не пропадает после обновления панели; в списке мира нет
   раздела «Вселенные».
3. **Две карточки: истории вверху, вселенные внизу.** Вверху выберите «Все истории», создайте персонажа
   «Борис». _Ожидается:_ «Борис» стоит в конце списка в группе «Без истории», у «Анны» подписана «Роман 1»; под
   названием карточки — «1 история». Верните вверху «Роман 1»: «Бориса» нет. Внизу откройте список: «Отдельные
   истории» и «Новая вселенная». «Новая вселенная», имя «Мир». _Ожидается:_ карточка внизу показывает «Мир», её
   страница открыта, вверху «Все истории» и «0 историй». Откройте базу «Истории» (вкладка на странице мастерской) и
   в строке «Роман 1» укажите «Вселенная» = «Мир». Выберите внизу «Мир». _Ожидается:_ вверху «Роман 1» в списке,
   «Анна» есть, «Бориса» нет. Выберите «Отдельные истории»: «Роман 1» в списке историй уже нет, «Борис» есть
   в группе «Без истории». Закройте и снова откройте приложение: выбор вселенной и истории сохранён.
4. **Блокнот.** Выберите «Роман 1». В части «Заметки» «Новый блокнот» → «Идеи». Создайте заметку «Мысль» и
   перетащите её на «Идеи». _Ожидается:_ заметка внутри блокнота, на диске `Заметки/Идеи/Мысль.md`. Откройте
   «Мысль» во вкладке. Удалите блокнот «Идеи» (меню блокнота → «Удалить блокнот…») и подтвердите.
   _Ожидается:_ «Мысль» поднялась в «Без блокнота» (файл `Заметки/Мысль.md`), вкладка с ней осталась открытой,
   папка «Идеи» ушла в корзину хранилища и восстанавливается оттуда.
5. **Якорь и арка, первая привязка.** В части «Якоря» нажмите «Добавить», введите «Встреча», Enter. Раздел
   «Арки» уже есть: создайте в нём арку «Любовь». Перетащите «Встреча» на «Глава 1».
   _Ожидается:_ у «Главы 1» значок якоря; в базе текста истории свойство «Якоря» уже стоит со времени создания
   истории (отдельной подготовки при первой привязке нет). Перетащите «Любовь» на «Главу 1»: рядом с названием цветная точка. В меню страницы
   «Главы 1» в «Якорях ▸» и «Арках ▸» стоят отметки; в меню якоря «Отвязать от страницы ▸» снимает привязку.
6. **Глава и блок справа.** Откройте «Главу 1». _Ожидается:_ справа (на узкой панели под текстом) «Сюжет
   страницы»: «Якоря этой страницы» — «Встреча», «Отталкиваемся от» и «Должны прийти к» — подсказки или
   соседние якоря, «Арки» — «Любовь» с цветом; редактор при этом не мигает и не теряет курсор.
7. **Рабочий стол истории.** Откройте страницу истории (кнопка справа от карточки «Истории»). _Ожидается:_ лента «Якоря»: «Встреча»
   с названием «Главы 1». Если установить «Главе 1» статус из группы «Готово», у якоря появится «пройден».
8. **Арка и досье персонажа.** Откройте арку «Любовь»: блоки «Якоря арки» («Встреча») и «Главы» («Глава 1»; при
   нескольких страницах — «от … до …»). В строке арки в свойстве «Персонажи» укажите «Анну», откройте «Анну».
   _Ожидается:_ в досье «Анны» блок «Арки» с «Любовью».
9. **Событие вселенной.** Откройте страницу вселенной «Мир». «События вселенной» → «Новое событие» → «Потоп»,
   Enter. _Ожидается:_ «Потоп» в списке событий; в панели при выбранной внизу «Мир» и «Все истории» он стоит
   первой группой «События вселенной»; в «Отдельных историях» его нет (события вселенных там не показываются).
10. **Прерванное создание.** Создание истории занимает считаные десятки миллисекунд, поэтому попасть в него
    руками трудно. Попробуйте: введите название новой истории, нажмите Enter и сразу принудительно завершите
    приложение (Force Quit или `kill -9`), несколько раз с разными названиями. Откройте хранилище снова.
    _Ожидается:_ каждая история либо создана целиком (три файла в её папке, открывается), либо её папки нет;
    полуготовых папок нет; в `.amby/recovery/creative/` нет файлов с незавершённой операцией и нет папки
    `quarantine/`. Если ни разу не попали в момент создания, проверка не удалась как проверка: падение на каждом
    шаге создания покрыто Rust-тестами (`create_test.rs`), но не нативным окном.
11. **Порядок страниц и якорей с клавиатуры.** Табом дойдите до строки страницы в дереве текста (не мышью) и
    нажмите клавишу меню или Shift+F10 (как в дереве файлов). _Ожидается:_ меню с пунктами «Выше», «Ниже»,
    «Вложить в предыдущую», «Вынести на уровень выше». У первой в списке страницы «Выше» серый; у «Главы 2» под
    «Главой 1» «Вложить в предыдущую» серый (тот же уровень); у «Книги» «Вынести на уровень выше» серый. «Глава 2» →
    «Выше»: она встала перед «Главой 1», после перезапуска порядок тот же. «Сцена» → «Вынести на уровень выше»:
    она встала на уровне глав сразу после своей главы. Серые пункты нажать нельзя, ошибки они не дают. Для
    якорей: создайте ещё два якоря без привязки (они в группе «Впереди»), в меню первого «Ниже» → порядок
    поменялся и сохранился после перезапуска (он же в ручном порядке таблицы «Якоря»); у привязанной «Встречи»
    пунктов «Выше»/«Ниже» нет.

12. **Папка мастерской в настройках.** «Настройки» → «Модули» → «Творческая мастерская» → «Папка мастерской»:
    видна «Мастерская». «Выбрать…» и выберите другую папку внутри хранилища (создайте пустую, например `Книги`).
    _Ожидается:_ путь сменился, файлы прежней мастерской остались на месте; панель «Мастерская» показывает экран
    инициализации с «Папка: Книги». Выберите папку вне хранилища. _Ожидается:_ сообщение, настройка не
    изменилась. Положите в `Книги` любой файл и нажмите «Инициализировать». _Ожидается:_ отказ с объяснением,
    на диске ничего не появилось. Верните «По умолчанию»: панель снова показывает прежнюю мастерскую.
13. **Мастерская прежних этапов.** Откройте хранилище, где мастерская создана до этапа 8 (без «Вселенных» и т. п.).
    _Ожидается:_ она единственная и сразу активна; вверху плашка «В мастерской не хватает разделов» с перечнем.
    Само по себе открытие ничего не изменило на диске (дата изменения `amby-workshop.json` прежняя). Нажмите
    «Создать недостающие разделы». _Ожидается:_ плашка исчезла, на диске появились недостающие папки баз, прежние
    страницы и файлы не тронуты.
14. **Узкая панель и старые папки.** Сузьте панель до ~320 px. _Ожидается:_ нет горизонтальной полосы прокрутки,
    «Добавить первую страницу» целиком (в несколько строк, без «…»). Если в хранилище есть папки с `amby-project.json`,
    внизу одна свёрнутая строка «Папки старого формата: N», баннера сверху нет. Слово «Мастерская» в панели —
    заголовок и карточка списка историй, больше нигде.

Если что-то из этого не так, запишите номер шага и что увидели; сам хранилищный контракт при этом не трогайте.

### Страницы и карточки (доводка 16 октября)

15. Навести на нижнюю карточку «Вселенные»: внутри рамки выдвигается сегмент со стрелкой вправо за тонкой чертой; при
    «Отдельных историях» стрелка открывает страницу «Отдельные истории», при выбранной вселенной — её страницу с её
    названием во вкладке.
16. На странице вселенной «Новая история» создаёт историю, которая сразу видна в этой вселенной; «Новое событие»
    создаёт якорь со связью на вселенную.
17. Вкладка «Персонажи» на странице истории или вселенной показывает только персонажей этого охвата; «Вся база»
    открывает страницу мастерской.
18. Кнопка рядом с заголовком панели «Мастерская» открывает страницу мастерской.
19. Открыть список карточки: он под карточкой, на всю её ширину, стрелка выбора перевёрнута; нажатие на стрелку
    вправо не сдвигает её вниз.

## Синхронизация: подключение к серверу (этап Э4)

Заметки пока не синхронизируются: проверяется только экран подключения (адрес, учётная запись, код
восстановления, вход, устройства, выход). Сценарий проходят против настоящего сервера в Docker. Автоматические
проверки (`npm run rust:test`, `npm run test`) не заменяют его: они подменяют системную связку ключей,
печать и окно сохранения файла.

**Подготовка.**

1. Сервер: из корня репозитория (нужен Docker)

   ```bash
   docker build -f sync/server/Dockerfile -t amby-sync-server:smoke sync/
   docker run -d --name amby-sync-smoke -p 127.0.0.1:18080:8080 amby-sync-server:smoke
   docker exec amby-sync-smoke amby-sync-server user add anna
   ```

   Команда `user add` печатает одноразовый код приглашения на 24 часа. Адрес сервера в приложении —
   `http://127.0.0.1:18080` (локальный адрес разрешён без https).

2. Приложение: `npm run tauri dev`. Проверка пишет в **настоящую** связку ключей системы (служба
   `com.ambynotes.sync`) и в каталог данных приложения (`sync-connection.json` рядом с настройками), поэтому
   в конце обязательно выполните шаг «Выйти» и уберите контейнер: `docker rm -f amby-sync-smoke`.
3. Второе устройство имитирует пример клиента (он входит по паролю и держит устройство):
   `cargo run --manifest-path sync/Cargo.toml -p amby-sync-client --example second_device -- http://127.0.0.1:18080 anna "<пароль>" "Второй компьютер"`.

**Сценарий.**

1. **Модуль выключен по умолчанию.** Настройки → список разделов слева. _Ожидается:_ раздела «Синхронизация» нет.
   Настройки → Модули → «Синхронизация» (отметка «бета») → включите. _Ожидается:_ появился раздел
   «Синхронизация». Отключите модуль и включите снова: раздел исчезает и появляется.
2. **Честный текст.** Откройте раздел. _Ожидается:_ написано, что заметки пока не синхронизируются.
3. **Адрес.** Пустой адрес: кнопка «Проверить сервер» недоступна. `http://example.com` _Ожидается:_ ошибка
   про `https://`. `http://192.168.1.5:8080` без переключателя — то же. Включите «Сервер в локальной сети»:
   _Ожидается:_ предупреждение, что без https данные идут по сети открыто. `http://127.0.0.1:18080`:
   «Сервер найден», версия сервера. Остановите контейнер (`docker stop amby-sync-smoke`) и нажмите
   «Проверить сервер»: «Не удалось связаться с сервером». Запустите снова (`docker start amby-sync-smoke`).
4. **Создание учётной записи.** «Создать учётную запись»: имя `anna`, код приглашения из `user add`.
   Пароль `password12345678`: _Ожидается:_ «Слабый пароль», «Продолжить» недоступна. Пароль `Short1!`:
   «Не короче 12 символов». Разные пароли в двух полях: «Пароли не совпадают». Пароль
   `correct horse battery staple 42`: «Отличный пароль», «Продолжить» доступна.
5. **Код восстановления.** «Продолжить». _Ожидается:_ крупно 14 групп по 4 символа, текст «если вы потеряете и
   пароль, и этот код, данные на сервере не вернёт никто»; кнопки «Сохранить в файл», «Напечатать»; два
   поля «Группа N»; кнопки «Подтвердить и подключиться» недоступна; другого пути вперёд нет (нет «Готово»,
   «Пропустить»). На сервере пока ничего нет: `docker exec amby-sync-smoke amby-sync-server user list`
   показывает `anna` без пароля.
   - «Сохранить в файл»: откроется окно сохранения с именем `amby-recovery-code.txt`; в файле код, адрес,
     имя и предупреждение, пароля нет. Отмена окна не даёт ошибки.
   - «Напечатать»: откроется окно печати системы (на macOS проверьте отдельно, это самое слабое место); на
     листе только код и пояснение, без остальных элементов окна.
   - Введите неверные группы: _Ожидается:_ «Эти группы не совпадают с кодом», вы остаётесь на шаге.
   - «Назад», затем снова «Продолжить»: _Ожидается:_ **другой** код (прежний недействителен).
   - Введите верные группы (можно маленькими буквами): _Ожидается:_ «Подключено к 127.0.0.1:18080»,
     пользователь `anna`, в списке устройств одно с пометкой «Это устройство». Кода на экране больше нет.
6. **Где что лежит.** В «Связке ключей» (macOS) / Диспетчере учётных данных (Windows) две записи службы
   `com.ambynotes.sync`: `account-key`, `device-token`. В каталоге данных приложения есть
   `sync-connection.json` с четырьмя полями (адрес, разрешение http, имя, номер устройства), без паролей и
   ключей. `grep -r "correct horse" <каталог данных>` ничего не находит; в журналах приложения (Настройки →
   Общие → Отладка → Показать журналы) нет пароля, кода и токена.
7. **Перезапуск.** Закройте приложение и откройте снова. _Ожидается:_ в разделе по-прежнему «Подключено».
8. **Второе устройство.** Запустите пример (подготовка, шаг 3). _Ожидается:_ в списке два устройства; имя
   «Второй компьютер» видно целиком, у него есть «Отключить». «Отключить» → «Отмена»: ничего не
   изменилось. «Отключить» → «Подтвердить отключение»: устройство исчезло; пример при следующем запросе
   сообщает, что его токен отозван.
9. **Выход.** «Выйти на этом устройстве». _Ожидается:_ снова мастер подключения; в связке ключей записей
   `com.ambynotes.sync` нет; `sync-connection.json` удалён; на сервере устройство исчезло.
10. **Вход паролем.** «Проверить сервер» → «Войти», имя `anna`, неверный пароль: _Ожидается:_ «Неверное имя
    пользователя, пароль или код восстановления», поля остались заполненными. Верный пароль: подключено, в списке
    ваше новое устройство (прежние устройства не пропали).
11. **Забыли пароль.** Выйдите. «Забыли пароль?»: имя, код восстановления **с пробелами и маленькими
