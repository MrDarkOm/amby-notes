# Удаление серверного пространства: пакет тестов

Дата: 12 ноября 2026. Ветка: `codex/sync-delete-space`, от `dev`.
Контракт: приложение Л [плана](../../sync-plan.md). Главное условие владельца:
удаляется только серверная копия, локальные файлы на всех устройствах остаются.

## Граница пакета

Это подготовка до реализации по разделу 6 плана. Новый DELETE отвечает
`501 not_implemented`, методы клиента и runtime — `todo!()`. Кнопки удаления и новой IPC-команды
в приложении нет. Заглушки не выполняют удаления. Существующие тесты не изменяются.

Тесты сервера/клиента и runtime пишет каждая своя отдельная сессия по приложению Л и публичным
интерфейсам. Инструменты этой сессии не предоставляют Sonnet и Opus; независимые сессии используют доступную модель.
Это не заменяет предусмотренную планом проверку Opus и одобрение отдельного коммита тестов.

## Покрытие и красный прогон

Сборка тестов и ожидаемое падение на заглушке проверяются раздельно; ошибка сборки или среды
не считается красной проверкой.

| Набор                                              | Требования и наблюдаемый результат                                                                                                                                              | Прогон                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `sync/conformance/tests/delete_space.rs`           | Л1–Л5: владелец и отозванное устройство, неразличимые отказы, физические тела и части, текущие/старые версии, квота, изоляция, гонка коммита/загрузки, SSE, перезапуск и повтор | 6 тестов собираются; все 6 падают на `501 not_implemented` |
| `sync/client/tests/delete_space.rs`                | Л1, Л2, Л5, Л9: метод/ID/токен, фактическое отсутствие тела, коды отказов, потерянный ответ и повтор                                                                            | 5 тестов собираются; все 5 падают на `todo!()` клиента     |
| `src-tauri/src/sync/runtime_delete_space_tests.rs` | Л6–Л9: байты заметок, вложений и долговечных данных; остановка до DELETE, чужое пространство, отказ и новая схема state.db; legacy-сервер, повтор, ID и другое устройство       | 14 тестов собираются; все 14 падают на `todo!()` runtime   |

Адресный прогон сервера и клиента (без настройки внешнего сервера):

```sh
env -u AMBY_SYNC_URL -u AMBY_SYNC_ADMIN_CMD cargo test --manifest-path sync/Cargo.toml \
  -p amby-sync-conformance -p amby-sync-client --test delete_space --no-fail-fast
```

Результат: код выхода 101, 11 ожидаемых падений, ошибок сборки и отказов среды нет.
Журналы: `/tmp/amby-delete-space-server-tests.log` и `/tmp/amby-delete-space-client-tests.log`.
Оба набора компилируются (`--no-run`), адресный Clippy проходит с `-D warnings`.

Независимая проверка доступной моделью нашла слабые места до заморозки: ожидание второго устройства
могло завершиться до прохода; старый сервер не записывал, какие запросы реально получил; порядок
«сохранить выключенное состояние → DELETE» проверялся только по конечному состоянию. Ошибки
исправлены до первого коммита: добавлены счётчики проходов, журналы HTTP-запросов и проверка SQLite
в момент DELETE. Повторная независимая проверка проведена; дополнительно усилены проверки состояния после
позднего ответа, а не только снимка до него. Результат stale-запроса не фиксируется как единственная
стратегия возврата: проверяются фактическое состояние и сохранность новой сессии. Отказ сохранения состояния проверяется в SQLite, где хранится
`META_ENABLED`; `ConnectionStore::save` сохраняет учётную запись и для этой проверки не подходит.

Адресный прогон приложения:

```sh
env -u AMBY_SYNC_URL -u AMBY_SYNC_ADMIN_CMD cargo test --manifest-path src-tauri/Cargo.toml \
  sync::runtime_delete_space_tests -- --nocapture
```

Результат: код выхода 101, 14 ожидаемых падений на заглушке runtime, без таймаутов и фоновых panic.
Журнал: `/tmp/amby-delete-space-runtime-tests.log`.

## Дополнительные сценарии до заморозки

- Л6: многопоточный fake удерживает проход на GET changes и продолжает принимать соединения;
  DELETE не должен обогнать проход. После освобождения барьера spy проверяет `META_ENABLED=0`.
- Л9: ответ DELETE удерживается, пока runtime переключается на другое хранилище или другую
  учётную запись; поздний результат не должен менять новую связь и реквизиты.
- Потерянный ответ DELETE проверен в клиенте и runtime: локальные байты сохраняются, связь остаётся
  выключенной, повтор с `404` подтверждается пустым GET-списком пространств.
- На втором устройстве проверяются законченный проход, сохранённый `enabled=0`, активация через
  новый runtime после перезапуска и побайтовая сохранность локальных файлов.
- Одновременные два вызова backend отдельно не моделируются; защита повторного клика Л11 относится
  к следующему UI-пакету. Л10–Л11 и IPC ещё не реализованы, тесты для них должны предшествовать коду.

## Следующий пакет

После проверки и отдельного коммита замороженных тестов — другая сессия реализации сервера,
клиента и runtime. Интерфейс — отдельные тесты до кода: расширение общего подтверждения вводом
названия, меню строки, локализованные результаты, IPC со сгенерированными Specta bindings.
Нужны адресные браузерные и нативные проверки, нативная сборка и проверка на двух компьютерах.
Сервер в интернете и пользовательские хранилища в этом пакете не меняются.

## Проверки репозитория

- `npm run build` — успешно.
- `npm run verify` — доходит до `rust:test` и ожидаемо останавливается на новых тестах runtime:
  1699 старых тестов прошли, 14 новых упали на `todo!()`, 14 пропущены. До этого прошли docs,
  версия, TypeScript, ESLint, 4130 тестов Vitest (428 файлов), тесты каналов обновлений,
  Prettier, Knip, Rustfmt и строгий Clippy приложения. Журнал: `/tmp/amby-delete-space-verify-complete.log`.
- `npm run bindings:check` — успешно (проверен отдельно, поскольку общий verify останавливается
  на намеренно красных тестах). Изменений IPC и генерируемых bindings нет.
- Строгий Clippy workspace `sync/` — успешно.
- После последнего усиления stale-проверок: повторно прошли сборка runtime-тестов (`--no-run`),
  Rustfmt и строгий Clippy приложения; все 14 адресных тестов снова падают именно на `todo!()`.
- 26 существующих conformance-тестов `spaces` и `info` — успешно.
- `npm run sync:req-check` — 91/91 прежних требований; новые Л1–Л11 сверены отдельно по матрице
  этого отчёта, скрипт их пока не учитывает.
- Первый прогон в sandbox прерван после отказов локального listener и системной корзины;
  итоговый прогон выполнен с доступом к временным локальным серверам, без внешнего `AMBY_SYNC_URL`.
- Нативная UI-проверка и сборка установщика не выполнялись: в этом пакете нет кнопки, команды IPC,
  изменений Tauri или реализации удаления; их нужно выполнить после реализации.
