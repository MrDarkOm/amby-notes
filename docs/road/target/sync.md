## Как начинать новую сессию

- Прочитать этот файл, затем только нужный раздел плана: этапы — раздел 6, свойства — приложение З.
- Порядок работы — раздел 6 плана «Сначала тесты». Строгие части: отдельная сессия красных тестов → коммит
  тестов с одобрения владельца → отдельная сессия кода, тесты заморожены. Облегчённые (интерфейс): тесты
  первым коммитом, потом код.
- Новые правила сначала записываются в план (решения с номером и датой), спорное для пользователя —
  вопросом владельцу. Работа в ветке от `dev`, вливание в `dev` без squash, когда этап зелёный.
- Коммиты, вливание, пуш и выпуск — только с одобрения владельца.

## Порядок (решение владельца, 5 ноября; уточнено 6 ноября)

Пункт 1 делает владелец; он не останавливает пункты 2 и 3 — правила и тесты для них пишутся параллельно.

1. **Ручная проверка свойств на двух компьютерах** (делает владелец, на копиях хранилищ: при первом
   открытии хранилище само переходит на новый формат). Сценарий: правка оформления на одном компьютере
   (иконка, цвет варианта, варианты, тип) видна на другом; одновременные правки оформления у разных
   заметок сливаются без конфликта; одновременная правка одной и той же заметки; переименование свойства;
   старая версия приложения на втором компьютере. Найденное — в ветку исправлений от `dev`.
2. **Э5: прежние версии и удалённые файлы** (строго). Сервер версии уже хранит, в приложении их не видно.
   Правила записаны 9 ноября — приложение И плана (версии — в истории заметки, удалённые — разделом
   «На сервере» в архиве; решение владельца). Дальше: проверка правил → красные тесты → код.
3. **Лимит файла 30 МБ** (решение владельца, 11 ноября 2026): Amby — заметник, поддержка больших
   файлов не требуется. Предельный исходный размер одного синхронизируемого файла — 30 000 000 байт;
   зашифрованное тело требует отдельного запаса на служебные данные. Вместо снятия ограничения через
   потоковое шифрование согласовать проверки клиента, сервера и сообщение в интерфейсе. Файл больше
   лимита не удаляется из хранилища, а остаётся в «Не синхронизируется». **Пока это план:** действующий
   предел движка 256 МиБ ещё не заменён. Работу по поддержке файлов крупнее 30 МБ из очереди убрать.
4. **Э5: удаление пространства с сервера из приложения** (сейчас только команда администратора `space remove`;
   нужен новый запрос на сервере).
5. **Э2б без QR**: открытая регистрация на своём сервере (настройка, по умолчанию выключена; сейчас интерфейс
   пишет «регистрация по коду приглашения»); имя устройства после входа (`device.name_enc` в `login` и
   `recover` станет необязательным); смена имени в карточке аккаунта (отложено 4 ноября; на сервере такого
   запроса нет, нужен новый образ). Выбор сервера по умолчанию: сейчас выбран «Сервер Amby», где регистрация
   только по коду приглашения, — человек без кода упирается в тупик; решить вместе с открытой регистрацией.
   Серверные изменения пунктов 4 и 5 выходят **одним** новым образом сервера (одно разрешение на публикацию).
6. **Э5: публичная документация** для своего сервера, контракт `docs/sync-format.md` (файла ещё нет),
   проверка безопасности всего этапа. Публикация Docker-образа и релиз — только по отдельному разрешению.
7. **Свой сервер в интернете** (перед тем как давать синхронизацию другим). Условия: **только после пункта 6**
   (проверка безопасности); замер миграции свойств сделан 6 ноября (З68) — у других людей
   не будет копий хранилищ. Hetzner «Omlet», домен и HTTPS
   через Caddy, данные на отдельном томе, открыты только порты 80 и 443, резервные копии.

## Свойства (приложение З): хвосты

- Ручная проверка на двух компьютерах — пункт 1 выше. 6 ноября нашла две ошибки, исправлены в ветке (З.13 плана, З64–З66): группы не попадали в синхронизацию (обход `VaultFs` не заходил в `.amby/properties`) и панель не перечитывала свойства после чужих изменений. Повторить проверку: правка оформления на одном компьютере попадает в `state.db`, на сервер и видна в открытой панели другого. Повторная проверка 6 ноября: группы синхронизируются за секунды, но хозяин уведомлений синхронизации не был подключён к приложению (З67) — исправлено; посмотреть глазами уведомления о конфликте, удалённой и вернувшейся заметке, которые раньше не показывались вовсе.
- Закрыто 6 ноября: первая встреча уже переведённых хранилищ сливается по заметкам против пустой базы (З64а); запись по строкам (З50) уже была сделана; замер миграции на большом хранилище — З68.
- Сделано 7 ноября (З69): конфликт группы свойств с базой решается по заметкам — две карточки «Этот компьютер» / «Другой компьютер» с самим различием, в настройках синхронизации и в окне по значку ⚠ (`resolve_group` ядра). Набор без базы по-прежнему решается файлом целиком.
- Сделано 7 ноября (З70, решение владельца после проверки на двух компьютерах): одна заметка, изменённая на двух компьютерах, — не конфликт, остаётся последняя правка по времени `edited` строки. Окно З69 осталось только для правок старых версий без времени. Подписи «этот / другой компьютер» в нём для наборов, созданных на другом компьютере, перевёрнуты (наборы синхронизируются) — исправить, если окно останется нужным.
- Ветки `sync/props-tests` и `claude/props-core-2cb6bb` (приложение Ж) уже удалены (6 ноября нет ни локально, ни на GitHub).
- Рабочие копии из `.claude/worktrees/` убраны 6 ноября, влитые ветки удалены. Сборка тестов `shadow_check`
